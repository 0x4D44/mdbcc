## Scope reduction (minimize requirements)
Across the WHOLE iostream/fstream hierarchy there is exactly ONE distinct virtual
base: `ios`. istream/ostream/fstreambase all `: virtual public ios`;
iostream(`: istream, ostream`) and fstream(`: fstreambase, iostream`) inherit
those NON-virtually. So Stage-3 only needs: **one shared (polymorphic,
data-bearing) virtual base per most-derived class, reached via a per-subobject
vbptr.** Multiple DISTINCT vbases can stay poisoned (rare; not in railc/OWL/RTL).

`ios` is polymorphic (`virtual ~ios()`) AND data-bearing — the hardest single case.

## Layout model (mdbcc's own)
Class C with shared vbase V:
- Non-virtual layout first: [vptr?][primary base nv][extra bases nv][own fields]
  [vbptr→V, IFF C *directly* says `virtual public V`].
- Append V's subobject ONCE at end of the MOST-DERIVED object (aligned).
- Each directly-virtually-deriving class (istream/ostream/fstreambase) carries a
  vbptr (4B) in its own region. iostream inherits 2 (via istream+ostream),
  fstream inherits 3 — all point to the single shared V.
- Standalone istream: V appended within istream; its vbptr → that V.
  As a base of fstream: istream's vbptr → fstream's shared V.

Record additions (ast.rs): `vbase: Option<VBaseInfo>` where
VBaseInfo { vbase_id, vbase_offset (V within this object as laid out),
vbptr_offset (offset of a vbptr field in THIS class that reaches V) }.
(Single-vbase scope ⇒ one VBaseInfo; generalizes to Vec later.)

## Member access to a V member through T* (T derives from V via virtual edge)
addr = *(char*)( (T*)e + T.vbase.vbptr_offset )   // load vbptr → &V
     + member_offset_within_V
MANDATORY for base-class methods (istream::getline compiled with static type
istream must reach the shared ios via vbptr). Most-derived code uses the same
path (reaches the same place).

## DECISION: site-driven vbase setup, scoped to LOCAL objects (model B)
The RTL ctors NEVER explicitly construct the vbase (`fstreambase::fstreambase()
: buf() { ios::init(&buf); }`; `fstream::fstream() : fstreambase(), iostream()
{}`) — ios is implicitly default-constructed by the most-derived, then base
ctors set it up via `ios::init` through the vbptr. So NO hidden ctor flag is
needed and NO ctor ABI changes:
- CONSTRUCTION SITE (Decl only, for now): (1) default-construct each vbase
  (`ios::ios()` on this+vbase_off — sets ios.vptr), (2) set ALL vbptr fields to
  this+vbase_off, (3) run the most-derived ctor normally. The ctor chains
  non-virtual base ctors (fstreambase→ios::init via vbptr, iostream→istream/
  ostream); vbase ctor calls are EXCLUDED from base-ctor injection (site did it).
- DESTRUCTION SITE (local scope-exit only, for now): run the dtor normally, THEN
  destroy each vbase once (`ios::~ios()` on this+vbase_off).
- Vbase member access + derived→vbase UPCAST: ALWAYS via vbptr (mandatory — a
  base-typed `this` inside istream::getline can't use a static offset).
- SCOPE: LOCAL vbase objects only (LAYOUT uses `fstream infile;`/`istrstream
  ins;` as locals). `new`/placement-new/array-new of a vbase class keep
  REJECTING (clean error) until a real need appears. Members/temporaries: later.
This is the ruthless-minimization path — exactly what LAYOUT.CPP + the minimal
diamond need, no more.

## (superseded) Constructor protocol (hidden most-derived flag)
Ctors of classes-with-vbases get a hidden trailing int param `__most_derived`
(1 = you own vbases). Construction site passes 1.
- Most-derived ctor (flag=1): (a) construct shared V once: V::V on (this+vbase_off);
  (b) set ALL vbptrs (it knows full layout: [subobj_off + vbptr_off] = this+vbase_off);
  (c) call base ctors passing flag=0; (d) own body + own vptr (SetVptr).
- Intermediate ctor (flag=0): skip V ctor + skip vbptr setup; call base ctors flag=0;
  own body. (When itself most-derived, flag=1 path runs.)
- Standalone V-direct class (e.g. istream alone, flag=1): constructs its own V, sets vbptr.

## Destructor protocol (mirror)
Most-derived dtor: own body → non-virtual bases (reverse) → destroy shared V ONCE last.
Intermediate dtor (flag=0): skip V dtor.
