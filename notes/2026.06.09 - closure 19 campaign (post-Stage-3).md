## Findings parked (NOT fixed — don't stack)

1. **i386 u64 `>>32` (or 64-bit mul high half) MISCOMPILES.**
   Probe `/tmp/u64probe.c`: `unsigned long long s = 1; s = s*0x000015A400004E35ULL+1;`
   twice → `printf("%u %u", (unsigned)(s>>32), (unsigned)s)` printed the LOW
   dword twice (`400860463 400860463`; correct hi is `221838220`). The rand
   shim deliberately avoids u64 because of this. Needs an oracle-diffed fix
   when 64-bit arithmetic enters the closure (e.g. __realcvt work).

2. **Call-arg evaluation order: mdbcc is left-to-right, bcc32 is RIGHT-to-left.**
   Observed: `printf("x%ld z%ld", _lrand(), _lrand())` gives swapped values vs
   bcc32. Unspecified in C, but vintage Borland code may DEPEND on
   right-to-left (cdecl push order). If railc parity diverges mysteriously,
   check this first. Consider switching i386 arg evaluation to right-to-left
   for dialect parity.

3. **RAND.C's asm `_lrand` multiplier is 0x000015A4_00004E35**, not the
   0x015A4E35 the C comment claims (asm splits 0x15A4/0x4E35 across dword
   boundaries). Shim matches the SHIPPED asm; proven byte-exact vs the real
   Borland RTL binary (`/tmp/randtest`, stdout parity incl. interleavings).

## 2026.06.10 (cont.) — the startup-init arc (G48/G49)

First 0-unresolved closure linked, but railc.exe segfaulted in `malloc`
(called from the very first string-global ctor thunk): the recompiled
HEAP.C `malloc` walks heap variables that only `_init_heap` sets up — and
`_init_heap` is registered via **`#pragma startup _init_heap 2`**, Borland's
INIT-record mechanism, which mdbcc ignored. `_init_heap` is `static`, so no
shim can reach it: the principled fix is implementing the pragma.

- **G48 (`#pragma startup <fn> [prio]`).** pp splices a reserved
  `__mdbcc_startup__ <fn> <prio> ;` token form (directive position only);
  the parser accepts it BOTH at file scope and as a STATEMENT (HEAP.C puts
  the pragma INSIDE `_init_heap`'s own body); codegen emits one
  `.mdbcc_ctor.$startup$NNN$<fn>` thunk per registration (same-TU ⇒ a
  static fn resolves); `collect_ctor_thunks` sorts startup thunks FIRST,
  ascending NNN (stable ⇒ plain ctor thunks keep first-seen order after).
  Default prio 100 when omitted. RTL chain now alive: version 0, video/
  locale/hdir/platform 1, heap 2, argv 3, handles 4, streams 5, cvt+scan
  10, iostream 16. Differential test (startups before C++ static ctors,
  ascending): `i386_pragma_startup_priority_order_before_ctors`.
- **G49 (tagless `typedef struct {…} NAME` adopts NAME for linkage).** The
  running init chain pulled STREAMS.C, whose `_allocbuf(FILE*,…)` extern
  ref mangled `@_allocbuf$qp4R165pciui` against ALLOCBUF.C's definition
  `@_allocbuf$qp2R0pciui` — `FILE` is a TAGLESS typedef'd struct and the
  `R<id>` fallback is TU-local. bcc32 adopts the typedef name (oracle:
  `@takefoo$qp3FOO`); `register_typedefs` now does the same (linkage only —
  NOT registered as an elaborated tag). o13_13 pins the EXTDEF parity.
- **Startup-chain surface (rtlshim + imports).** `_C0argc/_C0argv/
  _C0environ/_oscmd/_osenv` storage + a prio-0 `#pragma startup rtl_c0_init`
  seeding `_oscmd = GetCommandLineA()` / `_osenv = GetEnvironmentStringsA()`
  (STARTUP.C:392-395 verbatim — the shim itself now uses G48). `_control87`
  = SOFTWARE-CW shim (mdbcc drops inline asm; v1 gap: LDTRUNC/SIGNAL see
  consistent values, real x87 CW untouched). `_qmul10` 16-bit-limb C,
  `_fuildq` double-precision (loses >2^53 mantissa bits — same profile as
  every mdbcc `long double`). `isatty` forwards to mdbcc-compiled
  `__isatty` (ISATTY.ASM is a pure alias). Imports added: GetStartupInfoA,
  GetFileType, SetHandleCount, GetCommandLineA, GetEnvironmentStringsA,
  and the Global* heap family (GlobalAlloc/Free/Lock/Unlock/ReAlloc/Size/
  Handle — OWL DIB/clipboard/PRINTDLG).
- EASYWIN excluded from the sweep permanently (startup VARIANT: defines
