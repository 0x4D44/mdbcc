# EDIT Static Default And GROUPBOX Exception Classification

Status: SIGNED-OFF

## Scope

This design covers the next quality-map item after the constructor-default
promotion fix. It deliberately splits the two observed follow-on symptoms:

- Fix the deterministic EDIT compile blocker: an in-class constructor default
  argument references a static data member declared later in the same class.
- Preserve the current GROUPBOX classification as a runtime OWL class exception
  unless a narrow probe identifies a concrete, low-risk throw-site fix during
  implementation.

GROUPBOX and EDIT now fail in different layers. Treating them as one code fix
would mix parser/default-argument semantics with runtime window creation and C++
exception handling.

## Evidence

The product matrix advanced after the previous commit:

- `groupbox`: builds and launches, then exits before the `GroupBox Tester`
  window with `0xE0000002`.
- `edit`: reaches codegen and fails at `EDITX.CPP:289:3` with
  `no member named 'EditTextLen'`.

`0xE0000002` is mdbcc's `EXCEPTION_MDBCC_CLASS` runtime code, so GROUPBOX is an
unhandled OWL class exception rather than the prior constructor-overload
compiler error.

The EDIT source has this class shape:

```cpp
class TExampleEdit : public TEdit {
  public:
    TExampleEdit(...,
                 UINT textLen = EditTextLen + 1,
                 BOOL multiline = TRUE,
                 TModule* module = 0)
      : TEdit(..., textLen, multiline, module) {}

    ...
    static const unsigned EditTextLen;
};

const unsigned TExampleEdit::EditTextLen = 1000;
```

The default expression is parsed before the class member declaration loop reaches
`static const unsigned EditTextLen`. Current parser support for unqualified
static data members is keyed by `static_member_types`, so it cannot resolve this
forward reference at the parameter-list parse site. The expression is therefore
stored as a bare `Expr::Var("EditTextLen")`.

When overload default expansion later appends that expression at the call site,
codegen evaluates it in the caller's context. `this_member_fallback` then uses
the caller's `this` and falls through to `this->EditTextLen`, producing the
observed `no member named 'EditTextLen'`.

## Approach

Keep the fix in parser finalization, where the full class and static-member
declaration set are known:

1. Add a small expression rewrite helper for default arguments. For a member
   function or constructor default keyed as `Class::member`, walk the default
   expression and rewrite an unresolved bare `Expr::Var(name)` to
   `Expr::Var("ResolvedClass::name")` when the existing class/static lookup
   semantics would find a static data member in the declaring class or its
   supported base chain.
2. Apply that rewrite to both default stores before building the
   `TranslationUnit`:
   - `p.fn_defaults`
   - `p.overload_defaults`
3. Insert each rewritten qualified static into `p.referenced_statics`, so the
   existing parse-end extern-static emission continues to work when the static
   member is declared in this TU but defined elsewhere.
4. Run this rewrite before the existing `referenced_statics` extern emission and
   before the record-size refresh of default expressions. While touching this
   finalization path, refresh record-type caches in both default stores; today
   only `fn_defaults` is refreshed, but `overload_defaults` is now the
   authoritative path for promoted/overloaded constructors.
5. Keep the rewrite narrow:
   - only default arguments for qualified member/constructor keys;
   - only bare variables that are not already qualified;
   - only names declared as static data members reachable from the declaring
     class under the existing parser-supported lookup;
   - recurse through expression forms, including address-of, because this is
     only name qualification (`&Static` to `&Class::Static`), not constant
     substitution.

This avoids changing `this_member_fallback` globally. Codegen fallback is still
allowed to resolve real forward instance members in member bodies using the
current function's `this`; default arguments instead get their declaring-class
static names resolved before they are cloned into unrelated caller contexts.

## GROUPBOX Handling

This pass should not attempt a broad runtime fix for GROUPBOX. During
implementation, one low-cost classification probe is acceptable:

- rerun the product matrix and capture the GROUPBOX row after the EDIT fix;
- if it still exits with `0xE0000002`, keep the expected phase at launch and
  update quality-map text to say it is an unhandled OWL class exception;
- if a precise throw-site is already visible in existing logs/output, record it
  in the map or journal, but do not add runtime instrumentation or exception
  machinery without a separate HLD.

Likely throw sites live in OWL window/dialog creation (`TWindow::Create`,
`PerformCreate`, child registration/creation), not in the EDIT static-member
semantics. That is a separate runtime investigation.

## Decision Log

- Resolve default-argument class statics at parser finalization rather than at
  call-site codegen. Default expressions are declared in one class but expanded
  in arbitrary caller contexts; the caller's `this` is the wrong lookup anchor.
- Rewrite both `defaults` and `overload_defaults`. The previous constructor
  promotion fix made overload defaults authoritative for this product path, so
  fixing only the legacy `defaults` map would leave the observed EDIT call
  broken.
- Keep GROUPBOX separate. Its current failure is a runtime class exception after
  successful compile/link, while EDIT is still blocked in semantic/codegen name
  resolution.

## Adversarial Review

Sequential read-only review found and folded these changes into the design:

- Important: The rewrite must match the parser's existing class static lookup,
  not only the immediately owning class; otherwise inherited statics would stay
  inconsistent between body expressions and default arguments.
- Important: `overload_defaults` must be rewritten and record-refreshed together
  with `fn_defaults`, because promoted constructors now consume
  `overload_defaults` directly.
- Important: Address-of should not be excluded. Unlike integer-constant
  substitution, this rewrite preserves the operand as an lvalue/global name.
- Residual risk: The current parser's `unqualified_static_member` only follows
  the supported single-primary-base chain. Extending static lookup across all
  MI/vbase paths would be a broader semantic change and should not be hidden
  inside this EDIT fix unless an existing helper already provides it at parser
  finalization.
- Residual risk: GROUPBOX's unhandled class exception may turn out to share a
  default-argument cause in a later runtime probe, but the present evidence
  shows a different layer. This HLD keeps it as classification/follow-up work.
