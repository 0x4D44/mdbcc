## The one explained non-identity (not a regression)
The KINGSX delay-LED boxes (Arrival/Departure delay) are the ONLY differing region (a fixed ~1938 px,
identical at both tiers). The **BC4.5 golden exhibits its documented blank-delay-box GDI bug**
(LAYOUT.CPP:630 — `HTimeSym` selected into two DCs → `StretchBlt` from an empty 1×1 DC), leaving the boxes
black; the **native-Win64 build renders the LED digits correctly** (the source carries the fix). So the
native build is *more* correct than the golden there. O6 masks that region; everything else is pixel-exact.

## Win64 ABI bugs found + fixed this campaign (the "cookie-class siblings")
1. Startup heap corruption `0xC0000374` — array-new/`delete[]` cookie symmetry (prior, `6055544`).
2. Wall-2 dispatch `0xC0000005` — 32-bit WPARAM/LPARAM/LRESULT (M1, prior).
3. 4-byte float global load/store width (`f91163b`, prior) — the blank-track-diagram class.
4. **Dialog side-bitmaps** — DWL_USER bypasses the response table; TDialog-discriminated WM_PAINT route
   (`88f0d4c`).
5. **RTL printf integer varargs** — BC4.52's `<stdarg.h>` stack-walking `va_arg` macros compiled verbatim,
   reading garbage from Win64 register-passed args (FINISH `%d`). Fixed by routing the RTL printf to mdbcc's
   correct intrinsic `va_arg`: a BC45-compatible `<stdarg.h>` overlay (`756daaa`) + relaxing the
   `gen_va_arg` non-variadic gate (`61ba06f`). Fixes **all** Win64 RTL integer printf/sprintf/scanf, not
   just FINISH. Guarded by `tests/win64_varargs_int.rs`.
