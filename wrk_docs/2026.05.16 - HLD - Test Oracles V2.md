# HLD — Test Oracles for mdbcc (V2)

Date: 2026-05-16
Status: Design — V2 (post team review). No code changed by this document.
Supervisor: Claude. Reviewers: rigor, systems, simplicity-steward, devil's-advocate.

## 0. What changed V1 → V2 (review outcomes)

Accepted CRITICAL fixes: stdout CRLF normalisation; a precise equivalence
definition; per-run timeouts; stderr removed from pass/fail; the "retrofit
the 88 e2e tests" plan is **false** (those are Rust string fragments, not
files) and is replaced by a small new on-disk corpus with O1 kept
authoritative; mdbcc `printf` ignores width/precision/length → corpus
filter + recorded gap; `wrk_tools/`/`wrk_corpus/` are **not** git-ignored
today → mandatory precondition.

Cut as overengineering (team consensus, supervisor-confirmed): the named
"triangulation model"; the pluggable `Reference` trait/abstraction (only
one reference exists); the mdbcc-vs-mdbcc "self-check" (tautological); the
O3/O4/O5/O6 detailed prose and the BCC bitness essay; the UB "filter
taxonomy"; the stdin comment mini-DSL. O5 kept but deferred to v2 with an
honest, narrowed claim. O6 demoted to one non-goal sentence.

## 1. Purpose

Define the minimum oracle set that makes the autonomous build loop
trustworthy, and pin down *exactly* what "behaviourally equivalent" means
so a differential cannot manufacture false signal. Quality stance
(CLAUDE.md): solve the problem at hand, no speculative abstraction, no
migration/rollback, **no feature flags, minimal env vars**.

## 2. Environment (probed 2026-05-16)

- MSVC installed: `vswhere.exe` at the standard path → VS 2022/Community,
  `vcvars64.bat` + `cl` x64 present. `cl` is **not** on `PATH`.
- No Borland/Embarcadero compiler installed.
- `.gitignore` ignores `target/` only — **not** `wrk_tools/`/`wrk_corpus/`.

## 3. Oracle catalogue (compact)

| ID | Oracle | Proves | Gating | When |
|----|--------|--------|--------|------|
| O1 | Existing hand-expected e2e (`tests/end_to_end.rs`) | End-to-end correctness vs hand-computed values | **yes, authoritative** | live |
| O2 | Differential vs MSVC `cl` over a small on-disk corpus | Semantic equivalence on portable C | yes, when `cl` resolved | v1 |
| O3 | Differential/acceptance vs a real Borland compiler | Correctness of the *Borland dialect* | yes, when present | v3 (setup-gated) |
| O5 | x64 structural-decode sanity of emitted `.text` | Bytes are well-formed x64 (not semantics) | yes | v2 |

O1 stays the **authoritative gate** and is **not deleted or migrated**. O2
augments it; O3 extends coverage to the dialect when a Borland binary is
acquired. Perf/compile-time is a **non-goal** (one print if ever wanted;
never gated — naïve codegen, "run" not "run fast"). There is no separate
O4/O6.

Why O3 matters (settled, Arthur to acquire binaries): MSVC structurally
cannot compile authentic Borland source, so for dialect-specific code MSVC
is not a valid reference at all — only a real Borland compiler is. bcc64
(Embarcadero, Win64) = behavioural reference; bcc32-5.5 (Win32) =
front-end acceptance via `bcc32 -c` (no `ilink32`/cfg dependency). Detail
deferred to v3 when a binary is actually in `wrk_tools/`.

## 4. O2 — the only new oracle built in v1

### 4.1 Corpus is NEW files, not a retrofit
The 88 e2e "programs" are Rust string literals / expression fragments,
many tests running several programs each — there is no on-disk corpus.
Building an extractor for our own test file would be fragile
overengineering. Instead:

- `tests/corpus/portable/*.c` — a *small, hand-authored* set of complete
  translation units in the **mdbcc ∩ MSVC** intersection. Each is
  deterministic, input-free, UB-free, and avoids mdbcc's known gaps.
- `tests/corpus/dialect/*.c` — Borland-dialect programs. **MSVC is
  excluded for these by construction**; they are O3-only (a future BCC is
  their sole oracle). Listed now so dialect coverage is not silently lost
  to an MSVC-only differential.
- `tests/end_to_end.rs` (O1) is untouched and remains authoritative.

### 4.2 Reference build
`cl /nologo /MT <src> /Fe:<out>` in a per-invocation dir
`target/oracle/<pid>_<n>/` (mirrors O1's proven unique-temp pattern;
avoids `*.obj` collisions under parallel `cargo test`). `/MT` (static
CRT) so `ref.exe` is self-contained — no `VCRUNTIME*/ucrtbase` DLL
dependency that would false-fail as `0xC0000135`. No `/EHsc` (no
exceptions in scope), no `/O2` (codegen comparison is a non-goal).

### 4.3 `cl` discovery (no env var we define, no flag)
Locate `vswhere.exe` at its known path → resolve `vcvars64.bat`. Capture
its environment with the exact recipe
`cmd /c "\"<vcvars64>\" >NUL 2>&1 && set"`, parse only lines matching
`^[A-Za-z_][A-Za-z0-9_()]*=`, split on the **first** `=`. Cache in a
`OnceLock`. **Success criterion = resolving `cl.exe` on the captured
`PATH` and a probe build** of `int main(void){return 7;}` that runs and
exits 7, with `VSCMD_ARG_TGT_ARCH=x64` (or `cl` under `Hostx64\x64`)
asserted so a wrong-bitness reference can't false-fail. Three distinct
states, each printed loudly: `cl ACTIVE`, `SKIP: cl not found`,
`SKIP: cl found but environment unusable`.

### 4.4 Equivalence is defined as
A corpus program **passes** iff, for mdbcc's exe and `ref.exe`:

1. **Exit code**: equal as the `i32` from `std::process::ExitStatus::code()`
   on *both* sides (never mix in a `u32`). Corpus `main`s must return
   **0–125** (a §4.5 filter) so the value is unambiguous across the
   Windows DWORD path and shells.
2. **`None` exit code** (killed / no code) on either side ⇒ not a pass:
   if only mdbcc ⇒ **FAIL**; if both ⇒ **EXCLUDE** (program-level issue).
3. **Crash codes**: any exit code with high byte `0xC0`/`0x80`
   (Windows `STATUS_*`) is not a program value — mdbcc-only ⇒ **FAIL**,
   both ⇒ **EXCLUDE**. Two crashes are *not* "agreement".
4. **stdout**: byte-equal **after** stripping a `\r` immediately preceding
   each `\n` on *both* streams. Rationale: the MSVC CRT writes stdout in
   text mode (`\n`→`\r\n`) while mdbcc's hand-emitted `WriteFile` writes
   raw `\n`; without this, O2 false-fails on every newline. Documented
   blind spot: O2 cannot catch a newline-encoding bug (O1 still can). No
   other normalisation (no trimming/casing — that would mask real bugs).
5. **stderr**: **not** in the pass/fail tuple (CRT-vs-no-CRT asymmetry
   makes it structurally non-equal). Captured only for failure
   diagnostics.

### 4.5 Mandatory corpus filters (else the differential lies)
- **mdbcc printf gap**: no `%`-directive with flags/width/precision/length
  modifiers (mdbcc ignores them today → `"%5d"` diverges). Recorded as a
  real mdbcc gap O2 should later drive fixing, not just a curation nicety.
- **`main` returns 0–125** (see §4.4.1).
- **Deterministic, input-free, UB-free.** UB/impl-defined exclusion is
  hand-curated (a leading `// oracle: skip <reason>` excludes a file).
  *Cheap automated backstop*: also build the reference at `/Od` **and**
  `/O2`; if the two reference runs disagree, the program is
  UB/impl-defined → **auto-EXCLUDE** (do not blame mdbcc). ~10 lines, no
  flags; uses the one reference v1 has. This is the only "UB detection" —
  no automated UB analysis is attempted (explicit non-goal).
- (bcc32-5.5 only, v3) exclude pointer-size-observing programs (Win32
  ptr=4 vs our Win64 ptr=8).

### 4.6 Execution robustness
Every child (mdbcc exe, each reference build) runs under a fixed
**10 s wall-clock timeout**; exceeded ⇒ kill ⇒ mdbcc-only timeout = FAIL,
both = EXCLUDE. A *launch* failure (missing file / AV quarantine /
`0xC0000135`) is retried **once**, then reported as a distinct
"reference/exe failed to launch" state — never conflated with a
behavioural disagreement.

## 5. O5 — structural-decode sanity (v2, honest scope)

Linear-decode the whole `.text` (entry stub + all function bodies) with
`iced-x86` (a `[dev-dependencies]` entry only — Arthur pre-approved;
never linked into the `mdbcc`/`bcc` binary). Assert: **(a)** zero
`INVALID` instructions and **(b)** decoded instruction boundaries exactly
tile `[0, text.len())` (no gap/overlap/undecodable tail). Optional ~10
lines: each `rel32` `call/jmp/jcc` target lands in `[0, text.len())` —
a sanity net on `build_text`'s own arithmetic.

Honest claim (recorded so the loop never over-trusts it): O5 proves bytes
are **well-formed x64**, *not* that they are the **intended/semantically
correct** instructions — a typo'd-but-legal opcode passes O5 and is caught
only behaviourally. Its unique value: catching a truncated/garbage/
out-of-bounds emission on a path O1/O2 don't take. Precondition: valid
only while `.text` is pure code (true today; revisit if jump tables are
ever emitted into `.text`).

## 6. Engineering (simple, concrete, no premature abstraction)

- **No `Reference` trait/struct.** v1 is a concrete `fn msvc_ref(src) ->
  Result<RunOutcome>` + the discovery helper. If a second real reference
  (bcc) ever lands, extract a shared shape *then* — two concrete impls is
  the minimum information needed to design the interface; one is not.
- One test module `tests/differential.rs` + a small support module.
  Corpus = directories globbed; the only metadata convention is
  `// oracle: skip <reason>`. No manifest, no schema, no stdin DSL
  (v1 corpus is input-free).
- **Self-skip, but never silently green.** Every run prints a one-line
  coverage summary, e.g. `oracles: O1 ACTIVE | O2 SKIP(cl env unusable) |
  O5 n/a`. **O1 remains the authoritative gate at all times**; O2/O3 only
  *add* signal. "Zero external differential oracles active" is a loud
  WARN, not a green pass. There is no mdbcc-vs-mdbcc self-check (it tests
  determinism, not the comparator, and is tautologically green).
- Artifacts under `target/oracle/` (already git-ignored).
- **Precondition (must precede any tool/corpus acquisition):** add
  `wrk_tools/` and `wrk_corpus/` to `.gitignore`. Today they are *not*
  ignored; without this, acquired BCC binaries and copyrighted Borland
  sample sources would be committed.

## 7. Non-goals / recorded pushbacks (do not re-litigate)

- No machine-code comparison vs MSVC/BCC (optimiser noise; behaviour is
  the signal).
- Perf/compile-time never gated; not designed here.
- MSVC is not a reference for Borland-dialect source; `dialect/` corpus is
  O3-only and MSVC-excluded by construction. A future BCC disagreeing with
  MSVC on dialect code is **expected**, not "UB to exclude".
- No named triangulation model: "all *available* references must agree"
  is the whole rule; portable-corpus UB exclusion is the `/Od`-vs-`/O2`
  reference self-differential of §4.5, nothing more.
- O5 is structural sanity only — not a codegen-correctness oracle.
- No automated UB analysis; corpus is curated.

## 9. Decisions (resolved)

1. Acquire **bcc64** (Win64 behavioural) **and bcc32-5.5** (acceptance,
   `bcc32 -c`) into git-ignored `wrk_tools/` — manual, Arthur-performed,
   bcc64 availability intermittent; O3 self-skips until present.
2. `iced-x86` accepted as `[dev-dependencies]` only (O5/v2).
3. Self-skip confirmed, **bounded by**: O1 always authoritative; loud
   per-run coverage line; zero-external-oracle = WARN not green.
4. v1 O2 corpus is **new on-disk files**, not a retrofit; O1 not deleted.

## 10. Open risks (accepted, watched — not blockers)

- bcc64 free standalone availability is intermittent and outside our
  control; O3 (the *dialect* oracle, the project's core value) may stay
  unbuilt. Mitigation if it persists: bcc32-5.5 *behavioural* (Win32,
  pointer-size programs filtered) as a fallback dialect oracle.
- Defender may quarantine freshly written unsigned exes under O2's churn;
  recommend a documented Defender exclusion for `target/oracle/`;
  launch-failure is already a distinct retried state (§4.6).
- Sandbox network availability for acquiring tools/corpus is unconfirmed;
  verify before scheduling v3/v4 work.
