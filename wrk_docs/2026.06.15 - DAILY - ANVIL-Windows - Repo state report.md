## 3. `BUGS.md` — direction of travel

**The single biggest observability change in the project's history landed this cycle: `BUGS.md` now exists** (`ffc08a2`, 06-15 00:35). For the first time there is a single, severity-tagged, file:line-evidenced defect ledger. This directly closes the 06-14 daily's #1 recommendation (then tracked as `MDBCC-05`).

**Ledger snapshot at HEAD:**

| State | Count | Notes |
|---|---|---|
| **Open** | **24** | codegen/ABI 7 (B-01…07) · C++/RTTI/EH 10 (B-08…17) · RTL/CRT/toolchain 7 (B-18…24) |
| **Parked** | 4 | C-TU mode, i386 `va_arg` encoder, bit-field layout, set-data-file automation |
| **Fixed** | 5 | F-01…F-05, each with commit traceability |

**Trend (first ledgered cycle; prior reports tracked defects in prose):**

- **Severity profile is healthy-but-not-clean.** Only **two** high-severity items remain open: **B-08** (G58 — thrown exception-object string field is garbage on catch; affects OWL error paths) and **B-18** (`-m64` is test-scaffolding, not a real target). Everything else open is medium/low. No open `critical` (silent miscompile) items — the one that existed (64-bit arithmetic) was fixed this cycle.
- **F-01 is the cycle's headline fix.** The 06-14 daily's `MDBCC-13` — a *hypothesis* ("64-bit shift/division miscompile, no repro") — was confirmed **real and four layers deep** (`gen_intop` 32-bit opcodes for all widths; `expr_type` mistyping literals *and* op-results as `int`; `cdq` not `cqo`; unary `neg`/`not` 32-bit) and fixed in `98115c4`, guarded by 17 oracle cases in `tests/i64_ops.rs`. A *silent miscompile sitting under the "parity" banner* is the most important kind of bug to have caught — RailC survived only by avoiding `u64` in hot paths.
- **Two residual 64-bit gaps were honestly logged rather than papered over** — B-02 (`LL` literal in `0x8000_0000..` types as `int`) and B-03 (`const_eval` shift-fold is signedness-blind). The codegen/runtime path is fixed; the constant-fold path is not. Scoping these out (to preserve RailC bytes) and recording them is exactly the discipline the ledger is for.
- **The ledger was lightly stale ~20 min after birth.** `overlay_dirs` (`fa69d85`, 00:55) added overlay logic to `src/project.rs`, partially contradicting B-18's note "`src/project.rs` has no overlay logic." B-18's *substance* (no app builds to Win64 without a Rust-test edit; `build_bc45_libs` hardcoded `-m32`) still holds. Worth a one-line refresh.

**Net:** defect observability went from "prose-only, the project's weakest part" (06-14) to "a real ledger with full traceability" in one cycle. Strongly positive.
