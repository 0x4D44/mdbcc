## TL;DR (the mission)

> **`mdbcc` + `mdlink` compile `C:\language\railc` — and every library it depends on (OWL, the RTL, BIDS) — from Borland C++ source, producing a 32-bit (i386/PE32) `railc.exe` that runs natively on Win11 x64 under WOW64 and behaves identically to the `bcc32` + `tlink32` reference build.**

Not a horizon — a fixed, real, ~12 K-LOC OWL application (21 `.CPP` TUs in the current `railc.mak`). Done is unambiguous and differential-testable.

---

## 1. Why railc (the sharpening)

The old goal ("BCC 4.52 conformance") was unbounded — conformance to a whole compiler is a horizon, not a finish line. `railc` ("Railway Controller v2.3" — a vintage Borland C++/OWL railway-timetable simulation) is a **fixed acceptance corpus**: a known set of TUs + a known library closure. That turns the horizon into a test. It is also a *real* app, so passing it is a far stronger proof than synthetic tests or the minimal HELLOAPP. HELLOAPP does not vanish — it becomes the **minimal proving waypoint** on railc's path (W1 below).

This is the CLAUDE.md quality principle in action: build *exactly railc*, not all of bcc32. railc is "the someone who matters."

## 2. Definition of Done — **purist self-host** (Arthur's call, 2026-06-06)

The goal is satisfied **only** when **every byte of `railc.exe` is mdbcc-built**:

1. `mdbcc -m32` compiles all 21 current railc TUs → COFF `.obj` (i386), clean.
2. `mdbcc -m32` compiles the Borland **OWL**, **RTL**, and **BIDS** source → `mdowl.lib`, `mdcw32.lib`, `mdbids.lib` (+ the C0 startup object), clean.
3. `mdbcc`'s `src/rc/` resource compiler turns `RESOURCE/RAILC.RC` → `railc.res`.
4. `mdlink -m32` links the **all-mdbcc** closure (railc objs + our libs + our startup + our `.res`) + OS/CTL3D **imports** → `railc.exe`.
5. `railc.exe` runs on Win11/WOW64 and **matches the golden reference** (§6).

**Scope boundary — what "self-host" does and does not include.** We compile all *Borland-authored* code (OWL + RTL + BIDS). We do **not** compile the operating system: `KERNEL32/USER32/GDI32/COMDLG32/...` and `CTL3D32.DLL` are resolved as **imports** (an import library / DLL stub), exactly as `import32.lib`/`ctl3d32.lib` do for the reference build. You cannot self-host Windows.

**A property worth banking:** because the final image contains *no* Borland binary code, mdbcc's exception machinery only has to be **behaviourally** correct — it does **not** need to be bit-compatible with Borland's `fs:[0]` SEH protocol (which the "link prebuilt OWL" path would have forced). Self-host is *harder overall* but *easier on the EH axis*.

### GUI parity tiers (how "matches" is judged)
- **Tier 1 (must):** launches without crash; main window + menu + toolbar render; golden-screenshot diff of the main window and each dialog (CONFIG, ABOUT, FINISH) within tolerance (`mdscreensnap`).
- **Tier 2 (should):** scripted scenario — Start New with a known data file (e.g. `KINGSX.RCD`), advance the clock, open each `Window` menu child (Arrivals/Departures/Platforms/Loco yard); diff rendered state vs golden.
- **Tier 3 (stretch):** longer run / save-file byte parity.

## 3. Target & ABI — **i386 / PE32** (decision #62, locked)

railc is a 32-bit `EXETYPE WINDOWS` app; the reference is `bcc32` (the 32-bit compiler); OWL window dispatch recovers `this` from the i386 `_EAX` thunk. So the entire build is **i386**. **`-m32` must be passed to BOTH `bcc` AND `mdlink`** (mdlink defaults to Amd64; an i386 `.o` linked without `-m32` yields a malformed PE that runs i386 bytes as x64 — silently wrong). A native 64-bit port is explicitly **out of scope** (that is PLAN stone S7, a future goal).

## 5. What we already have (de-risking)

- **mdlink** already ingests OMF objects + archives: `src/link/omf.rs`, `src/link/archive.rs`, `src/link/crt.rs`.
- **mdbcc has a resource compiler**: `src/rc/{lexer,parser,res,mod}.rs` + `.rsrc` emission in `src/link/pe_writer.rs`.
- **Win32 import resolution** exists (`#26`).
- **The i386 backend** runs real OWL-shaped code on WOW64: calls, methods, virtual dispatch, heap, and the full class exception model (throw/catch/rethrow) — all bcc32-oracle-diffed.
- **Prebuilt Borland libs** for every layer live at `C:\language\mdbcc\wrk_oracle\bc45\BC45\LIB\` — used as a **bisection oracle**, not a finish line (§6).

## 6. The oracle (how every step is verified)

1. **Golden reference (W0):** build `railc.exe` with the *real* Borland toolchain — `C:/tmp/bc45/BIN/BCC32.EXE` + `BRC32.EXE` + `TLINK32.EXE` + the prebuilt libs. Capture: the binary, per-TU `.obj`, launch behaviour, and golden screenshots of each window/dialog. **Without this, "matches" is undefined.**
2. **Differential, per increment:** mdbcc output vs bcc32 output at the finest granularity available (per-TU `.obj`/symbol/behaviour early; whole-exe behaviour late).
3. **Bisection oracle (the PLAN's O16, repurposed for debugging):** when the all-mdbcc exe misbehaves, localize the layer by linking the *suspect* mdbcc-built lib against Borland's *prebuilt* counterparts (e.g. mdbcc-railc-objs + Borland `OWLWF/BIDSF/CW32`). If that runs, the bug is in our OWL/RTL/BIDS codegen; if it still fails, it's in our app codegen. This A/B isolates which of the four layers miscompiled — invaluable, and the reason we keep the prebuilt libs around even though they are not part of Done.
4. **b12 RUN-verify:** every increment must actually *run* on WOW64 and diff green; a hang/crash is worse than a clean error — **revert red increments** rather than stacking fixes.

## 7. The route (waypoints — the finish is W6)

- **W0 — Golden reference.** Build & capture the bcc32/tlink32 railc.exe (the oracle). *Doable now; do it early.*
- **W1 — App front-end/codegen complete.** `mdbcc -m32` compiles all 21 current railc TUs clean against the real OWL/RTL headers. This was the original engineering frontier; it is now closed by the 2026-06-11 closeout.
- **W2 — Self-host the RTL.** `SOURCE/RTL/` → `mdcw32.lib` + C0 startup (the foundation everything links).
- **W3 — Self-host BIDS.** `SOURCE/CLASSLIB/` → `mdbids.lib` (container templates OWL/railc use).
- **W4 — Self-host OWL.** `SOURCE/OWL/` → `mdowl.lib` (the big one — PLAN stone S5).
- **W5 — Link the all-mdbcc closure.** railc objs + our libs + our `.res` + OS/CTL3D imports → `railc.exe` (resource binding, imports, startup).
- **W6 — Run & match.** WOW64 run; differential vs the W0 golden across the parity tiers (§2); iterate to parity. **Done.**

Waypoints are a *route*, not a barrier — the bisection oracle lets W1–W5 proceed somewhat in parallel (e.g. compile OWL while the app front-end still has gaps, linking the gaps against prebuilt libs to keep testing).

## 8. Hard constraints (non-negotiable)

- **Never edit `C:\language\railc`** to make mdbcc compile it. railc is a **read-only acceptance corpus** owned by its *own* review/fix campaign. The `bcc32` oracle defines "valid railc"; if `bcc32` compiles a construct, mdbcc must too — **fixes go in mdbcc**. If a construct breaks *both* bcc32 and mdbcc, it's a railc bug for the other campaign, not ours to paper over.
- **Never edit the Borland oracle trees** (`C:\tmp\bc45`, `C:\language\mdbcc\wrk_oracle\...`).
- **`-m32` to both `bcc` and `mdlink`** for every railc/OWL artifact.
- **Green gate before every commit:** 88 byte-identity baselines ×2 + full test suite + `clippy` clean. i386 work stays **byte-additive** (behind `target == TargetKind::Win32`) so win64 byte-identity is preserved.
- **Commit discipline:** each verified increment straight to `main` as `0x4D44` / `martingdavidson@gmail.com`; end messages with `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>`; only `git add` files actually changed; atomic; **never amend or run destructive git ops** (`reset --hard`, `clean -fd`, `push --force`) without explicit written permission. (`git checkout -- <file>` to discard my own experiments is fine.)

- **Fully-qualified absolute paths** in all references.

## 10. Known risks (honest)

1. **Scale.** This is the *culmination*, not an increment — months of grind (PLAN budgets S5+S6 at ~9–18 mo). Fine for a perpetual goal; I won't pretend it's near.
2. **OWL/RTL/BIDS are large, template-heavy, and dialect-dense.** Self-hosting them is the bulk of the work (W2–W4). Expect a long tail of dialect-parity fixes.
3. **Resource fidelity.** `RAILC.RC` exercises inline-hex icons/bitmaps, file bitmaps, dialogs, stringtable, RCDATA — mdbcc's rc compiler must match BRC32's binary `.res`/`.rsrc` layout closely enough for the controls to render identically.
4. **CTL3D32 on Win11.** CTL3D is deprecated; the import may resolve to a no-op/absent DLL. A *runtime* concern (both builds share it), not a compile blocker — note if it perturbs parity.
5. **GUI parity is fuzzier than exit codes.** Hence the tiered, screenshot-based oracle (§2/§6) rather than a single diff.
