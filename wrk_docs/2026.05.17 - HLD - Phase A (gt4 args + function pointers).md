# HLD — Phase A: >4 arguments + function pointers

Date: 2026-05-17. Status: DESIGN (impl gated on a clean tree — a
concurrent agent is mid-commit on src/codegen.rs/parser.rs/ast.rs).
Roadmap: `wrk_journals/2026.05.17 - PLAN - OWL Windows roadmap.md`.

## Why
Hard prerequisite for every Win32 call (`CreateWindowEx` = 12 args) and
every callback (`WndProc`). Pure portable C/C++ ⇒ fully validated by the
existing O1 (hand-expected e2e) + O2 (`cl`) + O3 (bcc32 5.5.1
behavioural) oracles. No GUI yet.

## Current implementation (read 2026-05-17, grounded)
- `Gen::new` (src/codegen.rs:364) hard-errors when `f.params.len() > 4`.
- Frame: `frame = (vars_bytes + ntemps*8 + 32 + outgoing + 15) & !15`
  (codegen.rs:403). `+32` = shadow space for callees; `outgoing` = 16
  **iff `uses_io`** (the printf→WriteFile 5th-arg path), written at an
  `rsp`-relative offset. Locals/params live at `[rbp-off]`.
- `run` prologue (codegen.rs:426-430) spills params 0..n via
  `ARG_SPILL[i]` (`mov [rbp-off], rcx/rdx/r8/r9`), i∈0..4 only.
- `emit_call` (codegen.rs:1491) evaluates each arg → temp, then loads
  temps into `ARG_LOAD[base+i]` (rcx/rdx/r8/r9); hard cap `total>4`
  (1513). `lead` = implicit `this` (rcx, base=1). Direct calls are
  `E8 rel32` + `CallSite{at,callee}`; linker resolves by name via
  `offsets[callee]` (pe.rs:262). Imports use `FF 15` RIP through IAT
  (`RipRef::Import`). Variants: `RipRef::{Import,Str,Data}` (pe.rs:273).
- `declarator` (parser.rs:822) handles `*`, `&`, ident, `Tag::member`,
  `[N]`. No `(*name)(params)` form; no function param-type lists; no
  `Type::Func`.

## A1 — >4 arguments (Win64 stack ABI)

### Design
Win64: ints/pointers args 1-4 in RCX/RDX/R8/R9; args ≥5 on the stack
*above* the 32-byte shadow. With `push rbp; mov rbp,rsp`, stack param
`i` (0-based, i≥4) is at `[rbp + 16 + 8*i]` (ret@rbp+8, oldrbp@rbp+0,
shadow rbp+16..48, arg4@rbp+48). Caller writes outgoing stack args at
`[rsp + 32 + 8*(i-4)]` (its own shadow is rsp+0..32).

Changes (src/codegen.rs only for A1):
1. `Gen::new`: delete the `params.len() > 4` error. Generalise
   `outgoing`: walk `f.body` for the max call arity (Call/MethodCall/
   New/Delete incl. implicit `this` and default-arg expansion);
   `outgoing = max(io_need, 8 * max(0, max_total_args - 4))`, keep the
   16-align. Keep the existing `+32` shadow term.
2. `run` prologue: params 0..min(4,n) via `ARG_SPILL` as today; params
   i≥4: `mov rax,[rbp+16+8*i]` → store to `[rbp-off]` (consistent with
   the "everything addressed at [rbp-off]" invariant; minimal).
3. `emit_call`: drop the `total>4` cap. Args at reg-index <4 → `ARG_LOAD`
   as today; reg-index ≥4 → load temp into rax then
   `mov [rsp + 32 + 8*(idx-4)], rax`. Evaluate-to-temps order unchanged
   (already spills all args before loading — no reg clobber risk).

Invariant to preserve: `rsp` stays 16-aligned at every `call`
(`frame & !15`, and push rbp(8)+retaddr(8) keeps it aligned — already
true for the working io path; the generalisation only enlarges the
already-16-aligned `outgoing`).

### TDD (RED first; O1 + new portable corpus)
- `tests/end_to_end.rs`-style (via the in-proc pattern, mirror
  pe_layout.rs to avoid the still-WIP end_to_end.rs): a 6-arg and an
  8-arg pure-int function, result printed (`%d`), exact-stdout + exit.
  RED today = `CodegenError "only 4 are supported"`.
- `tests/corpus/portable/manyargs.c`: 8-arg sum + an 8-arg mixed
  (int/char/pointer) callee, printed `%d`/`%u` — O2 `cl` + O3 bcc32
  behavioural lock it three-way. Strict-C89, deterministic, no printf
  flags (§4.5).
- Regression: all O1 88 + printf 5 + pe_layout 2 + differential stay
  green & byte-identical for ≤4-arg programs (the frame term only
  grows when a >4-arg call exists; ≤4-arg funcs unchanged ⇒ byte-
  identical, same argument as the PE-layout regression proof).

### Risks
- Frame mis-sizing / rsp misalignment ⇒ crash: covered by the
  exact-stdout+exit oracle (a bad frame faults or corrupts the result).
- Interaction with the printf `outgoing=16` io path: take the max, do
  not replace — a >4-arg call *and* printf in the same fn must reserve
  both. Add a corpus case combining them.
- Default-arg expansion & implicit `this` already inflate arity in
  `emit_call`; arity pre-pass must mirror that exactly (use the same
  expansion or over-reserve safely).

## A2 — function pointers

### Design
- `ast.rs`: add `Type::Func { ret: Box<Type>, params: Vec<Type> }`.
  `size`/`align` of `Ptr(Func)` = 8 (function-designator decays to
  `Ptr(Func)` in value context, like arrays). `Type::Func` itself is
  non-storable (only as `Ptr` target / decl base).
- `parser.rs declarator`: parse the `ret (*[name])(paramtypes)` form
  (recurse: `(` `*`+ inner-declarator `)` then `( param-type-list )`),
  and a trailing `( param-type-list )` on a plain declarator = function
  type. typedef'd fn-ptr (`typedef int (*Cmp)(int,int);`) flows through
  `register_typedefs` unchanged once `declarator` yields the type.
  Function/array-of-fn-ptr parameters.
- Address-of-function: a bare function name or `&f` in value context →
  materialise the function address. New `RipRef::Func(String)` resolved
  in pe.rs exactly like a call target (`offsets[name]` → RVA), emitted
  as `lea reg,[rip+disp32]` (mirrors `RipRef::Import` shape; one new
  match arm at pe.rs:273-area + reuse the func `offsets` map at :262).
- Indirect call: when the callee expr is a value of `Ptr(Func)` (not a
  statically-known name), evaluate it to a temp, marshal args via the
  shared A1 path, then `call rax` (`FF D0`) instead of `E8 rel32`
  (no CallSite). `(*fp)(a)` and `fp(a)` both lower to this.
- Storage/compare/assign of fn-ptr values: already work once the value
  is an 8-byte address (existing pointer machinery).

### TDD (RED first; O1 + portable corpus)
- e2e (in-proc): fn-ptr variable called; array of fn-ptrs dispatched
  by index; a higher-order helper `int apply(int(*)(int),int)` invoked
  with a passed callback (qsort-shaped, no libc) — result printed,
  exact stdout+exit. RED today = parse error / unsupported.
- `tests/corpus/portable/funcptr.c`: callback-table dispatch, printed
  `%d` — O2 + O3 three-way (bcc32 fully supports fn pointers).
- Regression: O1/printf/pe_layout/differential green & byte-identical
  (new Type variant + new RipRef arm are additive; no ≤A1 path bytes
  change).

### Risks
- pe.rs touch (new `RipRef::Func` arm): pe.rs is currently committed/
  clean, but the *concurrent commit agent* may still be active — apply
  A2's pe.rs change only on a confirmed-clean tree; keep it to one
  additive match arm + reuse of the existing func `offsets` map (no
  layout/byte change for non-fn-ptr programs — same regression
  argument as the PE-layout fix).
- Declarator grammar is the classic C "spiral"; bound scope to the
  forms OWL/Win32 actually use: `Ret (*)(args)`, typedef'd, as a
  param/field/local/global. Defer fn-returning-fn and exotic nesting
  (error clearly, never silently wrong — matches house style).
- Member function pointers (OWL response tables) are **Phase E**, not
  A2 (different ABI: this-adjustment). A2 = free-function pointers
  only; record that boundary explicitly so Phase E owns the rest.
