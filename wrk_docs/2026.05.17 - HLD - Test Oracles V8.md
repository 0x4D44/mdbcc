## 1. Purpose

Define the minimum oracle set that makes the autonomous build loop
trustworthy, and pin down *exactly* what "behaviourally equivalent" means
so a differential cannot manufacture false signal or sit silently green.
Quality stance (CLAUDE.md): solve the problem at hand, no speculative
abstraction, no migration/rollback, **no feature flags, minimal env
vars**. V8 adds nothing speculative — it deletes a deferral that reality
removed.

## 4. O2 and O3 — the new differential oracles (both v1)

### 4.1 Corpus is NEW files, not a retrofit
The ~120 e2e program invocations are Rust string literals/fragments
(several per test); there is no on-disk corpus, and an extractor for our
own test file would be fragile overengineering. Instead:

- `tests/corpus/portable/*.c` — small, hand-authored complete TUs in the
  **mdbcc ∩ MSVC ∩ bcc32** intersection: deterministic, input-free,
  UB-free, avoiding mdbcc's known gaps (§4.5). Compared by **both** O2
  (`cl`) and O3 (`bcc32` behavioural).
- `tests/corpus/dialect/*.c` — Borland-dialect programs. MSVC is excluded
  for these **by construction** (O2 never sees them). They are **O3**:
  in v1 they get `bcc32 -c` **acceptance** (and behavioural where the
  program is pointer-size-agnostic and dialect-runnable). They also keep
  the mdbcc **front-end parse-smoke** tripwire (mdbcc compiles them;
  assert no error/panic — no behavioural claim; mdbcc silently drops
  unrecognised constructs, so a green smoke is *not* evidence the feature
  is supported — §6 coverage line says `dialect-smoke (tripwire)`).
- `tests/end_to_end.rs` (O1) is untouched and remains authoritative.

### 4.2 Reference builds
- **O2 (`cl`)**: `cl /nologo /MT <src> /Fe:<out>` in a per-invocation dir
  `target/oracle/<pid>_<n>/` (avoids `*.obj` collisions under parallel
  `cargo test`). `/MT` (static CRT) ⇒ self-contained `ref.exe`. No
  `/EHsc`, no `/O2` (codegen comparison is a non-goal).
- **O3 (`bcc32`)**, validated invocations (spike-confirmed):
  - acceptance: `bcc32 -q -c -I<BCC55\Include> <src>` (exit 0 + `.obj`).
  - behavioural: `bcc32 -q -I<BCC55\Include> -L<BCC55\Lib> -e<out.exe>
    <src>` (bcc32 drives `ilink32`).
  - `wrk_tools\BCC55\Bin` must be on the child's `PATH` (runtime DLLs
    `cc3250.dll`, `rw32core.dll`). Per-invocation dir as for O2.
  - **Sandbox:** bcc32 (and bcc32-produced exes) run **sandbox-off**,
    scoped strictly to this O3 step writing into the git-ignored
    per-invocation dir (Arthur-authorised standing policy, §9). mdbcc and
    `cl` continue to run sandboxed.

### 4.3 `cl` discovery + representative probe (validated as written)
Locate `vswhere.exe` at its known path → resolve `vcvars64.bat`. Capture
its env with `cmd /c "\"<vcvars64>\" >NUL 2>&1 && set"`, keep only lines
matching `^[A-Za-z_][A-Za-z0-9_()]*=`, split on the **first** `=`, cache
in a `OnceLock`. Success criterion = a **known-answer probe build**:
`#include <stdio.h>\nint main(void){ printf("%d %u %lld\\n", -7,
4294967295u, 4294967295LL); return 7; }` built with the **exact §4.2 O2
command line and flags**, then run — the harness asserts the
**Rust-computed** expected bytes `-7 4294967295 4294967295\n` (after
§4.4.3 normalisation) **and** exit 7. *(Spike 2026-05-17: this exact
sequence produced exit 7 and raw `…\r\n`, matching the asserted bytes
post-normalisation — validated, no change.)* Three loud states:
`cl ACTIVE`, `SKIP: cl not found`, `SKIP: cl found but environment
unusable`. bitness implied by a working x64 stdio exe.

O3 has an analogous **liveness check** (cheap, not a known-answer probe —
acceptance is its own strong signal): on first use, statically confirm
`wrk_tools\BCC55\Bin\bcc32.exe` exists, then `bcc32 -c` the §4.3 probe
source minus `%lld` (bcc32 5.5.1 predates `long long`); exit 0 ⇒
`O3 ACTIVE`, else `SKIP: bcc32 not present/usable`. O3 self-skips
(never silently green) exactly like O2.

**Health guards.** With `cl` ACTIVE (and, independently, `bcc32`
ACTIVE), three observable conditions per reference, each a deterministic
function of counts collected this run (no undefined state, no
auto-attribution of a culprit). Evaluated **independently, may co-fire**;
none suppresses another. Each, when it trips, **fails the test process
(non-zero exit / panicking assertion), halting the loop until a human
clears it** — an *oracle-health halt*, explicitly **not** an mdbcc
correctness verdict (O1 remains authoritative; a non-blocking banner
would be silently green to an autonomous loop — the exact failure this
document exists to prevent). `WARN`/`STOP` denote triage severity only —
**all halt**:
- **0** non-skip corpus files successfully compared ⇒ loud WARN
  (compared nothing), not green;
- **≥5 and ≥25 %** of non-skip files **fail to build/launch** ⇒ loud
  WARN (toolchain broken), not green. (Absolute floor stops one
  transient failure on the explicitly-small v1 corpus tripping a
  corpus-wide WARN.)
- **≥5 and ≥25 %** of *compared* files **FAIL** ⇒ a loud
  `STOP: <ref> broad-divergence — triage required`: **never green, never
  an auto-attributed verdict** (neither a clean "mdbcc broken" red nor a
  "reference's fault" exoneration). Below this floor, per-file FAILs are
  **not** escalated — they stay normal, actionable mdbcc reds (post §4.5
  UB-triage); that per-file band is the everyday value and must remain
  reachable on a small corpus. FAILs are preserved as evidence; the
  banner carries *diagnostic hints only* (the `cl`-only known-answer
  probe state; the build/launch-failure fraction; any §4.5
  reference-instability WARNs). The probe is demoted to a hint *only
  here*; it still authoritatively **gates O2 activation** (a failed
  probe ⇒ SKIP, never ACTIVE). Rationale: a narrow probe cannot license
  auto-blaming mdbcc for arbitrary broad disagreement, nor may broad
  divergence auto-exonerate a genuine mdbcc regression. Honest posture:
  at ≥25 % divergence the oracle is **not a trustworthy pass/fail oracle
  for this run and says so loudly**; O1 remains authoritative
  throughout; sub-threshold per-file FAILs remain normal actionable
  mdbcc reds after §4.5 triage. *(The guards are evaluated per reference:
  a broad O2 STOP and a broad O3 STOP are independent; O3 also self-skips
  when bcc32 is absent.)*

### 4.4 Equivalence is defined as
A corpus program **passes** iff, for mdbcc's exe and the reference exe
(`ref_cl.exe` for O2, `ref_bcc32.exe` for O3 behavioural):

1. **Primary observable is stdout, not the exit code.** Corpus programs
   compute a result and report it via `printf("%d\n", r)` / `%u` etc.,
   then `return 0;`. Recovers full-range coverage (negative, >255,
   unsigned) through a channel where mdbcc and the reference CRT are
   byte-equivalent post-normalisation, and removes exit-code-range
   ambiguity. (O1 keeps deliberate -7/255/0x7FFFFFFF returns; O2/O3
   route that via stdout.) The print directive **must match the
   result's signedness** (`%d` signed, `%u` unsigned) — a mismatch makes
   *both* sides emit the same wrong text ⇒ false PASS.
2. **Exit code** is still compared, as the `i32` from
   `std::process::ExitStatus::code()` on *both* sides (never mixed with
   `u32`); normally 0. `None` (killed/no code): only mdbcc ⇒ **FAIL**;
   both ⇒ **EXCLUDE**. Crash codes (high byte `0xC0`/`0x80`,
   `STATUS_*`): mdbcc-only ⇒ **FAIL**, both ⇒ **EXCLUDE** — two crashes
   are *not* agreement. *(Spike: exit codes 88 / 7 / 0 round-trip
   identically across mdbcc, cl, bcc32 — validated.)*
3. **stdout** captured as **raw bytes (no string decode), read bounded
   (8 MiB; overflow ⇒ `WARN: <file> output-overflow — likely
   miscurated`, then EXCLUDE)**; compared byte-equal **after** stripping
   a `\r` immediately preceding each `\n` on *both* streams. **Spike-
   confirmed and now general:** MSVC CRT *and* Borland bcc32 CRT both
   emit `\n`→`\r\n`; mdbcc emits raw `\n`. This single normalisation is
   **necessary** (else 100 % false-FAIL) and **sufficient** across all
   three compilers — no other normalisation. Documented blind spot: O2/O3
   cannot catch a newline-encoding bug — O1's byte-exact check still can.
4. **stderr**: **not** in the pass/fail tuple (CRT-vs-no-CRT asymmetry;
   bcc32 also prints a banner unless `-q`); captured for diagnostics
   only.

For O3 **acceptance**, equivalence is degenerate: pass iff `bcc32 -c`
exits 0 (and an `.obj` is produced); a non-zero exit is a real signal
that authentic Borland source mdbcc claims to support is rejected by the
genuine front-end — triaged like any O3 FAIL.

### 4.5 Mandatory corpus filters (else the differential lies)
- **mdbcc printf gap**: no `%`-directive with flags/width/precision/
  length modifiers (mdbcc ignores them today ⇒ `"%5d"` diverges). A real
  mdbcc gap O2/O3 should later drive fixing, not just curation.
- **Deterministic, input-free, UB-free.** UB/impl-defined exclusion is
  **hand-curated**: a leading `// oracle: skip <reason>` excludes a file
  from differential comparison. **Sole primary UB gate**; no automated UB
  analysis (explicit non-goal).
- **Pointer-size filter (O3 behavioural / bcc32 only).** bcc32 5.5.1 is
  Win32 (ptr = 4); mdbcc targets Win64 (ptr = 8). A leading
  `// oracle: skip-bcc32-behaviour <reason>` excludes a file from the
  **bcc32 behavioural** arm only — it still gets O2 (`cl`) and O3
  **acceptance**. Curated by hand alongside the UB gate. (Removed if
  bcc64 — Win64, ptr = 8 — is later acquired, §8.)
- **Advisory only** (not an exclude, not an exoneration): also build a
  second `cl` reference at the §4.2 command line **plus `/O2`**; if the
  two disagree, emit `WARN: <file> reference-unstable — hand-curate`.
  Never auto-EXCLUDEs, never exonerates mdbcc. Rationale: `/Od`==`/O2`
  does not imply "no UB" (hardware/layout-deterministic UB agrees across
  modes), `/Od`≠`/O2` does not imply UB. Triage a surprising FAIL for UB
  **before** attributing to mdbcc; the WARN just flags candidates.

### 4.6 Execution robustness
Every child runs under a fixed **10 s wall-clock timeout**; exceeded ⇒
kill ⇒ mdbcc-only = FAIL, both = EXCLUDE. A **reference** launch failure
or recognised AV-quarantine of a freshly written file is retried
**once**, then reported as a distinct "reference failed to launch" state
— never conflated with a behavioural disagreement (applies to both
`cl`-built and `bcc32`-built reference exes). An **mdbcc-exe**
launch/crash is reported on **first occurrence and never retried**
(retrying could mask a nondeterministic mdbcc crash as a pass — fail
toward exposing mdbcc). *(Spike: mdbcc verified byte-deterministic on a
representative program — same source ⇒ identical SHA-256 across builds;
this is asserted, not assumed: §6 keeps a cheap compile-twice guard.)*

## 5. O5 — structural-decode sanity (v2, honest scope)

Linear-decode the whole `.text` with `iced-x86` (`[dev-dependencies]`
only; Arthur pre-approved; never linked into the shipping binary). Assert
**(a)** zero `INVALID` instructions and **(b)** decoded boundaries
exactly tile `[0, text.len())` (no gap/overlap/undecodable tail).
`rel32`-target range-checking is decided **when O5 is built (v2)**, not
pre-committed.

Honest claim: O5 proves bytes are **well-formed x64**, *not*
**semantically correct** — a typo'd-but-legal opcode passes O5 and is
caught only behaviourally. Unique value: catching truncated/garbage/
out-of-bounds emission on a path O1/O2/O3 don't take. Precondition: valid
only while `.text` is pure code (true today; revisit if jump tables land
in `.text`).

## 6. Engineering (simple, concrete, no premature abstraction)

- **Compiler-under-test path hazard (NEW, spike-found).** A stale
  `bcc.exe` (a *copy of mdbcc*) is on `PATH` at `c:\apps\bcc.exe`. The
  harness MUST invoke mdbcc by its **cargo build artifact path**
  (`CARGO_BIN_EXE_bcc` in integration tests, or the resolved
  `target/<profile>/bcc.exe`) — **never** by the bare name `bcc`. A
  PATH-resolved `bcc` would silently test a stale, possibly-divergent
  binary and manufacture false signal.
- **Two concrete references now justify a shared shape.** v1 has
  `fn msvc_ref(src) -> RunOutcome` **and** `fn bcc32_ref(src) ->
  RunOutcome`. The V7 trigger ("extract a shared shape only when two
  concrete impls exist") is now met — but the spike proved the *only*
  shared logic is the §4.4 equivalence/normalisation comparator
  (identical for both; bcc32 CRT == cl CRT re `\r\n`). Factor **only the
  comparator** into one helper taking `(mdbcc_out, ref_out)`; keep the
  two build/discovery functions concrete and separate (no `Reference`
  trait — build commands, discovery, and the pointer-size filter differ;
  a trait would abstract nothing useful).
- One module `tests/differential.rs` + a small support module. Corpus =
  directories globbed; only metadata conventions are
  `// oracle: skip <reason>` and `// oracle: skip-bcc32-behaviour
  <reason>`. No manifest/schema/stdin DSL.
- **Determinism guard (cheap, keep).** One property test compiles a
  representative corpus file twice with mdbcc and asserts byte-identical
  output (spike showed this holds; codegen uses `HashMap`s, so guard it
  rather than assume it). Not an oracle — a tripwire against accidental
  nondeterministic emission.
- **Self-skip, never silently green.** Every run prints a one-line
  coverage summary, e.g. `oracles: O1 ACTIVE | O2 ACTIVE | O3 ACTIVE
  (bcc32 5.5.1: accept+behave) | dialect-smoke (tripwire)`. **O1 is the
  authoritative gate at all times.** "Zero external differential oracles
  active", the §4.3 compared-nothing / build-launch WARNs, and the
  (≥5 and ≥25 %) `STOP: <ref> broad-divergence` are loud, never green,
  and **fail the test process to halt the loop** (oracle-health halt,
  not an mdbcc verdict); no auto-attribution of broad divergence.
- Artifacts under `target/oracle/` (already git-ignored). bcc32 / its
  exes run sandbox-off **only** within this per-invocation dir (§4.2,
  §9).
- **Precondition (DONE):** `wrk_tools/` and `wrk_corpus/` are in
  `.gitignore` (verified `git check-ignore` exit 0).

## 7. Non-goals / recorded pushbacks (do not re-litigate)

- No machine-code comparison vs MSVC/BCC (optimiser noise).
- Perf/compile-time never gated; not designed here.
- MSVC is **not** a reference for Borland-dialect source; `dialect/` is
  O3-only, MSVC-excluded by construction. bcc32 disagreeing with MSVC on
  dialect code is **expected**, not "UB to exclude".
- "All *available* references must agree" is the whole rule — now with
  three references (mdbcc vs cl vs bcc32) on portable code. No named
  triangulation model.
- O2 **and O3** never auto-attribute broad divergence to a culprit
  (≥5 and ≥25 % compared-FAIL ⇒ loud non-attributing triage-STOP).
- The `/Od`-vs-`/O2` check is **advisory only** (§4.5).
- O5 is structural sanity only — not a codegen-correctness oracle.
- No automated UB analysis; the corpus is curated.
- bcc64 (Win64) is **not** in v1 scope — best-effort v3 (§8). bcc32-5.5
  Win32 + pointer-size filter is the v1 dialect reference.

  not a bug — the §4.5 `skip-bcc32-behaviour` filter is **mandatory**
  for the behavioural arm; acceptance is unaffected. Mis-curation here
  manufactures false FAILs — treat the filter as part of the oracle.
- Provenance: bcc32 came from the Internet Archive (sha-256 recorded). It
  is genuine 25-year-old Borland; run only sandbox-off within the scoped
  O3 dir (§9). Not re-downloaded per run (cached in `wrk_tools/`).
- Defender may quarantine freshly written unsigned exes under O2/O3
  churn; recommend a documented Defender exclusion for `target/oracle/`;
  launch-failure is a distinct retried state for the reference side only.
- bcc32 needs `BCC55\Bin` on the child `PATH` for its runtime DLLs
  (spike-confirmed); the harness sets this per-invocation, not globally.
