# PLAN — mdbcc to ultimate goal: BCC 4.52 conformance

Date: 2026-05-26. Authored by supervisor after Arthur set the ultimate
goal and confirmed five framing decisions. **Supersedes**
`2026.05.22 - PLAN - Compiler completion (J + N + tail).md`.

The May-22 plan defined "100% complete" as three OWL apps green via a
synthetic OWL substrate. Arthur subsequently sharpened the goal:
**recompile real legacy BCC source so it runs on Windows 11**, with a
32-bit WOW64 stepping stone permitted on the way to native 64-bit.

The May-22 plan's Stage J (J-1 … J-21) is done; its Stages K-N are
**retired** and replaced by S0-S8 below. Outstanding J polish items
(G-1/G-2/G-3 inline-method bugs, J-17 coverage wiring, J-13c variadic
virtual methods, etc.) are folded into S1 as opportunistic-fix items
because the single-TU back end they live in is being rewritten anyway.

---

## 0. The destination, sharpened

**A multi-file C/C++ source tree written for BCC 4.5/4.52 (Win3.x or
Win32 + OWL/ClassLib/RTL) builds with `mdbcc + mdlink` and runs on
Win11 x64 — first as a 32-bit WOW64 PE, then as a native 64-bit PE —
with observable behaviour matching the BCC-built reference.**

"Observable behaviour matches" = same exit codes, same stdout, same
window appearance (mdscreensnap diff under tolerance), same response
to scripted message injection. Pixel-perfect repaint is the bar for
the GUI samples shipped on the CDs.

Explicitly **out of scope** to keep the goal finite:
- 16-bit codegen / NE format (Win11 x64 cannot run NE; recompile the
  source as 32-bit instead — most Win3.x BCC apps' source compiles as
  32-bit because OWL handles the `_far`/`_huge` indirection via
  conditional compilation).
- The Borland IDE (`BCW.EXE`). We are a compiler, not an IDE.
- VBX, OWL DDE, OLE2 — defer unless an in-scope sample demands.
- DPMI / Win32s.
- BCC 5.x / OWL 5.x — out of scope for the plan; S8+ if Arthur
  re-opens.

## 1. Decisions (recorded 2026-05-26)

Arthur confirmed all five framing decisions:

1. **Object format**: COFF only. We never read Borland's pre-built
   OMF `.lib` files; everything is rebuilt from source on the CDs.
2. **Order**: 32-bit-first (S2 before everything OWL-related). We do
   more total work but gain a working demo years sooner and a
   byte-level differential oracle on every PE.
3. **Compiler version**: BCC 4.52 only. BCC 5.x is S8+ if at all.
4. **Multi-TU sequencing**: S1 starts next. Outstanding J polish
   items fold into S1 opportunistically; the single-TU back end is
   being rewritten anyway.
5. **codegen.rs split**: bundle into S1 (rewrite the back end once,
   in flight, while it's being restructured for COFF emission).

## 2. The hard architectural truths

To reach the goal, **all six** of these must become true. None is
currently true. Skipping any one means the goal isn't met.

| # | Truth | State today | Cost |
|---|---|---|---|
| **T1** | Compiler emits object files; a separate linker produces the PE | Single-TU, PE-direct | Big — touches codegen.rs end-to-end |
| **T2** | Real Borland source compiles: headers + OWL + ClassLib + RTL | Hand-rolled stubs | Bounded by what real source actually uses |
| **T3** | C++ feature parity for BCC 4.5 dialect (templates, MI, RTTI, namespaces, exception specs, member templates, full operator overloading) | Templates absent; MI absent; RTTI partial | Templates alone: many months |
| **T4** | 32-bit x86 codegen (`__cdecl` / `__stdcall` / `__fastcall`) | Win64 only | Months — second register set + ABI |
| **T5** | 64-bit retarget of OWL itself (source mods to OWL, not to the compiler) | Never attempted | Bounded — OWL is finite (~50-80k LoC) |
| **T6** | Static init / global ctor ordering, real `.def` parser, real COFF `.lib` emission, `.res` merge, CRT startup correctness | Partial `.res`; no `.def`, no `.lib`, no proper CRT | Months but well-understood |

These are linearly dependent in only one place: T1 unlocks T2/T3/T4.
Everything else has scheduling flex.

### S1 — Multi-TU + COFF + linker (3-6 months)

The architectural fork. Three sub-phases:

**S1a — Codegen restructure for object emission.** Split codegen.rs
(8302 LoC) into modules along the natural seams: `codegen/expr.rs`,
`codegen/stmt.rs`, `codegen/decl.rs`, `codegen/cpp.rs`, `codegen/abi
.rs`. Already-extracted `eh.rs` stays. **No PE emission yet** —
new entry point `emit_object(unit) -> Object` produces an in-memory
IR (sections, symbols, relocations) detached from PE writer.

**S1b — COFF writer.** Implement `coff::write(obj, out)`. Section
table, symbol table, string table, relocation tables. Target: x86_64
COFF first (matches current Win64 codegen). Validated by O13: each
emitted `.obj` decodes through `dumpbin /symbols` to the same symbol
set as bcc32's `.obj` for matching source (modulo name mangling — see
S1c). The IMAGE_FILE_MACHINE_AMD64 path is the simplest start.

**S1c — Linker (`mdlink`).** New binary in `src/bin/mdlink.rs`. Reads
COFF `.obj` and `.lib` (`.lib` = ar-style archive of COFF members);
resolves external symbols; produces PE32+. Inherits the PE writer
from current `pe.rs` (which becomes the linker's back end). Static
initialization via `.CRT$XCU` array convention (matches MSVC); CRT
startup stub generated by mdlink, calls `__do_global_ctors` then
`main`/`WinMain`.

**Critical sub-decisions:**
- **Name mangling**: adopt Borland's mangling exactly (it differs
  from MSVC/Itanium). Audit one bcc32-emitted `.obj` per ASCII name
  to derive the algorithm; document. This is what makes O14 (round-
  trip with `tlink32`) possible.
- **Calling convention**: still Win64 in S1; Win32 conventions in S2.
- **`.def` files**: minimal parser (EXPORTS, NAME, DESCRIPTION,
  STACKSIZE). Defer DLL output to S5 / S8.
- **CRT**: minimum viable. Compile a subset of `\BC45\SOURCE\RTL\`
  needed for `printf`, `malloc/free`, `exit`. Real Borland source.

**Outstanding J items folded in here**:
- G-1 / G-4 (inline member returning own class by value, class record
  not finalised) — fix during S1a parser/AST cleanup, since the AST
  is being touched anyway.
- G-2 / G-3 (operator+ returning class by value not materialised) —
  same; the materialisation path lives in the expr codegen module.
- G-5 (`obj.operator+(rhs)` parser arm) — trivial; bundle.
- J-13c (variadic virtual methods, ctors/dtors with `...`,
  variadic + record-return) — fix when the variadic ABI moves through
  the new abi.rs module.
- J-12b (dtor-throws-while-unwinding terminate detection) — fix in
  eh.rs which is already split out.
- J-17 (`cargo llvm-cov` wiring) — wire as part of S1 CI; coverage
  delta becomes a journal line per tick (as planned).
- J-20b (`FIXTURES` extraction from `o1_byte_identity.rs`) — fix
  in passing if a tick has slack.
- J-11b (SEH refinements — implicit-default, member-init partial-
  construction) — only if surfaced; otherwise S8.

**Exit**: `mdbcc -c foo.cpp` produces COFF `foo.obj`; `mdlink foo.obj
bar.obj -lc -o foo.exe` produces a runnable PE32+; two-file program
runs; all 681 prior tests still green via the new pipeline; O13 +
O14 oracles green.

### S2 — 32-bit x86 backend (3-6 months)

Add PE32 (Win32-x86) emission alongside PE32+ (Win64). Driver flag
`-m32` selects.

Sub-phases:
- **S2a**: x86 instruction encoder (new `codegen/x86_encode.rs`).
  ModR/M, SIB, displacement, immediate. Far less than x64 because
  we skip REX prefixes and 64-bit operand forms.
- **S2b**: Win32 calling conventions in `codegen/abi.rs`:
  - `__cdecl` (caller cleans stack, args right-to-left, no register
    args).
  - `__stdcall` (callee cleans, args right-to-left, name `@N` suffix).
  - `__fastcall` (first two args in ECX/EDX, rest on stack, name `@N`
    prefix). Borland's variant differs slightly from MS — match
    Borland.
  - `__pascal` (used in early OWL; left-to-right, callee cleans).
- **S2c**: COFF writer extension for IMAGE_FILE_MACHINE_I386.
- **S2d**: PE32 writer extension in linker (PE32 has different
  optional header size, no `.pdata`/`.xdata` requirement since SEH on
  x86 uses fs:[0] chain not table-based unwind).
- **S2e**: x86 SEH (different from x64). Borland and MSVC both use the
  fs:[0] exception chain; our personality function ports across.
  Validate with the existing EH test corpus rebuilt as 32-bit.

**Exit**: 88-program portable C corpus compiles + runs as 32-bit on
Win11 x64 (via WOW64); exit codes + stdout match BCC32 reference for
≥ 90% of cases (the rest are flagged for investigation). O12 oracle
green.

### S3 — Real Borland headers (3-6 months)

Stop using `OWL_RUNTIME_H` / `WIN32_PROLOGUE` substitutes. mdbcc
preprocessor reads `\BC45\INCLUDE\` directly. This is where most
remaining preprocessor and C language gaps will surface.

Preprocessor work:
- Full hide-set semantics (X3J11 algorithm, not the
  re-include-protect hack).
- System header search (`<...>` first searches system paths, then
  user). Multiple `-I` paths, ordered.
- `#pragma once`, `#pragma hdrstop`, `#pragma argsused`, `#pragma
  warn`, `#pragma pack(push/pop, n)` — at minimum recognised; some
  acted on.
- Predefined macros: `__BORLANDC__`, `__BCPLUSPLUS__`, `__TURBOC__`,
  `__MSDOS__` (off for 32-bit), `_WIN32`, `__WIN32__`, `__FLAT__`,
  `__CONSOLE__` etc. Match BCC's predefined set per `\BC45\DOC\`.
- Function-style macros with stringification, token paste, variadic
  not required in BCC 4.52 (C89 era).

C language work surfaced by real headers (predicted):
- `_pascal`, `__pascal`, `_cdecl`, `__cdecl`, `_stdcall`, `__stdcall`
  as keywords (with leading underscore variants).
- `_huge`, `_far`, `_near` — accepted as no-ops in 32-bit flat.
- `__declspec(dllimport)`, `__declspec(dllexport)`, `__declspec(naked)`
  — at minimum recognised.
- Bit-fields with non-int base types.
- `__interrupt` (Borland) — recognise and ignore for 32-bit user code.
- Anonymous structs/unions in struct members.

**Exit**: A Petzold-style Win32 sample (`HELLOWIN.C`, ~150 LoC,
classic) using real Borland `<windows.h>` builds and runs (32-bit).
O15 header-acceptance oracle: every `.h` in `\BC45\INCLUDE\` parses
through `mdbcc -E` without error (no requirement they semantically
type-check yet — that's S4/S5).

### S4 — C++ dialect parity (6-12 months)

Templates first; everything else is bounded.

**Templates** (the big one):
- **Class templates**: `template <class T> class Foo { ... };` with
  declaration / definition / specialization / explicit instantiation.
- **Function templates**: argument deduction (no SFINAE — BCC 4.52
  predates the formalisation).
- **Member templates**: `template <class U> Foo<T>::convert<U>() {}`.
- **Default template arguments**: `template <class T = int>`.
- **Partial specialization**: simple cases (`template <class T> class
  Foo<T*> {};`).
- **Nested templates / dependent names**: pragmatic resolution — BCC
  4.52 was loose about two-phase lookup.
- **NOT in scope**: SFINAE, variadic templates, alias templates,
  template template parameters (rare in BCC source), `constexpr`.

Mangling for templates: instantiation-aware. Each instantiation gets
its own external symbol; comdat groups (`.text$X`) for unique-link
dedup in the linker.

**Multiple inheritance**:
- Non-virtual MI: vtable per base, `this`-adjustment thunks on calls
  through pointers/references to secondary bases.
- Virtual bases: shared subobject; vbase pointer or offset in primary
  vtable.

**RTTI**:
- `typeid(expr)` producing `type_info&`.
- `dynamic_cast<T*>(p)` and `dynamic_cast<T&>(r)`.
- Type info chain matches Borland's layout (audit `\BC45\INCLUDE\
  typeinfo.h` + an example `.obj`).

**Namespaces**: basic. `namespace foo { ... }`, `using namespace
foo;`, `using foo::bar;`, `namespace foo = bar;`. Argument-dependent
lookup (Koenig) — minimal, just operator lookup for `std::`-style
patterns.

**Exception specifications**: parsed and stored; `throw()` enforced
as terminate-on-throw (Borland's behaviour). Other lists informational.

**Other dialect gaps** (likely surfaced by real source):
- Default arguments anywhere (already partial).
- Member-function pointer corner cases (already largely done; J-14b
  closed virtual MFPs).
- Placement new (`new (ptr) T(...)`) — likely already works; verify.
- Function-try-blocks (`try { ... } catch ...` as function body) —
  used by some OWL constructors.
- `__property` and `__closure` — assess whether OWL 2.5 uses; if
  not, defer to S8.

**Exit**: A test fixture building `TArrayAsVector<int>` (BCC's BIDS
template container) compiles, instantiates, runs. Differential
against bcc32 of the same fixture green. Single MI+RTTI fixture green.

### S5 — Build OWL from source (6-12 months)

Compile `\BC45\SOURCE\OWL\` end to end as 32-bit. Produce `mdowl.lib`
(COFF archive). Bring in `\BC45\SOURCE\CLASSLIB\` (BIDS container
templates) as `mdclasslib.lib`. Bring in `\BC45\SOURCE\RTL\` for any
CRT dependencies not yet done.

Approach: iterative. Try to compile each OWL source file. Bug surfaces
in mdbcc → fix → continue. Track per-file status in
`wrk_journals/2026.05.?? - JRN - OWL build progress.md`.

OWL has its own internal idioms that will exercise S4 thoroughly:
- Response tables (`DECLARE_RESPONSE_TABLE`, `DEFINE_RESPONSE_TABLE`)
  — macro-heavy, expand to per-class static dispatch tables.
- `_USERENTRY` calling-convention macro.
- `TMessage` cracker macros.
- `TStreamableBase` + persistent-streams machinery (heavy template
  use).

**Exit**: `mdowl.lib` produced; A/B build of one Borland OWL example
linked against (i) Borland's `owl.lib` from CD and (ii) our `mdowl
.lib` — both runs produce identical observable behaviour. O16 green.

## 5. Oracle ladder (extends O1-O11 from prior plans)

| Oracle | What it asserts | Active from |
|---|---|---|
| **O12 — BCC32 source-to-behaviour** | Identical source through mdbcc vs bcc32 → identical exit code + stdout | S2 onward |
| **O13 — BCC32 source-to-OBJ structure** | mdbcc-emitted `.obj` has same external symbols, sections, relocations as bcc32-emitted (modulo ordering) | S1 onward |
| **O14 — TLINK32 link-equivalence** | Our `.obj` links cleanly through TLINK32; bcc32's `.obj` links cleanly through `mdlink` — both directions | S1 onward |
| **O15 — header acceptance** | Every `.h` in `\BC45\INCLUDE\` parses through `mdbcc -E` without error | S3 onward |
| **O16 — OWL build differential** | `mdowl.lib` and Borland's `owl.lib` produce same observable behaviour for the same OWL example | S5 onward |
| **O17 — sample app behavioural parity** | Each `\BC45\EXAMPLES\` sample built two ways behaves identically | S6 onward |
| **O18 — 32-bit vs 64-bit OWL parity** | Same OWL sample, built 32-bit (S6) and 64-bit (S7), same observable behaviour | S7 onward |

**O14 is the killer oracle**: if TLINK32 accepts our `.obj` AND we
accept bcc32's `.obj`, we cannot drift from Borland's object format
silently. Highest leverage per dollar of harness investment. Build the
harness for O13+O14 first in S1.

## 7. Risk register

- **R1 — Templates are a year on their own.** BCC 4.5-era templates
  predate the 1998 standard (no SFINAE, no variadic, no two-phase-as-
  mandated). Easier than modern C++, still substantial. **Mitigation**:
  implement only what real Borland source uses; surface-driven not
  spec-driven.
- **R2 — OWL may have non-trivial 64-bit issues.** Event vector
  tables, MFP dispatch, message cracker macros all written for 32-bit
  pointer-size. **Mitigation**: S0 produces the OWL fitness audit;
  S7 has a concrete fix-list before it starts.
- **R3 — BCC's CRT startup is intricate.** Global ctor ordering,
  `_setargv`, `_initterm`, `__chkstk`, `_DllMainCRTStartup`. RTL
  source is on the CD. **Mitigation**: rebuild from CD source; never
  reverse-engineer.
- **R4 — BCC32 may not run cleanly on Win11 x64.** WOW64 is reliable
  for normal 32-bit Win9x console apps, but BCC32 might use
  undocumented patterns. **Mitigation**: S0 confirms; fallback is
  Win98/XP VM with shared folders. Arthur decision point if the
  fallback is needed.
- **R5 — Self-graded oracle persists until S6.** The 88-program
  corpus is still ours-grading-ours until bcc32 differential lands
  in S2. **Mitigation**: don't add to it speculatively; favour bcc32-
  differential tests in S2.
- **R6 — Estimates are honest but soft.** 2-3 years is my best
  guess. Individual stones can blow up. **Mitigation**: re-baseline
  after each stone; the stones are independently demoable, so
  schedule risk is bounded per-stone, not total.
- **R7 — Dialect contract is still vague.** Tightened progressively
  as each stone consumes more real source. By S5 it is pinned to
  "what BCC 4.52 accepts and what Borland's own source uses." Until
  then it is internally measured.
- **R8 — TLINK32 quirks.** Borland's TLINK32 has its own .obj
  acceptance quirks (idiom-level, not spec-level). Mitigation: O14
  oracle catches divergence immediately.
- **R9 — codegen.rs split risk during S1.** 8302 LoC restructure
  while the back end is changing semantics is risky. Mitigation: do
  the restructure first in S1a as a pure refactor (tests green
  throughout), then change semantics in S1b.
- **R10 — Multi-TU symbol resolution complexity.** External symbols,
  weak symbols, comdat dedup. Bounded but new for us. Mitigation:
  start with simplest case (single external function call between
  two .obj files) and grow.
- **R11 — `\BC45\INCLUDE\` files may contain BCC bugs.** Real
  shipped headers often had compiler-specific workarounds. We may
  reject valid Borland source. Mitigation: O15 doesn't require
  semantic acceptance, just preprocessor acceptance; semantic fixes
  iterate during S4/S5.
- **R12 — OWL's persistent-streams machinery.** `TStreamableBase`
  uses extensive template machinery + ctor dispatch tricks. May
  require dialect features beyond S4's plan. Mitigation: if S5
  surfaces a gap, treat as S4-extension and loop back.
