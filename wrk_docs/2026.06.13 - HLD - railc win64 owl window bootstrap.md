## Scope

**In (wall 1 — the window-procedure/bootstrap path).** Make the source-built Win64 RailC OWL exe
(`wrk_probe/railc_source_slice_win64_link/build/railc_source_slice_win64.exe`, PE32+, 12,468,736 B)
stop dying at **`0xC0000374`** (STATUS_HEAP_CORRUPTION, ntdll offset 0x117555) *before any window*.
Root cause is OWL's 32-bit per-window mechanism: a heap-allocated x86 instruction-byte thunk
(`new TInstanceThunk`, `OWL.CPP:88-123`), a truncating `SetWindowLong(hWindow, GWL_WNDPROC, uint32(thunk))`
(`OWL.CPP:68`; member forms `WINDOW.CPP:248,294`), and `_EAX`-register `this` recovery (`WINDOW.CPP:900`).
Replace with the proven in-tree model (`src/pp.rs:548-562` `OwlStaticWndProc`): one **static dispatcher**
WNDPROC installed full-width via `SetWindowLongPtrA`, the `TWindow*` stored/recovered full-width via
`*Ptr*(GWLP_USERDATA)`, no executable heap thunk. **Audit-confirmed completeness (D11):** across the entire
65-member OWL slice, `_EAX` (the pseudo-register `this`-recovery) appears in **only `WINDOW.CPP`**, and
`GWL_WNDPROC` proc-installs appear in **only `OWL.CPP` + `WINDOW.CPP`** — so the whole window-procedure/thunk
machinery is centralized in the two files we patch. MDI children (`MDICHILD.o`/`MDICLIEN.o`/`MDIFRAME.o`)
install no separate proc; they bootstrap through the patched `TWindow::Create`. So the two-file patch is
**complete for the first-window bootstrap**.

**Out (deferred frontiers).**
- **Wall 2 — OWL response-dispatch int32 layer:** `SIGNATUR.H:458` `LRESULT_WPARAM_LPARAM_Sig == I32_U_I32_Sig`,
  `DISPATCH.CPP`, `COMPAT.H` Win16 param widths — and the slice-wide message-width view (`WPARAM`/`LPARAM`/`LRESULT`
  stay at the oracle's 32-bit width). This design **deliberately does not widen those typedefs** (D2). The likely
  next failure — a pointer carried in `lParam` (e.g. `WM_NCCREATE`/`WM_CREATE` `CREATESTRUCTA*`, `WM_GETMINMAXINFO`
  `MINMAXINFO*`) truncated to 32 bits → an access violation `0xC0000005` — is a *new frontier* to be **detected,
  not pre-fixed**. The runtime oracle tells "wall-1 cleared" apart from "new frontier".
- **Dialogs — a SEPARATE frontier (Codex #1, D11).** `DIALOG.CPP` (in the slice) and the common dialogs
  (`CHOOSECO/CHOOSEFO/FINDREPL/OPENSAVE/PRINTDIA`) use a *different* dialog-proc + `DWL_USER` mechanism (not the
  thunk/`_EAX`/`GWL_WNDPROC` path), with its own 32-bit `DWL_USER` truncation. RailC's main frame window is an OWL
  `TFrameWindow` (the `TWindow::Create` path — covered); **dialogs only appear when the user opens one (ABOUT/CONFIG/
  FINISH), i.e. after the main window**, so the `DWL_USER` path is explicitly a later frontier, NOT part of wall 1.
  Patching it (the `DWLP_USER`/`SetWindowLongPtrA` analog in `DIALOG.CPP`) is a follow-up tracked alongside wall 2.

**Non-goals.** No linker/import-table change (`SetWindowLongPtrA`/`GetWindowLongPtrA` are already core
USER32 imports, `src/link/pe_writer.rs:225-226`). No `src/pp.rs` predefined-macro change (no `_WIN64`).
No slice-member additions (counts pinned 65/48/11/207; manifest stays 332 lines). No edits under
`wrk_oracle/`. No new env vars or feature flags.

## Design

### CRUX — how the patched CPPs get Win64 pointer-width primitives: **additive shared header** (mechanism B)

The recursion hazard (a same-name overlay header cannot re-include the original — no `#include_next`,
no `#pragma once`, first-match-wins → include-depth>64, `pp.rs:1232-1234`) only bites if an overlay must
*replace or chain into* an oracle header. **It never needs to:** the wall-1 fix requires only symbols the
oracle headers are *missing*, never a different definition of one they already provide. Verified:
the oracle INCLUDE tree defines **none** of `LONG_PTR`, `UINT_PTR`, `GWLP_WNDPROC`, `GWLP_USERDATA`,
`SetWindowLongPtrA`, `GetWindowLongPtrA` (they post-date BC45 ~1999).

So the mechanism is a single **purely additive** header `wrk_owl_win64/mdwin64thunk.h`, quote-included by
the two patched CPPs *after* the oracle includes (so `HWND`/`int` already exist). It resolves as a sibling
quoted include via the TU's `base_dir` = the source file's own directory (`src/main.rs:151`; quote-include
arm `src/pp.rs:714`) — **no `-I` change, no `Roots` include-dir change, no resolver change.** It shadows
nothing and re-includes nothing.

```c
/* wrk_owl_win64/mdwin64thunk.h
   ADDITIVE ONLY. Never shadows/re-includes an oracle header, so the first-match-wins
   recursion hazard cannot arise. Include AFTER the oracle <owl/*.h> includes.
   WPARAM/LPARAM/LRESULT are intentionally LEFT at the oracle's 32-bit width (D2): widening
   them would change the mangled names of the non-virtual, cross-TU-inlined
   TWindow::ReceiveMessage/HandleMessage and break the link. The int32 message layer is wall 2. */
#ifndef MDBCC_WIN64_THUNK_H
#define MDBCC_WIN64_THUNK_H
typedef __int64          LONG_PTR;
typedef unsigned __int64 UINT_PTR;
#define GWLP_WNDPROC  (-4)         /* absent from BC45 WINUSER.H; Win32/Win64 value */
#define GWLP_USERDATA (-21)        /* absent from BC45 WINUSER.H; Win32/Win64 value */
/* LONG_PTR return type is load-bearing: it stops the recovered TWindow* being narrowed to int.
   We NAME only the *Ptr* variants -> no 32-bit SetWindowLongA prototype is pulled over these
   call sites. x64 has one calling convention, so no __stdcall/CALLBACK decoration is needed. */
extern "C" LONG_PTR SetWindowLongPtrA(HWND hWnd, int nIndex, LONG_PTR dwNewLong);
extern "C" LONG_PTR GetWindowLongPtrA(HWND hWnd, int nIndex);
#endif
```

**Why B over A/C/D:**
- **A (inline self-contained prologue in each CPP)** — equally recursion-free and safe, but duplicates the
  ~6 declarations across both CPPs, inviting drift. B factors them into one reviewable source of truth.
  (B is "A with the shared bit factored out.")
- **C (prepended full-replacement overlay dir)** — **rejected.** The resolver fallback never returns `None`
  (stubs every miss to empty, `pp.rs:639/720`), so a mistyped/missing replacement of `WTYPES.H`/`WINUSER.H`
  **silently miscompiles** to 32-bit → straight back to `0xC0000374`. It would also force reproducing
  hundreds of unrelated typedefs. Pointless when the need is purely additive.
- **D (`#include_next` + per-dir tracking)** — **rejected.** Most invasive (preprocessor surgery); additive
  symbols never need to chain to an original.

**Guard rails (in each patched CPP, after the includes, before the first patched function):**
```c
#ifndef MDBCC_WIN64_THUNK_H
#error "mdwin64thunk.h overlay missing — Win64 ABI prologue not applied"
#endif
typedef char _mdbcc_ptrwidth_check[(sizeof(void*)==8 && sizeof(LONG_PTR)==8) ? 1 : -1];
```
The `#error` catches a missing/stubbed header; the negative-size-array typedef catches any residual
width skew. Both live in the CPP — which is passed to `bcc` directly and **cannot itself be stubbed** —
so a layering failure is a **loud compile error**, never a silent 32-bit miscompile.

### Why `WPARAM`/`LPARAM`/`LRESULT` are NOT widened (the dissolved sub-problem) — D2

The wall-1 pointer truncation is **not** in the message args — it is in the *WNDPROC install* and *`this`
recovery*, which flow through `LONG_PTR`/`GWLP_*`, a path independent of `WPARAM`/`LPARAM`. Widening the
message typedefs is unnecessary for wall 1 **and actively harmful**: `TWindow::ReceiveMessage`
(`WINDOW.H:317`) and `HandleMessage` (`WINDOW.H:325`) are **non-virtual** members, defined once in
WINDOW.CPP but called inline from ~20 other OWL TUs. Widening `WPARAM`/`LPARAM` in only the two patched TUs
would make WINDOW.CPP *define* `…HandleMessage(uint,u64,i64)` while BUTTON/EDIT/… *reference*
`…HandleMessage(uint,u32,i32)` → unresolved externals → the currently-green link breaks. Coherent widening
would have to be **slice-wide** = exactly the deferred wall 2. Therefore: keep 32-bit message widths
everywhere; confine the change to `LONG_PTR`/`GWLP_*`/`*Ptr*`. (`this` flows via the `CreationWindow`
global → `GWLP_USERDATA`, **never via `lParam`**, so wall 1 does not depend on `lParam` width.)

### `_WIN64`/`__WIN64__` predefine: **NO** (`src/pp.rs:1496-1499` unchanged) — D3

BC45 headers have no `_WIN64`/`_M_X64` branch; predefining it flips nothing useful while risking activation
of un-audited header blocks for **every** `-m64` TU, and would force threading `TargetKind` through `Pp`.
Pointer-width correctness comes from the wrapper's explicit `LONG_PTR=__int64`, which agrees with codegen's
8-byte `-m64` pointer layout (`compile.rs:293-296`). **Net `src/pp.rs` change: none.**

### Patched OWL.CPP behaviour (full reviewable copy of the 223-line oracle; surgical edits in `#if defined(BI_PLAT_WIN32)`)

- **`InitWndProc` (replaces `:68`).** After `CreationWindow->HWindow = hWindow` and `DefaultProc` setup,
  capture `TWindow* w = CreationWindow;` *before* `CreationWindow = 0;`, then install full-width:
  ```c
  SetWindowLongPtrA(hWindow, GWLP_USERDATA, (LONG_PTR)w);        /* recovered by StdWndProc */
  SetWindowLongPtrA(hWindow, GWLP_WNDPROC,  (LONG_PTR)thunk);    /* thunk == StdWndProc */
  return (*(WNDPROC)thunk)(hWindow, message, wParam, lParam);
  ```
- **`CreateInstanceThunk` (replaces `:88-123`).** `return (WNDPROC)StdWndProc;` — the single static
  dispatcher. No `new`, no executable bytes; `struct TInstanceThunk`/`CODEDISP` deleted (kills the
  heap-thunk and its packing risk outright).
- **`FreeInstanceThunk` (replaces `:125-129`).** No-op `{ (void)proc; }`.
- **`StdWndProcInstance` (`:16`) and `DefaultProc = GetProcAddress(USER32,"DefWindowProcA")` (`:54-55`):** kept.

### Patched WINDOW.CPP behaviour (full reviewable copy of the 2537-line oracle; surgical edits)

- **`StdWndProc` (replaces `:896-902`) — the bootstrap-critical edit.** Name the `HWND hWnd` param; recover
  via the stored pointer instead of `_EAX`:
  ```c
  TWindow* w = (TWindow*)GetWindowLongPtrA(hWnd, GWLP_USERDATA);
  if (!w) return ::DefWindowProc(hWnd, msg, wParam, lParam);     /* null-self safety, cf. pp.rs:561 */
  return w->ReceiveMessage(msg, wParam, lParam);
  ```
- **`SubclassWindowFunction` (`:248`) — MUST store `this` in `GWLP_USERDATA`, with the install atomic (D10, Codex #8).**
  For predefined-class controls (standard BUTTON/EDIT/etc.) `InitWndProc` never runs, so this is the *only* site
  that sets the recovery slot. Store `this` first, then capture the prior proc from `SetWindowLongPtrA`'s return
  (atomic set-and-return-old, mirroring the oracle's `DefaultProc = SetWindowLong(...)` — not a separate Get):
  ```c
  ::SetWindowLongPtrA(HWindow, GWLP_USERDATA, (LONG_PTR)this);                          /* so StdWndProc recovers this */
  DefaultProc = (WNDPROC)(LONG_PTR)::SetWindowLongPtrA(HWindow, GWLP_WNDPROC, (LONG_PTR)GetThunk());
  CHECK(DefaultProc != GetThunk());
  ```
- **`GetWindowPtr` (`:991`) — proc-validated recovery (D12, Codex #2/#3/#4).** Only trust `GWLP_USERDATA` when
  the window's proc is *our* dispatcher — this restores the original's "is this one of *our* OWL windows?" gate
  (the oracle answered this via the `GetWindowPtrMsgId` protocol that only OWL procs honor):
  ```c
  if ((WNDPROC)(LONG_PTR)::GetWindowLongPtrA(hWnd, GWLP_WNDPROC) != StdWndProc) return 0;
  return (TWindow*)(LONG_PTR)::GetWindowLongPtrA(hWnd, GWLP_USERDATA);
  ```
  This (a) avoids a false-positive when a foreign/standard window happens to have nonzero `GWLP_USERDATA` (Codex #2);
  (b) returns null after teardown, since the proc has been restored to `DefaultProc != StdWndProc` — no dangling
  `TWindow*` (Codex #3); (c) is the correct discriminator at `Create():1557` (OWL-class → proc==StdWndProc + userdata
  set → non-null → skip subclass block; predefined-class → proc≠StdWndProc → null → run SubclassWindowFunction).
  *(`StdWndProc` is the dispatcher's address; comparing the slot against it is exact.)* The original cross-app-instance
  filter (`lParam == LPARAM(Application)`) is dropped — acceptable for RailC (a single OWL app instance); noted as a
  documented simplification (Codex #4).
- **`~TWindow` alias teardown (`:292-294`)** restores `GWLP_WNDPROC` to `DefaultProc` via `::SetWindowLongPtrA`, **and
  clears `GWLP_USERDATA` if it still equals `this`** (`::SetWindowLongPtrA(HWindow, GWLP_USERDATA, 0)`), so no freed
  pointer lingers (Codex #3). `~TWindow`'s `::FreeInstanceThunk(Thunk)` (`:333`) is now a no-op.
- The member forwarders `TWindow::Get/SetWindowLong` (`WINDOW.H:439-440/1047-1055`, return 32-bit `long`) and
  all genuinely-32-bit uses (`GWL_STYLE`, etc.) are **left alone** — patching `WINDOW.H` would break ABI
  coherence and those values don't need 64 bits. `StdWndProc` is referenced only in OWL.CPP/WINDOW.CPP, so
  its unchanged-width signature creates no cross-TU break.

### O3 — Runtime smoke (the focus; new): `owl_window_smoke.ps1`, bounded & headless
`run_window_smoke(exe)` invokes the PS1 via `std::process::Command` (native spawn under `cargo test`).
PS1 contract:
- **WER suppression (headless):** save `HKCU\Software\Microsoft\Windows\Windows Error Reporting\DontShowUI`,
  set `=1` (DWORD; per-user, no admin), restore in `finally`. Leave WER otherwise enabled so the
  Application-Error event is still logged (the `c0000374` cross-check). Bounded `WaitForExit` + `Kill`
  backstop + stray-`WerFault.exe` kill.
- **Launch & classify** (proven pattern from `wrk_probe/gui_parity/capture_main_window_parity.ps1:165-275`):
  `Start-Process -PassThru`; poll `EnumWindows` every 100 ms for ≤ 10 s for a **visible** top-level window
  whose `GetWindowThreadProcessId == $proc.Id` (keyed on **PID + visible**, NOT a class name — robust even if
  the Win64 build registers a class other than `Main_Window_Class`; a class match is logged as a bonus). Then
  bounded `WaitForExit(15 s)`; if still alive, `Kill()`.
- **Exit-code contract** (`0xC0000374` = signed `-1073740940` / unsigned `3221226356`):

  | PS1 exit | Condition | Meaning |
  |---|---|---|
  | **0** | A visible top-level window owned by the child PID appeared within 10 s | **PASS — wall 1 cleared** (the crash currently precedes *any* window) |
  | **2** | No window AND the **normalized** child exit code is `0xC0000374` (see below) | **FAIL — old failure reproduced** (the only failing outcome) |
  | **3** | No window AND child exited with any *other* non-zero code (e.g. `0xC0000005`), OR still running at timeout (then killed) | **NEW FRONTIER** — different/better-localized failure; wall 1 plausibly cleared |
  | **4** | exe missing / launch failed / harness error | Harness error |

- **Exit-code normalization (Codex #6 — load-bearing).** `$proc.ExitCode` is a **signed** Int32, and the PS literal
  `0xC0000374` is a positive number, so `$proc.ExitCode -eq 0xC0000374` silently never matches. Compare the unsigned
  form explicitly: `([uint32]($proc.ExitCode -band 0xFFFFFFFF)) -eq 0xC0000374` (equivalently `$proc.ExitCode -eq -1073740940`).
  Use the **same normalized comparison** to classify exit-3 (any other non-zero, e.g. `0xC0000005`).
- **Exit code is the PRIMARY oracle; the event log is diagnostic only (Codex #7).** The `Application Error` (event id 1000)
  scrape is unreliable as a gate (late arrival, localization, concurrent same-exe runs, missing fields). It is recorded —
  keyed by child **PID + exe path + launch timestamp** — only as corroborating triage, NEVER as the sole basis for FAIL.
  A correct normalized exit-code comparison is what makes regression detection deterministic.
- **Rust assertion (the DoD):** `assert_ne!(code, 4)`; `assert_ne!(code, 2, "REGRESSION: 0xC0000374 before any window")`.
  `code == 0` → window appeared (headline success); `code == 3` → wall-1 heap-corruption signature cleared but **NOT a
  proven window** — see R4: this is the stakeholder bar. A bare `exit==0` gate is explicitly **too strict** for "no
  regression," but exit-3 must NOT be read as "done." The smoke writes a one-line TSV
  (`outcome  child_exit  window_seen  class  note`) under `wrk_probe/owl_win64_smoke/` for triage.

## Residual risks
1. **The next wall is probably a truncated-pointer AV, not a visible window.** With `lParam` left 32-bit,
   `WM_NCCREATE`/`WM_CREATE` (`CREATESTRUCTA*`), `WM_GETMINMAXINFO`, etc. carry a pointer that `StdWndProc`
   forwards truncated → likely `0xC0000005`. That is a *new frontier* (smoke exit 3) with a different
   signature from wall 1's heap corruption. **Honest expectation: `0xC0000374` is removed; the most probable
   observed outcome is exit-3, not exit-0.** Clearing exit-3 needs slice-wide pointer-width message types = wall 2.
   *(This makes the acceptance philosophy explicit — see Review item R4: is "moved past `0xC0000374`" the agreed
   bar, or does sign-off expect an actual window?)*
2. **Heap corruption could recur from a different site** (e.g. int32 dispatch). Then the smoke reports exit-2
   and fails — correctly flagging "not actually past the heap wall."
3. **Sandbox spawn** (`notes/spike-oracles.md:65`): the smoke spawns a self-built exe. Under `cargo test` it uses
   native `std::process::Command`, not the agent `uv_spawn`, so EPERM should not apply; if a runner sandboxes it,
   the test reports exit-4 (harness error) rather than hanging.
4. **External-tool availability** (R2): if neither `llvm-readobj`/`llvm-nm` nor an in-repo PE/COFF reader is wired,
   O1/O2 can't run. Mitigation: prefer in-repo parsing (the linker already understands PE/COFF).
5. **Maintaining a 2537-line verbatim WINDOW.CPP copy** — drift risk, but the oracle is frozen evidence; the copy
   pins changed line ranges and the guard rails + O2 catch any miscopy affecting ABI.
6. **`extern "C"` `*Ptr*` decl / name mangling** — if mdbcc decorated the call differently from the undecorated
   import it wouldn't resolve; caught loud by link "unresolved external" and by O1 (symbol absent). Mirrors the
   proven in-tree `WIN32_IMPORTS` style.
7. **Dialogs are a separate, deferred frontier (Codex #1).** `DIALOG.CPP`'s dialog-proc/`DWL_USER` path is NOT patched
   by wall 1; opening ABOUT/CONFIG/FINISH could truncate `DWL_USER` and crash *after* the main window. This is expected
   and out of scope; the smoke (which exercises startup, not dialog interaction) won't hit it, and it's tracked as a
   follow-up alongside wall 2.
8. **`GWLP_USERDATA` ownership on subclassed controls (Codex #2).** For predefined-class controls, OWL now consumes the
   control's `GWLP_USERDATA`; a standard control that used that slot itself would clash. RailC's own windows are OWL
   classes (no clash); the proc-validated `GetWindowPtr` (D12) prevents *mis-reading* a foreign slot. If a future
   subclassed control needs its own userdata, switch that path to `SetPropA`/`GetPropA` (noted, not needed for RailC).

## Decision log
- **D1 — CRUX = additive shared header (B).** Wall-1 need is purely additive (`LONG_PTR`/`UINT_PTR`/`GWLP_*`/`*Ptr*`,
  none defined by the oracle), so no header is shadowed/re-included and the recursion hazard never arises.
  Rejected C (silent empty-stub miscompile, `pp.rs:639/720`) and D (invasive resolver rewrite); A is B without DRY.
  Resolved via sibling quoted include (`base_dir`), so no `-I`/`Roots`/resolver change. Safety from the in-CPP
  `#error` sentinel + `sizeof==8` static assert that cannot be stubbed.
- **D2 — Do NOT widen `WPARAM`/`LPARAM`/`LRESULT`.** They are not the truncation site; widening only the two
  patched TUs changes the mangled names of the non-virtual, cross-TU-inlined `TWindow::ReceiveMessage`/`HandleMessage`
  → link break; coherent widening would be slice-wide = wall 2. **Explicitly rejects the risk-first draft's guard-pre-claim
  widening as link-breaking and as violating the brief's "one coherent message-width view" constraint.**
- **D3 — No `_WIN64`/`__WIN64__` predefine** (`pp.rs:1496-1499` untouched). Inert in BC45 headers; pointer width
  already 8 bytes in codegen; a target-blind predefine has slice-wide blast radius for no wall-1 gain.
- **D4 — No executable thunk:** `CreateInstanceThunk` returns the static dispatcher; `FreeInstanceThunk` is a no-op;
  `TInstanceThunk` deleted — removes the heap-thunk crash and struct-packing concern outright.
- **D5 — Redirect via `Roots.owl_overlay: Option` set only in the win64 test**, consumed in `member_source`.
  `member_source` stays the single source-mapping point; `None` default keeps the always-on manifest test and the
  `-m32` path on the oracle. Name-preserving (counts/trace/manifest untouched).
- **D6 — "Patched used?" proved twice:** O1 (only the patched code names `*Ptr*` → import ⟺ linked) and O2 (marker
  symbols in the `.o`s). The name-only trace key needs no change.
- **D7 — Runtime DoD = three-way classification; fail only on exit-2** (`0xC0000374` before any window, confirmed by
  `ExitCode` or the Application-Error event). Exit-0 (window) is the headline success; exit-3 (different code / survives)
  is the sanctioned hand-off to wall 2. Makes "moved past the crash vs new frontier" unambiguous and unattended-safe.
- **D8 — Judging & synthesis done by the team lead in-thread** (the agent judge panel + synthesizer hit a session rate
  limit). Phase 3 (this adversarial review round) and Phase 4 (Codex) supply the independent scrutiny.
- **D9 — `GetWindowPtr` recovers `this` from `GWLP_USERDATA`, not the old `GWLP_WNDPROC`/`CallWindowProc` dance**
  (review round 1 fix; superseded in detail by D12's proc-validation). The stored `this` lives in `GWLP_USERDATA`.
- **D10 — `SubclassWindowFunction` must store `this` in `GWLP_USERDATA`** (review round 1; refined by Codex #8 in D14).
  For predefined-class controls `InitWndProc` never runs, so this is the only site that sets the recovery slot; without
  it `StdWndProc` recovers null and the subclass is lost. The original OWL didn't need this (its per-window thunk carried
  `this`); the static-dispatcher model does.
- **D11 — Dialog/MDI audit (Codex #1, RESOLVED).** Grep of the 65-member OWL slice: `_EAX` only in `WINDOW.CPP`;
  `GWL_WNDPROC` proc-installs only in `OWL.CPP`+`WINDOW.CPP`; MDI children install no separate proc → covered by the
  patched `TWindow::Create`. So the two-file patch is complete for the window-procedure bootstrap. `DIALOG.CPP` + the
  common dialogs use a separate dialog-proc/`DWL_USER` mechanism → a **distinct deferred frontier** (dialogs open after
  the main window); documented in Scope, NOT pulled into wall 1.
- **D12 — `GetWindowPtr` is proc-validated (Codex #2/#3/#4, RESOLVED).** Trust `GWLP_USERDATA` only when
  `GWLP_WNDPROC == StdWndProc`. This restores the oracle's "is this *our* OWL window?" gate, prevents false positives on
  foreign nonzero userdata (#2), returns null after teardown so there is no dangling `TWindow*` (#3), and is the correct
  `Create():1557` discriminator. The cross-app-instance filter is dropped — acceptable for single-app RailC (#4). Teardown
  also clears `GWLP_USERDATA` when it still equals `this`.
- **D13 — Runtime oracle hardening (Codex #6/#7, RESOLVED).** `$proc.ExitCode` is signed, so `0xC0000374` is matched via
  the normalized `[uint32]($code -band 0xFFFFFFFF) -eq 0xC0000374` (≡ `-1073740940`); the normalized exit code is the
  PRIMARY gate; the `Application Error` event log is PID+path+timestamp-keyed **diagnostic only**, never the sole FAIL basis.
- **D14 — Subclass install is atomic + residual-truncation scan (Codex #8/#10, RESOLVED).** `SubclassWindowFunction`
  stores userdata first, then captures the prior proc from `SetWindowLongPtrA`'s return (atomic). O2 adds a source scan
  asserting the two patched CPPs contain zero `_EAX`/`uint32(thunk)`/`SetWindowLong(...GWL_WNDPROC)` truncating sites.
- **D15 — `StdWndProcInstance` (Codex #9, minor, OPTIONAL).** Since `CreateInstanceThunk` returns `StdWndProc` directly,
  the `TProcInstance StdWndProcInstance` wrapper is no longer load-bearing; team-build may drop it from the patched copy
  if unreferenced. Left in by default (harmless); not worth a deliberate edit unless the compiler flags it unused.

## Review round 1 (Phase 3) — items resolved against the code
- **R1 ✅ CONFIRMED (load-bearing for D2).** `TWindow::ReceiveMessage` (`WINDOW.H:317`) and `HandleMessage` (`:325`)
  are declared **without `virtual`** (contrast `WindowProc`/`DefWindowProc` at `:333-334`, which *are* virtual), and
  are referenced across **19 OWL slice TUs / 87 occurrences** (BUTTON, COMBOBOX, EDIT, FRAMEWIN, MDICHILD, LISTBOX, …).
  So widening their `WPARAM`/`LPARAM` in only the 2 patched TUs would change their mangled names → unresolved externals.
  D2 ("do NOT widen") is correct; the risk-first draft's widening would have broken the link.
- **R2 ✅ RESOLVED.** `llvm-readobj`/`llvm-nm`/`dumpbin` all absent → O1/O2 use in-repo parsing (`src/coff.rs` + a PE
  import-directory walk). See O1/O2.
- **R3 ✅ CONFIRMED.** `WINUSER.H:1116` `#define GWL_WNDPROC (-4)`, `:1121` `#define GWL_USERDATA (-21)`; no `GWLP_*`
  in the oracle. Hardcoding `GWLP_WNDPROC=-4`/`GWLP_USERDATA=-21` matches; the patched code installs via `GWLP_WNDPROC`
  and never needs `GWL_WNDPROC`.
- **R4 ⚠️ FOR SIGN-OFF (acceptance philosophy).** "Moved past `0xC0000374`" (exit-3 acceptable, no window required) is
  the proposed definition of done, inherited from the original draft HLD's acceptance bar. **Honest expectation: the
  most probable observed outcome is exit-3 (a truncated-pointer AV = wall 2), not a visible window.** This is the one
  item that is a *stakeholder decision*, surfaced explicitly at sign-off — see Residual risk 1.
- **R5 ✅ MOSTLY RESOLVED.** `extern "C"` is supported (`tests/cpp_extern_c.rs`). The `*Ptr*` prototypes are
  load-bearing: they force a `LONG_PTR` (8-byte) return so the recovered `this` is not narrowed through an implicit-int
  return. The `typedef char[neg]` static-assert is **best-effort** (not verified that mdbcc diagnoses negative array
  sizes); the `#error` sentinel is the guaranteed guard (preprocessor-level). team-build: if the negative-array idiom
  doesn't fault, drop it — the `#error` + the link/import gates already catch a missing overlay.
- **R6 ✅ CONFIRMED.** `TWindow::Create` brackets the create: `::SetCreationWindow(this)` (`WINDOW.CPP:1528`) →
  `PerformCreate` → `::CreateWindowEx` (`:1492`, synchronous, so the first messages reach `InitWndProc` while
  `CreationWindow` is valid) → `::SetCreationWindow(0)` (`:1562`, in the predefined-class branch). The identical
  `CreationWindow` mechanism already works in the shipping 32-bit build. Two paths handled: OWL-class windows
  (InitWndProc stores `this`) and predefined-class windows (SubclassWindowFunction stores `this` — D10).

## The one decision for sign-off (R4 / Codex #5) — the acceptance bar
This fix removes the `0xC0000374` heap-corruption crash. The **honest expectation** is that the next observed outcome is a
**truncated-pointer access violation (`0xC0000005`) = wall 2**, not necessarily a visible window. Two possible definitions of done:
- **(A) "No regression" bar (what this HLD encodes):** PASS if the smoke no longer sees `0xC0000374`-before-any-window —
  exit-0 (window) OR exit-3 (new, better-localized frontier). Wall-1 done = crash signature cleared; wall 2 stays open.
- **(B) "Visible window" bar:** PASS only on exit-0 (a real top-level window). This very likely pulls **wall 2** (slice-wide
  pointer-width message types / the int32 dispatch layer) into scope — a materially larger build.

**Recommendation:** bar (A) — it's the right-sized increment, keeps the change to two files, and makes the next frontier
explicit and measurable. If you want a window on screen this pass, choose (B) and I'll re-scope to include wall 2.
