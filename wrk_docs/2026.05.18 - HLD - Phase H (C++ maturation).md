## Purpose

Phase H closes the *language-layer* gap between Phases A-G and
Phase I (a genuine legacy OWL app). The seven PoR sub-items are
exactly the C++ features real Borland-era OWL source uses
pervasively that mdbcc rejects or miscompiles today: struct-by-
value (every `TRect`/`TPoint`), exceptions (`TXOwl` hierarchy
throughout error paths), member-fn overloading (every container's
`T& operator[](int)` plus const overload), `new T[n]`,
`operator[]/()/=`, block-scope shadowing, global-init adjacent-
string-concat. Each absence is a localised seam to open.

## Scope-in / scope-out

**In (v1, the seven PoR items, expanded into 10 atomic
increments):** struct/class by-value parameters (H1) + returns
(H2); exception syntax (H3) + SEH runtime int-only (H4a) + class
hierarchy (H4b); member-fn overloading (H5); array-new
`new T[n]`/`delete[]` with cookie (H6); member operator
overloading `[]`/`()`/`=` (H7); block-scope shadowing (H8);
global-init adjacent-string-concat (H9); independent review +
closure (H10).

**Out (H-future):**
- **H-future-1:** Templates / template metaprogramming —
  pre-template-metaprogramming OWL doesn't use them.
- **H-future-2:** Namespaces — Borland C++ 4.x / OWL 2.x predate
  general adoption.
- **H-future-3:** RTTI (`dynamic_cast`, `typeid`). Lexer already
  tokenises them (`src/lexer.rs:680-688`); parser/codegen-reject
  is a one-liner on Phase-I demand.
- **H-future-4:** Multiple / virtual inheritance — Phase B's
  model is single-inheritance + vtable; OWL is single-inheritance.
- **H-future-5:** `constexpr`, `auto`, lambdas, range-for — modern
  C++; target era is `bcc32 5.5.1` / Borland C++ 4.x-5.x.
- **H-future-6:** Placement `new`. PoR pairs it with `new T[n]`
  but it has no allocation seam — defer.
- **H-future-7:** Exception specifications (`throw()`/`noexcept`).

## Increments H1..H10 (smallest-first, independently green-committable)

Per charter: each increment ends green / clippy-clean / committable;
O1 `tests/end_to_end.rs` (88) byte-identical throughout (none of
the 88 O1 programs uses any Phase-H feature; every increment is
gated on `is_record()` or a typed AST flag).

### H1 — struct/class by-value parameter passing (Win64 ABI)

**Current state**: `Gen::new` at `src/codegen.rs:633` **explicitly
rejects** record params (*"function 'X': struct/union by value is
not yet supported (use a pointer)"*); a second reject in
`marshal_args` at `src/codegen.rs:2555`. Two well-named seams.

**Win64 ABI for aggregates** (Microsoft, **not** SysV — SysV's
"two-eightbyte" rule does **not** apply): size ∈ {1,2,4,8} ⇒
passed in the integer arg register, packed; all other sizes
(incl. 3/5/6/7 and >8) ⇒ **passed by hidden pointer** to a
caller-allocated copy.

Touch: `src/codegen.rs` only (lift both rejections; extend
`marshal_args` and `Gen::new` param-slot layout to copy from
`rcx`/`rdx`/`r8`/`r9` / `[rsp+…]` into a hidden-pointer-
addressed local for the big-aggregate case). No AST change
(`Type::Record` already carries `size`/`align`). No parser change.

- **RED** `tests/cpp_struct.rs` (new): aggregates of size {1,4,
  8,9,12,16,24}; exit code from a function consuming fields.
- **GREEN**: ~80-120 LoC; both rejects become decision branches.
- **Differential**: `cl /O2` viable; `bcc32` ABI diverges (defer).
- **Regression**: O1 byte-identical (gated on `is_record()`).

### H2 — struct/class by-value return

**Win64 ABI for return**: size ∈ {1,2,4,8} ⇒ in `rax`; all other
sizes ⇒ caller allocates return slot, passes its address as a
**hidden first argument**, callee writes through it and returns
the same pointer in `rax`. (No "rax+rdx" pair: that's SysV.)

Touch: `src/codegen.rs` — the `f.ret.is_record()` reject becomes
a branch; `gen_return` writes through `[rcx]`; call sites
allocate a caller-side temporary and inject the hidden pointer
before any `this` (see Open Question 1).

- **RED**: `tests/cpp_struct.rs` (extended) — returning 4B/16B/
  24B aggregates; caller reads fields.
- **GREEN**: ~60-100 LoC. **Differential**: `cl /O2` viable.
- **Regression**: O1 byte-identical.

- **GREEN**: ~80 LoC. **Regression**: O1 byte-identical.
- **Unblocks** Phase-I fixtures referencing the keywords.

### H4a — exception runtime, integer-only (SEH plumbing)

Largest single increment (per PoR's own warning). Win64 SEH is
what cl emits; Phase-I apps run on modern Windows where SEH IS
the unwinder ⇒ OS provides unwinder for free, mdbcc emits only
the unwind tables. (Open Question 2 covers SEH-vs-Borland.)

**Scope**: `throw <int-expr>;` and `try {…} catch (int e) {…}`
only. No class hierarchies, no `catch (…)`, no rethrow.

**Win64 SEH artifacts** mdbcc emits: `.pdata`
(`RUNTIME_FUNCTION{BeginAddress, EndAddress, UnwindData}` per
function with a `try`); `.xdata` (`UNWIND_INFO` + scope-table
records per `try`: PC-range → handler + filter); throw lowering
calls helper `__mdbcc_throw_int(int)` → `RaiseException(
0xE0000001, EXCEPTION_NONCONTINUABLE, 1, &value)`; catch filter
returns `EXCEPTION_EXECUTE_HANDLER` on code match; handler
extracts the int from the exception record.

Touch: `src/pe.rs` (new `build_pdata`/`build_xdata` mirroring
`build_idata`; section table 4 → 6 *iff* `try`/`throw` present;
data-directory[3] = EXCEPTION; `WIN32_IMPORTS` += `RaiseException`);
`src/codegen.rs` (per-function unwind info; throw helper; filter+
handler stubs); new `src/eh.rs` (~150-250 LoC, pure layout for
`RUNTIME_FUNCTION`/`UNWIND_INFO`/scope-table records, mirroring
Phase G's `src/rc/res.rs` separation).

- **RED**: 6 programs — simple `throw 42; catch (int)`; nested
  `try`; no-matching-handler propagates (non-zero OS-killed exit);
  throw in loop; throw across two frames.
- **Differential**: `cl /O2` unwind codes diverge bit-for-bit;
  **behavioural only** (OS unwinder is the oracle).
- **Regression**: O1 byte-identical.

### H4b — exception class hierarchy (`TXOwl`-style)

Extends H4a to `throw <class-expr>;` + `catch (Tag &e) {…}` with
**catch-by-base**: `catch (Base &)` matches any `throw Derived(…)`
within Phase B's single-inheritance chain.

**Mechanism**: type-info pointer **is the class's vtable address**
(Phase B vtables already live in `.rdata`). Throw captures
`(vtable_addr, sizeof(T), &temp_copy)`. Catch's filter walks the
thrown type's base chain (parser already knows
`Record::base: Option<usize>`) comparing vtable addresses.

Touch: `src/codegen.rs` (`gen_throw` for class operand: copy-
construct into a runtime-managed temporary; raise exception code
`0xE0000002` with 3 args); `src/eh.rs` (class-aware scope-table
entry); tiny runtime helper `__mdbcc_throw_class(void*, size_t,
void*)`.

- **RED**: single-class and 2-deep-derived throws; catch by
  exact type; catch by base; first-match-wins.
- **GREEN**: ~150-250 LoC. **Regression**: O1 byte-identical.

### H5 — member-function overloading

**Surprising finding**: free-function overloading **already works**
(`src/codegen.rs:288-298,310-340` — `overload_symbol` mangles
e.g. `f$ic` for `f(int,char)`). Comment at `src/codegen.rs:311`
says verbatim *"Member overloading is deferred; only free-
function names participate."*

H5 lifts that. The hard parts exist: mangler, parser member
naming (`Tag::name`), `method_target` (`src/codegen.rs:1188`)
inheritance walk. What H5 adds: pass-1 overload detection keyed
by (Tag, base-name); `method_target` best-match via generalised
`resolve_overload` (`src/codegen.rs:2412`); mangled member
symbols `Tag::name$<typecodes>`.

**Mangling scheme — keep mdbcc's current Borland-ish single-char
codes** (NOT MSVC `?` mangling, NOT Itanium `_Z`). Rationale: the
existing scheme is already in production; class methods never
cross the DLL boundary (only `WIN32_IMPORTS` link), so the
format is **private to emitted `.text`**. The cl differential is
behavioural; internal symbol format is not observable.

Touch: `src/codegen.rs` only.

- **RED** `tests/cpp_overload.rs`: `class C { void f(int); void
  f(double); void f(int,int); };` per-overload dispatch by arg
  types; ambiguous-overload error.
- **GREEN**: ~80 LoC. **Regression**: O1 byte-identical.

### H6 — array-new `new T[n]` + `delete[] p`

**Current state**: `new T` and `new T(args)` work (`src/parser.rs:
1808-1823`, `Expr::New`); `delete p` codegens; `delete[] p`
**parses but the brackets are silently ignored**
(`src/parser.rs:1828-1830`); `new T[n]` is **not** parsed.

H6 adds: AST `Expr::NewArray { ty, count, init_args }` +
`Expr::DeleteArray { expr }` (split so codegen can dispatch);
parser `[expr]` suffix after `new T`; codegen emits
`HeapAlloc(GPH(), 0, n*sizeof(T) + 8)` with an 8-byte cookie
storing `n`, constructs `n` elements, returns the payload (cookie
hidden); `delete[]` loads `n = *(p-8)`, destructs elements `n-1`
… `0` (reverse construction order, per the standard), calls
`HeapFree(GPH(), 0, p-8)`.

Touch: `src/ast.rs`, `src/parser.rs`, `src/codegen.rs`. No
`src/pe.rs` change (HeapAlloc/HeapFree imported in Phase C).

- **RED** `tests/cpp_newarray.rs`: `int* a = new int[5]; a[0]=…;
  delete[] a;`; same with a class with ctor/dtor counters
  asserting `5 ctors + 5 dtors`.
- **GREEN**: ~80-120 LoC. **Regression**: O1 byte-identical
  (gated on new AST variant).

### H7 — operator overloading: `[]`, `()`, `=`

**Surprising finding**: binary-operator lowering `a @ b →
a.operator@(b)` already exists (`src/codegen.rs:1684-1710` —
`overloaded_binop`/`gen_binary`); parser's `operator_name`
(`src/parser.rs:970`) accepts `operator[]` and `operator()`
syntactically (lines 985-998). **What's missing is the call-site
lowering**: `expr[idx]` on a class with `operator[]` ⇒
`expr.operator[](idx)` (`Expr::Index` currently always lowers as
`*(base+idx)`, `src/codegen.rs:1437`); `expr(args)` on a class
operand ⇒ `expr.operator()(args…)`; `lhs = rhs` where lhs is a
class with `operator=` ⇒ `lhs.operator=(rhs)` (trivial member-
wise assignment stays the fallback; `operator=` is only lowered
when explicitly defined).

Touch: `src/codegen.rs` — three decision branches in existing
`gen_expr` dispatch. No parser change, no AST change.

- **RED** `tests/cpp_operators.rs`: `Vec` with `int&
  operator[](int)`; `Functor` with `int operator()(int,int)`;
  assign-overload side-effects.
- **GREEN**: ~80 LoC. **Regression**: O1 byte-identical (gated
  on `is_record()`).

### H8 — block-scope shadowing

**Surprising finding — this is NOT "verify it works"**:
`collect_decls` at `src/codegen.rs:3783-3804` flattens **all**
nested blocks into a single `locals: HashMap<String, …>`, so
`{ int x; { int x = 2; } printf("%d", x); }` collapses both `x`s
to the same slot — silent miscompile, observable today.

**Design**: assign a unique synthetic decl-id per declaration
site; `Stmt::Decl` and `Expr::Var` gain `decl_id: u32`; parser
maintains a scope stack and records the bound id on each Var;
codegen keys `locals` by decl-id. Recommended over a side-table
(smaller diff, AST authoritative, no lifetime concern).

Touch: `src/ast.rs` (decl-id fields), `src/parser.rs` (scope
stack), `src/codegen.rs` (resolution by decl-id).

- **RED** `tests/cpp_scope.rs`: inner-shadow with different
  values; addresses differ; parallel blocks with same name
  resolve to **different** slots.
- **GREEN**: ~100-150 LoC; AST shape change ripples through
  pattern matches.
- **Regression**: O1 byte-identical iff decl-id resolution is
  degenerate when no shadowing exists. Mechanical proof: in any
  TU where every name appears at most once per function, scope-
  stack lookup equals the flat HashMap lookup.

### H9 — global-init adjacent string-concat

`const char *s = "abc" "def";` is C99 §5.1.1.2/6 phase-6
adjacent-string-concat. mdbcc **does not** do this today (grep
`concat|adjacent` in `src/lexer.rs` ⇒ 0 hits): lexer emits two
`TokenKind::Str` tokens; parser sees two expressions and errors.
**Simplest fix**: post-pass in the `lex()` driver
(`src/lexer.rs:138-148`) — collapse adjacent
`TokenKind::Str { bytes, wide }` tokens with matching `wide`.
Pure post-pass; no parser change.

Touch: `src/lexer.rs` only.

- **RED** `tests/cpp_lex.rs`: `"abc" "def"` ⇒ one Str of length
  6; 3-way concat; mismatched-wide errors.
- **GREEN**: ~25 LoC. **Regression**: O1 byte-identical (no-op
  when no adjacencies exist). **Likely the smallest H increment.**

## Risk register

1. **Win64 struct-ABI subtlety (H1/H2).** Sizes 3/5/6/7 go
   **hidden-pointer**, **NOT** zero-padded to 4/8 — easy to
   misclassify. *Mitigation*: corpus covers size ∈
   {1,2,3,4,5,6,7,8,9,12,16,17,24}; `cl /O2` differential catches
   mechanically. *Impact if missed*: silent miscompile.

2. **Exception runtime is THE largest H increment (H4a + H4b).**
   `.pdata`/`.xdata` is intricate; format errors typically appear
   as `STATUS_BAD_FUNCTION_TABLE` process-kill, not a clean
   error. *Mitigation*: the H3/H4a/H4b split makes it tractable;
   H4a gets SEH plumbing right with the simplest payload (one
   int); H4b only adds type-matching.

3. **Mangling-scheme lock-in (H5).** mdbcc's Borland-ish scheme
   (`f$ic`) is incompatible with cl (`?f@@YAHHD@Z`) and Itanium
   (`_Z1fic`). *Mitigation*: keep current scheme; class methods
   never cross the DLL boundary (only `WIN32_IMPORTS` do).
   Revisit only if a Phase-I app links pre-built object files
   (none planned).

4. **Block-scope shadowing demands AST shape change (H8).** Risk:
   AST ripple accidentally breaks O1 in a no-shadowing function.
   *Mitigation*: prove the degenerate case by pre/post-H8 O1
   rerun.

5. **Over- or under-investment in H9.** Tiny (~25 LoC) but easy
   to gold-plate or skip. *Mitigation*: ship it; the lex-pass
   collapse is mechanical.

6. **Phase B vptr interaction with H1/H2.** A polymorphic class
   has a vptr at `[0,8)` and members shifted +8
   (`src/ast.rs:80-84`). The by-value copy must be sized by
   `Record::size` (incl. +8), **not** sum-of-fields.
   *Mitigation*: `Type::size()` already returns `Record::size`;
   use unmodified.

## Open questions (genuine)

1. **Hidden-arg ordering in a record-returning member function
   (H2).** Microsoft ABI: hidden return pointer is **first
   integer arg** (`rcx`); `this` is also normally first. cl's
   convention: return-ptr in `rcx`, `this` in `rdx`, real args
   from `r8`. *Recommendation: match cl exactly* — Phase B's
   `lead` machinery is already one-extra-arg; H2 generalises to
   two leads.

2. **Exception ABI: SEH vs Borland-style table unwind?**
   *Recommendation: SEH.* (a) OS unwinder is unforgiving truth —
   matching it gives the strongest runtime oracle (malformed =
   process-kill, never silent); (b) Phase-I OWL apps run on
   modern Windows where SEH IS *the* unwinder regardless of
   compile origin; (c) mdbcc has never matched bcc32 ABI byte-
   for-byte (it follows Microsoft Win64) — the bcc32 exception-
   table differential was always aspirational. Accept the gap
   as H-future / Phase-I-driven.

3. **Mangling scheme.** Discussed in Risk 3. *Recommendation:
   keep mdbcc's current scheme.*

4. **`catch (…)` catch-all.** Not in PoR; trivial (filter
   unconditionally returns `EXECUTE_HANDLER`). *Recommendation:
   include in H4a if one-line; defer otherwise.*

5. **Order H5 vs H7.** Either works. Current order keeps the
   smaller increment last. *Recommendation: ship as listed; swap
   if H5 grows.*

6. **Rethrow `Stmt::Throw(None)`?** Needs a live exception
   context (H4a runtime). *Recommendation: parse in H3; reject
   in codegen until H4a/b lands.*
