# Preserve Constructor Defaults During Overload Promotion

Status: SIGNED-OFF

## Scope

This design covers the first quality-map next step only: classify and fix the
GROUPBOX/EDIT constructor overload failures. The remaining next steps
(OWL/GDI helper link gaps, STATIC close heap corruption, HELLO/POPUP launch
crashes, and GCC torture/C89 triage) will each use the same workflow after this
step lands.

## Evidence

The Win64 OWL product matrix currently reaches these GROUPBOX/EDIT failures:

- `groupbox`: `GROUPBXX.CPP:error: 111:3: no matching overload for call to 'TOrderGroupBox::TOrderGroupBox'`
- `edit`: `EDITX.CPP:error: 289:3: no matching overload for call to 'TExampleEdit::TExampleEdit'`

Both failing call sites omit trailing constructor defaults:

- `TOrderGroupBox(..., TModule* module = 0)` is called with the first seven
  arguments.
- `TExampleEdit(..., UINT textLen = ..., BOOL multiline = TRUE,
  TModule* module = 0)` is called with the first seven arguments.

The parser already records in-class constructor defaults via
`Parser::note_defaults`. Normal overload registration preserves those defaults.
The suspicious path is later codegen promotion: when memberwise copy-constructor
synthesis needs to add a synthesized copy constructor, a sole user constructor
is removed from `sigs.funcs` and pushed into `sigs.overloads`, but that promoted
candidate is currently created with `defaults: Vec::new()`. That makes omitted
trailing-default calls non-viable and produces the observed overload error.

## Approach

Keep the fix at signature-registration level:

1. Add a small helper for looking up `TranslationUnit::overload_defaults`.
   The helper takes the source name and the full named parameter list exactly
   as registered on the function/prototype (`this` included for members and
   constructors). It must preserve the existing lookup contract:
   `d.len() == full_params.len()`, compare default-record parameter types
   against the no-`this` parameter types after `complete_record_sizes`, then
   return defaults aligned to the overload candidate's explicit parameter list
   by filtering out every `this` slot.
2. Use that helper in the existing definition/prototype overload-registration
   paths, preserving behavior while removing duplicated lookup logic.
3. Use the same helper in the constructor-promotion path that moves a sole user
   constructor from `sigs.funcs` into `sigs.overloads` before adding a
   synthesized copy constructor.
4. Add a focused regression for the exact promotion shape: an outer class has
   one non-copy user constructor with trailing defaults, no explicit outer copy
   constructor, and an own member whose type has a user copy constructor. The
   test should construct the outer class with omitted defaults through `new`
   and also copy-construct it, proving the promoted user constructor kept its
   defaults and the synthesized copy candidate did not inherit them.
5. Rerun the OWL product matrix and verify the captured output, not only the
   test exit status. The matrix currently asserts only green-example
   regressions, so known-gap rows need explicit inspection/grep: GROUPBOX and
   EDIT must no longer contain the constructor overload/default diagnostic.
   Update quality-map expectations to the newly observed phase if they progress
   past this overload failure.

## File Impact

- `src/codegen.rs`: preserve defaults when promoting a sole user constructor
  into an overload set; likely factor the repeated default lookup into a helper.
- `tests/end_to_end.rs` or `tests/i386_run.rs`: focused regression for the
  promotion/default interaction. Prefer `tests/end_to_end.rs` unless the
  observed failure proves target-specific.
- `tests/owl_examples_product.rs`: update GROUPBOX/EDIT expected phases only
  after observing the post-fix product matrix. Do not treat `BuildOnly` as
  runtime/window success.
- `tests/quality_map.rs`: retire or reword the completed GROUPBOX/EDIT overload
  item only while preserving traceability, for example by adding/updating a
  `MAP_DRIVEN_OUTCOMES` entry with the exact evidence command and observed
  before/after phase.
- `wrk_journals/2026.06.19 - JRN - resolve quality next steps.md`: keep the
  task journal current.

No version bump is planned for this design step. Implementation changes shipped
compiler behavior, and this repo is versioned at `0.7.6` in `Cargo.toml` and
`Cargo.lock`, so the implementation commit must include exactly one patch bump
to both files.

## Acceptance Criteria

- A focused regression for the exact promotion shape fails before the fix with
  `no matching overload` and passes after the fix.
- The regression covers both omitted-default construction and copy construction
  so the synthesized copy candidate remains usable and does not inherit the
  user constructor's defaults.
- Existing default-argument constructor tests still pass.
- `mdtimeout 120 -- cargo test -q --test end_to_end default_arg -- --nocapture`
  passes, adjusted if the new regression lands in a narrower test target.
- `mdtimeout 900 -- cargo test --release --test owl_examples_product owl_stock_product_matrix_win64 -- --ignored --nocapture --test-threads=1`
  is run with product prerequisites present. Its captured output is checked for
  the GROUPBOX and EDIT rows, and those rows no longer contain the constructor
  overload/default diagnostic. The test's pass exit status alone is not
  sufficient evidence for known-gap rows.
- If GROUPBOX/EDIT advance to a link/runtime known gap, the product matrix and
  quality map name the new observed phase instead of the stale overload blocker.
- Worktree is clean after commit and all intended changes are committed on
  `task/resolve-quality-next-steps`.

## Decision Log

- Keep the first workflow pass scoped to the top quality-map item. Solving all
  next steps in one design would mix unrelated parser/codegen, link, and runtime
  problems and weaken review.
- Preserve constructor defaults at the promotion site rather than special-casing
  GROUPBOX/EDIT or relaxing overload resolution globally.
- Use a focused synthetic regression plus the product matrix. The synthetic test
  gives a fast oracle for the exact bug; the product matrix proves the real OWL
  examples moved.
- Preserve quality-map traceability when retiring or rewording a backlog item;
  the map should explain what changed and name the command that proved it.

## Adversarial Review

Three read-only reviewers checked the design, followed by one refutation pass.
Surviving findings folded into this draft:

- Important: The helper contract must include the full raw arity check with
  `this` present, no-`this` parameter-type matching after record-size
  completion, and `this` filtering in the returned `Overload.defaults`.
- Important: The regression must force the actual promotion path and also use
  the synthesized copy constructor, not just a generic default-argument
  constructor.
- Important: The OWL product matrix does not assert known-gap row details, so
  acceptance needs explicit output inspection for GROUPBOX/EDIT.
- Important: Quality-map edits must preserve evidence and traceability.
- Residual risk: Non-overloaded extern constructor prototypes use source-form
  symbols, while promotion creates an overloaded/mangled candidate. This is
  expected to be consistent when caller and libraries are rebuilt by mdbcc, but
  GROUPBOX/EDIT may advance from overload failure to a link-symbol issue.
- Residual risk: parser finalization refreshes `fn_defaults` expressions but
  not `overload_defaults` expressions. GROUPBOX/EDIT use scalar/null/bool
  defaults, so this is probably not this bug; record-typed default expressions
  remain a separate parser-side risk.
