# Next North-Star After RailC Self-Host

Date: 2026-06-11

## North-Star

Move from "RailC self-host works" to "bcc32 compatibility is hard to regress."

The next useful target is not another large heroic closure. It is a small sequence of conformance hardening slices that preserve the RailC win while reducing the highest remaining compatibility risks from the self-host campaign.

## First Slices

1. Promote the RailC acceptance harness shape.
   - Decide which ignored `wrk_probe` scripts should become tracked, stable test assets and which should remain local scratch.
   - Keep generated binaries, object caches, screenshots, and oracle outputs ignored.
   - Done when a fresh checkout has enough documented commands to reproduce the self-host acceptance without relying on session memory.

2. Close the C++ exception object lifetime gap.
   - Focus on thrown class object copy construction and catch-side destruction.
   - Use tiny bcc32 differential probes before touching the RailC-sized path.
   - This is the most direct follow-up to the parked G58 family and reduces risk in real OWL error paths.

3. Audit x64 parity for the i386 G55/G57 family.
   - Check x64 marshal/ref-binding and cross-TU EH behavior against the i386 fixes.
   - Land only narrow fixes backed by differential probes.

4. Add file-scope arrays of ctor-class globals.
   - Current support covers default-ctor file-scope globals, but not arrays such as `G g[3];`.
   - Use one small runtime differential test before generalizing.

5. Improve floating/CRT fidelity only where an oracle demands it.
   - `_control87` is currently a software-control-word shim.
   - `_fuildq` loses precision above 2^53.
   - These should be pulled by failing scanf/strtod/formatting evidence, not speculative cleanup.

## Parked Until There Is Better Leverage

- Common-dialog Set data file select-success automation. Revisit with a debugger/API hook, manual acceptance pass, or an instrumented app build.
- Parser C-TU mode for the principled `!proto.c_linkage` force-cpp fix.
- EXCEPT.C `_EAX` pseudo-register support.

## Working Rule

Keep the new phase boring: one differential probe, one targeted fix, one validation gate, one commit. The RailC closure is now the regression anchor, not the place to discover every remaining compiler bug.
