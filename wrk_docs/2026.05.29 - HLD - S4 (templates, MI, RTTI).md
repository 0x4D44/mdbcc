# HLD — S4 (templates · multiple inheritance · RTTI)

Stone **S4** of `2026.05.26 - PLAN - Ultimate goal (BCC 4.52 conformance).md`.
The C++-maturation language features that OWL 4.52 + the BIDS class library
require, so S5 ("build OWL") can recompile the real Borland source and S6 can
run OWL sample apps. Successor context: **S3 LANDED** (real `<windows.h>`
compiles+links+runs; HELLOWIN.C is a live native i386 GUI app).

## Scope — driven by what OWL actually uses (ruthlessly minimised)

A minimal OWL app is tiny at the source level (verified against the real
samples):

```cpp
// HELLOAPP.CPP                      // STEP01.CPP (tutorial)
#include <owl/applicat.h>           class TDrawApp : public TApplication {
int OwlMain(int, char*[]) {           void InitMainWindow() {
  return TApplication("Hi").Run();      SetMainWindow(new TFrameWindow(0,"…"));
}                                     } };
                                    int OwlMain(int,char*[]){ return TDrawApp().Run(); }
```

The **app** needs only single inheritance + a virtual override + `new` +
member calls — **all already supported**. Templates/MI/RTTI are needed to
compile the **OWL headers + library** that these pull in. So S4's true scope
is whatever those headers/`SOURCE/` use — discovered EMPIRICALLY by compiling
the OWL headers (the S3 playbook: surface a gap → RED→GREEN → diff vs bcc32),
NOT by building a general C++ template engine speculatively.

### Probe (2026-05-29, current `bcc -c`)
| Feature | State |
|---|---|
| function template `template<class T> T f(T)` | GAP — parser: "expected a type" |
| class template `template<class T> struct Box{…}` | GAP |

Templates are the long pole (absent entirely). MI has a head start. RTTI
absent.

## Design

### Templates — monomorphisation (the only sane strategy)
Exactly what every C++ compiler does, and it fits mdbcc's "no generics at
runtime" model: a template is a *recipe*; each distinct set of type arguments
yields a fresh concrete entity fed into the EXISTING codegen.

- **Parse** (translation phase): `template < param-list > decl`. `param-list`
  is `class`/`typename` (+ optional `= default-type`) and (later) non-type
  params. Capture the generic `decl` (a `Function` or `Record`) verbatim with
  its param names; do NOT codegen it. New AST: `Item::Template { params,
  body: TemplateBody::{Func(Function) | Record(Record)} }` (and a registry).
- **Instantiate on use**:
  - *Function template*: at a call `f(args)` where `f` names a function
    template, **deduce** each `T` from the argument types (the BC4.52 subset:
    deduce `T` from a by-value/`T&`/`T*`/`const T&` parameter against the
    argument's static type; explicit `f<int>(…)` overrides deduction).
    Substitute the deduced types through a clone of the generic `Function`,
    mangle the instantiation (Borland template mangling `@…$…`), and run it
    through the normal function-codegen path. Cache by (name, type-args) so
    one instantiation is emitted per distinct signature.
  - *Class template*: when a type `Box<int>` is named, substitute through a
    clone of the generic `Record` → a concrete `Record` registered under the
    mangled tag; its member functions become function-template-like
    instantiations (emitted on use). Cache by (tag, type-args).
- **Substitution** is a structural walk replacing `Type` references to a
  template param with the concrete argument type, in: member/param/return
  types, local decl types, `sizeof`/cast types, and nested template-ids.
- **Two-phase is NOT attempted**: like bcc32-era compilers, names in the
  template body are resolved at instantiation time against the concrete
  types (no `typename`/`template` disambiguation rigor beyond what the real
  headers need). Add `typename`/`template`-keyword tolerance only as headers
  demand it.

### Multiple inheritance — extend the working base
Non-virtual MI already lowers. Outstanding work, surfaced as OWL needs it:
- **Base subobject layout** for >1 base (offsets; `this`-adjustment when
  up/down-casting to a non-leading base — the classic `add this, off`).
- **Virtual bases** (`class D : virtual public B`) if OWL uses them (TStreamable
  mix-ins may) — vbase pointer/offset. Defer until a header forces it.
- **vtable composition** across multiple polymorphic bases (one vptr per
  polymorphic base subobject; thunks for overrides reached through a
  non-leading base).

### RTTI — minimal, real-data
- `typeid(expr)` / `typeid(Type)` → a `type_info` object. Borland's
  `type_info` layout + the per-class RTTI descriptor the vtable points at.
- `dynamic_cast<T*>(p)` → walk the RTTI graph (downcast/crosscast); `0` on
  failure, the adjusted pointer on success. `<typeinfo>` header acceptance.
- Scope to what OWL uses (OWL 4.52 uses RTTI sparingly; `TYPESAFE_DOWNCAST`
  macro + streaming). Build the descriptor emission first, then the casts.

## Staged plan (each: smallest RED→GREEN, diff-tested vs bcc32, byte-identical)
1. **S4.1 Function-template monomorphisation** — `template<class T> T maxv(T,T)`
   deduced + explicit; cache; Borland mangling. The foundation.
2. **S4.2 Class-template monomorphisation** — `Box<int>` data + member fns;
   default type args; member-out-of-line.
3. **S4.3 Compile the BIDS container headers** the OWL closure pulls in
   (ARRAYS.H/…): drive surface-first, fix template gaps as they appear.
4. **S4.4 MI completion** — non-leading-base `this`-adjust + vtable
   composition (+ virtual bases iff a header needs them).
5. **S4.5 RTTI** — `type_info` + `typeid` + `dynamic_cast`, scoped to OWL.
6. **S4.6 Compile `<owl/applicat.h>` + `<owl/framewin.h>`** (the minimal-app
   closure) end-to-end → the S4→S5 seam.

## Testing oracle
- bcc32 differential (O12-style exit/stdout) for every template/MI/RTTI
  behaviour — the correctness multiplier.
- Compile-acceptance ratchets for the OWL/BIDS headers (the S3 O15/parse-floor
  pattern), SHA-locked once stable.
- **Non-negotiable invariant (every tick):** the 88 x64 SipHash + x86 stripe
  stay byte-identical (templates/MI/RTTI are new surface; a TU using none must
  emit identical bytes), `cargo test` green, `clippy -D warnings` clean.

## Risks
- **Scope creep** — a general template engine is a tar pit. Mitigation: only
  build what compiling the real OWL closure demands; let the headers pull the
  feature set. Stop the moment `<owl/applicat.h>`+`framewin.h` compile.
- **Mangling fidelity** — Borland template/MI symbol mangling must match the
  precompiled OWL `.lib` for S5 linking. Mitigation: probe bcc32's emitted
  symbols (`tdump`/COFF) and differential-mangle, as S1b/S2 did for the
  function/overload manglers.
- **Instantiation explosion / infinite recursion** (recursive templates).
  Mitigation: cache + a depth bound with a clean diagnostic.
