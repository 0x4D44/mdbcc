## 3. "BUGS.MD" — direction of travel

**There is no `BUGS.md` in this repo** (confirmed: no `BUGS*` file on disk; `git ls-files` shows none). The project tracks defects through three de-facto mechanisms instead:

1. **The RailC link-closure count** — the number of unresolved externals when linking RailC. This is the project's primary "burndown" metric, threaded directly into commit subjects (e.g. `closure 343→30`, `closure 287→134`, `closure 8→0`).
2. **The `G##` gap-fix log** — a numbered series (G1…G57b) where each commit closes one C++/codegen/linker compatibility gap.
3. **Known-gap tests** — incomplete behaviour encoded honestly as locked tests (e.g. `s4_mi_plus_rtti_secondary_base_dynamic_cast_known_gap`).

**Direction of travel:**

- **i386 link-closure: high-hundreds → 0.** Drove from ~498 (06-07) to 0 (06-10), validated on 06-11 (`b188eb6`). A 06-08 "reality correction" exposed earlier optimistic figures (25/26/30) as stale-archive artifacts; the true count was 287 — a standing reminder that the closure metric is only as honest as the archive set it's measured against.
- **The frontier metric has moved.** Link-time unresolved externals are now *saturated at zero* on both targets. The live metric is now **"runtime survival to first window,"** which is currently failing at `0xC0000374`.
- **The bug *class* has migrated** from C++ semantics (multiple inheritance, shared virtual bases, RTTI, cross-TU exceptions) toward **ABI / pointer-width defects** (WNDPROC truncation, 32-bit `WPARAM`/`LPARAM`/`LRESULT` typedefs, `int32` dispatchers, heap-layout corruption) as the target moved from i386 PE32 to AMD64 PE32+.

**Recommendation:** stand up a lightweight `BUGS.md` consolidating the scattered known gaps (see Issue tracker §10) into one registry. This is directly required by the formally-nominated "hard to regress" north star and is currently the weakest part of the project's defect observability.

## 9. Trends (vs the historical docs)

1. **Metric saturation → metric shift.** "Unresolved externals at link" went from the project's central burndown to fully saturated (0 on both i386 and Win64). The meaningful metric is now *runtime survival to first window*.
2. **Bug-class migration.** C++ semantics gaps (MI / vbase / RTTI / cross-TU EH) are largely closed; the new defects are ABI/pointer-width (WNDPROC truncation, 32-bit message typedefs, heap layout). This is the predictable consequence of moving i386 → AMD64.
3. **Strategic bifurcation.** The formal 2026-06-11 PLN names *conformance hardening* as the next north star; every doc/commit since 06-12 pursues *native Win64*. Both are legitimate — but they coexist informally, and Win64 is winning in practice without an explicit decision.
4. **Cadence pulse.** 47 commits/day peak → closeout lull → today's Win64 burst. Healthy rhythm; work is being committed atomically (the heavy Win64 diff went from dirty tree to 4 clean commits within the day).
5. **Observability decaying relative to velocity.** Coverage 683 commits stale, reviews ~4 weeks stale, no BUGS.md — all at odds with the "hard to regress" ambition.
