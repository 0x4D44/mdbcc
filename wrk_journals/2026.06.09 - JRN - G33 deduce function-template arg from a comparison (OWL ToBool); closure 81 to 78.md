# 2026.06.09 — G33: deduce a function-template argument from a COMPARISON result (OWL's `ToBool<T>`); railc closure 81 → 78

One-line root-cause fix unblocking the OWL geometry inline operators.

## Symptom

`TPoint::operator!=`, `TSize::operator!=`, `@TRect@Contains$xqr6TPoint` were
unresolved — referenced (FRAMEWIN/GADGETWI/WINDOW/…) but **defined nowhere**,
even though they're inline in `OSL/GEOMETRY.H`. FRAMEWIN.o emitted the *other*
TPoint inline operators (`operator+`, `operator-`, …) but not `==`/`!=`.

## Root cause

The two un-emitted operators are exactly the ones whose body calls the OWL
function template `ToBool<T>`:

```cpp
template<class T> inline bool ToBool(const T& t) { return static_cast<bool>(t); }
inline bool TPoint::operator !=(const TPoint& o) const { return ToBool(x != o.x); }
```

The template monomorphizer (`src/codegen/template.rs`) deduces `T` from the call
argument via `type_of_expr`. That helper typed *arithmetic* binaries (`+`, `-`,
`<<`, …) but deliberately routed *relational/logical* ones (`==`, `!=`, `<`,
`&&`, …) to `None` — with a comment "a comparison is never a sensible `min<T>`
argument anyway." But `ToBool(x != o.x)` deduces `T` **from a comparison**. With
the argument un-typeable, `T` was undeducible → `ToBool` was never instantiated →
`rewrite_stmts` errored → the calling inline was **deferred and DROPPED** (the
S4.2g mechanism), with the note already seen on LAYOUT.CPP:
`deferred … not-yet-instantiable template calls (S4.2g): TPoint::operator==, TPoint::operator!=, …`.

## Fix

`type_of_expr` now types a relational/logical binary as `int` (C's "comparison
yields int" rule — codegen's own `expr_type` agrees, pe_writer.rs:9035). `ToBool(x
!= o.x)` deduces `T = int`, `ToBool<int>` instantiates, and the operator is
emitted (as a weak vague-linkage def). This is *more* correct, not a hack — a
comparison genuinely has type int; previously valid `min<T>(cmp, x)` deduction
(if any) only becomes the C++-correct "both args must agree" rule.

## Effect

- railc closure **81 → 78**: `TPoint::operator!=`, `TSize::operator!=`,
  `@TRect@Contains$xqr6TPoint` resolve.
- `ToBool` is used pervasively in OWL (`IsString`/`TestFlag`/`IsRef`/…), so this
  also unblocks those inline accessors wherever they're live.
