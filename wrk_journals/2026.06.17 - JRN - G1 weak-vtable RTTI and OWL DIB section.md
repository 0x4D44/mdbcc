# 2026.06.17 - JRN - G1 weak-vtable RTTI and OWL DIB section

## Context

This continues the "toolchain generality and scale" goal. G0 is already landed
locally as F-26/F-27 (RailC Win64 toolbar and Start-dialog fixes). The current
dirty slice is a G1-style productization/generalization slice: make vtable RTTI
metadata safe across TUs and let the Win64 BC45 lib producer include the useful
sectioned part of OWL `DIB.CPP`.

## Findings

- Cross-TU weak vtable folding exposed a layout hazard. A TU that did not use
  `dynamic_cast` could emit a no-prefix weak `@Tag@3` vtable; if that copy won
  the image-wide fold, another TU's `dynamic_cast` would read the word before
  the vtable as an adjustment/base-link prefix and compute a bogus pointer.
- The fix is to make the vtable RTTI prefix unconditional for polymorphic
  vtables. The vtable symbol still points at the slot array, so virtual
  dispatch sees the same address shape; only the bytes immediately before the
  symbol become uniform and safe for RTTI/EH walkers.
- `virtual.c` in the i386 byte stripe legitimately changed because it contains
  polymorphic classes but no `dynamic_cast`; this is the exact no-prefix shape
  the fix removes. Re-blessed only that fixture:
  `0x4945_1685_8989_2a16 -> 0x3dd9_20c3_3104_a639`.
- Fstream-shaped truthiness through the shared virtual base needs conversion
  operator lookup to walk primary, extra, and virtual bases, not just the primary
  `base` chain. `record_lookup_ids` now supplies that walk for conversion
  operator discovery.
- OWL `DIB.CPP` is Borland-sectioned. The full TU still exceeds current
  compiler stack limits in bitmap read/write sections, but `SECTION=1` provides
  `TDib::ToClipboard`, which RailC and OWL clipboard helpers need. The lib
  producer now adds `SECTION=1` for that source.
