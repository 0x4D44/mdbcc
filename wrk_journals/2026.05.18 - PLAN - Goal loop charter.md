## Operating model — I am the SUPERVISOR (protect my context)
The bottleneck is the supervisor's context. Therefore:
- **Delegate all heavy work to subagents** (Agent tool — each gets
  its own fresh context). Heavy = reading large code, writing HLDs,
  implementing, rigorous code review, applying review feedback.
- **The supervisor keeps only cheap, authoritative work**: pick the
  next increment from the plan of record; write precise subagent
  briefs; run the quality gates (`cargo test`, `cargo clippy
  --all-targets -- -D warnings`) — these are the ground truth and
  ~1 call each; `git` commit/push; journal; schedule the next tick.
- Never read big diffs/files yourself. Trust subagent summaries +
  the test/clippy oracles to gate quality. The oracles, not the
  prose, decide correctness.

## Per-iteration protocol (one reviewed increment per tick)
1. Re-ground: read this charter, plan of record, newest
   `wrk_journals/*JRN*` tail, `git log --oneline -8`, `git status`.
   If a phase has no HLD, the increment is "write the HLD".
2. Pick the SMALLEST next increment of the current phase that ends
   in a committable, green state. Map to the documented process:
   DESIGN(HLD) → TDD RED → IMPL GREEN → code-review (subagent,
   artifact in `wrk_journals/reviews/`) → apply-feedback → commit.
3. Brief a subagent with: exact scope, deliverable, files, the
   "leave it green" contract, and "return a terse summary, not
   dumps". Use a separate subagent for the code review (skeptical,
   independent). Run subagents in worktree isolation only if they
   would otherwise collide.
4. Gate (supervisor, mandatory): `cargo test` must be all-green and
   `cargo clippy --all-targets -- -D warnings` clean **before any
   commit**. O1 `tests/end_to_end.rs` is authoritative and stays
   byte-identical for unrelated features (regression guard). If a
   subagent's work fails the gate, send it back (don't fix it
   yourself unless trivial); never commit red.
5. Commit atomically (impl+tests one commit; docs/journal another),
   then fast-forward `main` and push both refs (the established
   `git fetch . feat/test-oracles-v1:main` + push pattern).
6. Journal every tick to `wrk_journals/YYYY.MM.DD - JRN - <desc>.md`
   (naming convention strict). Update the roadmap journal backlog.
7. Schedule the next tick and continue.

## Quality gates (hard, non-negotiable)
- All test suites green; clippy `-D warnings` clean; O1 e2e
  byte-identical for non-targeted features.
- Atomic commits; everything pushed every tick (unattended-safe:
  never leave broken or uncommitted state at a tick boundary).
- House style: errors are explicit `CodegenError`, never silently
  wrong; smallest change that satisfies; no speculative
  abstractions; no new crate deps without need.

## Stop / escalate to Arthur (end the loop, journal why)
- A genuine architectural fork or ambiguous product decision (not
  covered by the plan of record / D-1..D-3).
- A blocker that cannot be resolved without Arthur (e.g., needing a
  provenance-pinned genuine OWL source acquisition — Phase I D-1).
- Roadmap complete (Phase I success criteria met).
- Repeated inability to get a subagent increment green (2 tries) →
  stop, journal the wall, leave green, hand back.
Otherwise: keep driving. "As long as possible" = until done or
genuinely blocked, not until bored.
