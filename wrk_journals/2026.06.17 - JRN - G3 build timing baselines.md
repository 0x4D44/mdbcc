# 2026.06.17 - JRN - G3 build timing baselines

## Context

G3 of `wrk_docs/2026.06.17 - GOAL - toolchain generality and scale.md`
requires a repeatable build-time baseline before any performance patch. This
slice used release-built tools and kept all generated outputs under
`wrk_probe/perf_baseline_2026_06_17/`.

RailC's checked `C:\language\railc\mdbcc.toml` writes under the RailC tree, so
the timing run generated a workspace-local equivalent manifest at
`wrk_probe/perf_baseline_2026_06_17/railc_product/mdbcc.toml`. It reads the
RailC sources/resources from `C:\language\railc` but writes the executable and
intermediates inside this repo.

## Commands

- `mdtimeout 600 -- cargo build --release --bins`
- Product builds with `MDBCC_TIME=1`:
  - `target/release/mdbcc.exe --config wrk_probe/owl_examples_product/button/mdbcc.toml`
  - `target/release/mdbcc.exe --config wrk_probe/owl_examples_product/instance/mdbcc.toml`
  - `target/release/mdbcc.exe --config wrk_probe/perf_baseline_2026_06_17/railc_product/mdbcc.toml`
  - same RailC manifest with `MDBCC_JOBS=1`
- `mdtimeout 600 -- cargo test --release --test perf_harness -- --ignored --nocapture`

Raw logs and `summary.json` were written under
`wrk_probe/perf_baseline_2026_06_17/`.

## Synthetic Harness Baseline

- Tier 1 full compile, 2000 generated functions, 253599 bytes:
  - min 84.099 ms, median 85.703 ms, max 88.607 ms, n=5.
- Tier 2 preprocess guarded header re-include, 140711-byte header, 5 includes:
  - min 17.143 ms, median 18.939 ms, max 20.065 ms, n=10.

## Takeaways

- For the measured RailC/product workload, codegen dominates the serial sum
  (~61.1s) and the sample apps show the same shape (~1.8s codegen per small
  OWL TU). Header/preprocess work is material but not the largest measured
  bottleneck here.
- Default project parallelism hides most of RailC's per-TU codegen cost:
  default wall was ~5.3s versus ~68.0s with `MDBCC_JOBS=1`.
- The first G4 optimization candidate should be selected from codegen profiling
  or a narrower codegen timing split, not from the earlier tokenize-once header
  cache hunch unless future measurements contradict this baseline.
