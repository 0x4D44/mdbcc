# 2026.06.09 — railc closure 72 → 49: the reused oracle RTL/BIDS libs were STALE (old mdar — weak symbols unindexed); regenerated in place

Not a code change — a deliverable correction that the G32 mdar fix made possible.

## What happened

The all-mdbcc closure reuses `wrk_oracle/mdcw32.lib` (RTL) and
`wrk_oracle/mdbids.lib` (BIDS) rather than recompiling the RTL each run. Those
`.lib` files had been built by `mdar` BEFORE the G32 weak-symbol-indexing fix, so
their symbol index advertised only plain `External` symbols. Every vague-linkage
definition (the iostream `streambuf`/`filebuf`/`fstreambase`, `xalloc`,
`string::clone`, `TThread::CheckStatus`, `TRegexp::find`, …) is emitted WEAK and
was therefore UNINDEXED → the linker (which pulls members only via the index)
never pulled the members that define them → ~23 "unresolved" symbols that were
actually present in the archives all along.

## Fix

Regenerated both libs with the current (post-G32) `mdar`:

```
mdar -o wrk_oracle/mdcw32.lib  wrk_oracle/rtl_objs/*.o    (567 members, 1103 symbols)
mdar -o wrk_oracle/mdbids.lib  wrk_oracle/bids_objs/*.o   (19 members,  942 symbols)
```

The objs are mdbcc-built (weak `string::clone`, bare-form member symbols), so the
libs remain valid self-host deliverables. The `.lib` files are gitignored
artifacts — no source/tracked change. `closure.sh` now rebuilds them from objs
each run so measurements stay accurate against the live `mdar`.

## Effect

- railc closure **72 → 49**. Resolved the whole iostream/streams RTL cluster
  (`streambuf::*`, `filebuf::*`, `fstreambase::open`, `xalloc::*`,
  `string::clone`, `TStreamableBase::~`, `TThread::CheckStatus`,
  `TRegexp::find`, …). A few new file-I/O deps surfaced (`open`/`read`/`write`/
  `lseek`/`close`) — pulled by the now-live `filebuf`.

KEY INSIGHT: the iostream/streams RTL (the data-bearing ios diamond) is ALREADY
compiled in the mdbcc rtl_objs and links — so the streams half of "Stage-3" is
covered by the prebuilt RTL. The remaining Stage-3 work is railc-DIRECT:
LAYOUT.CPP's own `fstream` variable declaration (the `TLayout::*` cascade).
