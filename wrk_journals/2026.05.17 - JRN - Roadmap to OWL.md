1. **Compiler core (slices 1–14) is DONE and solid.** C89 + a real
   C++ subset + Borland dialect → Win64 PE, emitted directly (no
   external assembler/linker). 88 hand-expected e2e (O1, authoritative)

   (36056b4 / 2010507 / 7cf7390). Large .text/.data build & load.
3. **OWL is entirely unaddressed.** Zero OWL/Windows-GUI code. The
   user's brief explicitly includes "plus OWL Windows library"; this
   is the bulk of the remaining work.
4. **Critical prerequisites for OWL are missing in codegen:**
   - >4 function arguments (Win64 stack-arg ABI). CreateWindowEx = 12
     args ⇒ hard blocker for Win32.
   - Function pointers (WndProc callbacks) — not parsed/codegen'd.
   - Virtual functions / vtables / virtual dtors — the heart of OWL;
     essentially absent (codegen grep: 2 hits; parser only skips
     `virtual` in base clause).
   - Imports are a fixed 6-symbol single-DLL KERNEL32 array;
     Subsystem hard-coded to console (3). No user32/gdi32, no WinMain,
     no GUI subsystem.
   - No float/double, no exceptions, no resource (.rc) compiler,
     no struct-by-value, no member-fn overloading, no array-new.
5. **BCC55 free CLI ships no OWL** (OWL shipped with the BC++ IDE
   products, not the free 5.5.1 command-line tools). So OWL must be
   reimplemented (a faithful subset) in our own dialect — consistent
   with the project being a *reimplementation of BCC + OWL*.

## Phase A1 — >4 args — DONE (2026-05-17)
- TDD RED: tests/calling.rs (9 tests) all failed (5 A1 hit the 4-param
  cap, 4 A2 unparsed). Confirmed.
- IMPL (src/codegen.rs only): removed the >4-param/4-arg caps;
  Win64 stack-arg ABI. Key design = **deferred frame sizing**: emit a
  placeholder `sub rsp,imm32`, track `max_stack_args` while emitting
  the body, re-patch the imm32 in `run` (mirrors existing jump-patch
  infra). ⇒ no call-arity prediction; ≤4-arg/io-only functions emit
  **byte-identically** (max_stack_args==0 ⇒ outgoing==io_out ⇒ same
  imm). Params 0..3 spill from regs (ARG_SPILL); params ≥4 copied in
  from `[rbp+16+8*i]`; outgoing args ≥5 written to `[rsp+0x20+8*(i-4)]`.
- GREEN: 5/5 A1 tests pass (5/6/8-arg weighted sums, >4-arg+printf in
  one fn, nested >4-arg call). Regression: lib 59 · O1 e2e 88 ·
  pe_layout 2 · printf 5 — all green, byte-identical preserved.
- Known limit (noted, house-style explicit): deeply nested many-arg
  calls can exceed the 16-temp budget; not bumped (would change frame
  size for ALL fns ⇒ break byte-identical regression). Tests avoid it.
