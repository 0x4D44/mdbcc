The single biggest OWL-closure wall — the DECLARE_STREAMER nested-`Streamer`

regression-free. OWL source compilation: **60→66 / 119**.

## The 5-attempt arc and the decisive breakthrough

Prior attempts (2, 4) RUN-passed the repro + full suite but REGRESSED real
OWL files (APPLICAT/WINDOW/GAUGE → window.h:409 "expected a member name").
Two wrong hypotheses were ruled out by instrumentation this turn:
1. attempt-2: blamed the `tags[orig]` OVERWRITE → wrong (attempt-4 was
   scoped-only, no overwrite, still regressed).
2. attempt-4: blamed the MINT itself → wrong (the bare mint, no tag rebind,
   compiles APPLICAT fine).

**The actual cause: the TAG REBIND broke ctor detection.** `is_ctor` compares
the member name token to `tag_s` (the class tag). Rebinding `tag_s` to the
unique `Streamer$<id>` made the source `Streamer(...)` ctor fail that compare
→ parsed as a stray method → member-loop desync at the NEXT method
(window.h:409). The dtor detection (bare `~` + name, no tag compare) was
never affected — which is why only ctors desynced.

## The landed feature

- Collision (`defined_records` + a `class_nest` stack — cur_class is None
  during nested parse) ⇒ mint a FRESH record with a unique tag
  `Inner$<id>`; flat `tags[Inner]` left untouched.
- **ctor/dtor detected by the BARE source name** (`name_tag`), so the
  rebound tag drives only the SYMBOL keys, not name recognition.
- Every nested class also registers a SCOPED key `Outer::Inner -> id`;
  `qualify_nested` (qualified types) and the out-of-line member-def path
  resolve via it, keying symbols off the resolved record's tag so inline +
  out-of-line registrations match.
- Non-nested / non-colliding classes are byte-identical (name_tag==tag_s,
  no scoped key, no mint) — 88 baselines + the Lock triple unaffected.

RUN 42 vs bcc32: two `Streamer`s (TBase+TButton), the derived one's inline +
out-of-line `GetObject()->IsDefPB` and an external `TButton::Streamer s;` all
resolve correctly.
