# JRN — Open-source snapshot

Date: 2026-09-22. Host: crucible.

## What happened

mdbcc went public today as `0x4D44/mdbcc`, a single root commit (`470011a`)
carrying the trunk tree at version 0.7.12. The full development history was
kept, private, as `0x4D44/mdbcc-history`. Repo URL and `origin` are unchanged.

## Decisions

- **Licence: MIT OR Apache-2.0** (the Rust convention), not GPLv3. mdbcc
  places its own code inside every executable it links (the synthesised CRT
  startup in `src/link/crt.rs`, the RTL shims, the Win64 `STDARG.H` and thunk
  header), so plain GPLv3 would have encumbered users' binaries; a permissive
  licence needs no runtime exception.
- **Fresh repository rather than a force-push.** A rewritten `origin/main`
  would have tripped the fleet trunk guard on every clone and left the old
  Borland-bearing objects fetchable by hash from GitHub for a long time. A new
  repo under the old name gets the same URL, needs no guard escape, and leaks
  nothing. Catch-up per clone: `git fetch --prune origin && git update-ref
  refs/heads/main refs/remotes/origin/main` (equal to origin, so allowed).
- **Borland/Microsoft sources out, patches in.** The six patched OWL/WINDEF
  copies in `wrk_owl_win64/` became `wrk_owl_win64/patches/*.patch`, applied to
  the user's own BC4.52 tree by the std-only applier in `src/overlay.rs`.
  Proved by byte identity of the four Win64 archives before and after.
- **Sample programs rewritten.** `tests/gui.rs` embedded five Borland OWL
  samples (HELLOAPP, INSTTEST, CURSAPP, STATTEST, SCRIBAPP), not the three a
  first grep found. Each is now an original fixture satisfying the same
  behaviour oracles; the "real_" test-name infix went with them.
- **The BC4.52 tree is fetched, never committed**: `scripts/get-bc45.ps1`
  pulls the WinWorld archive (SHA-256 pinned) into git-ignored `wrk_oracle/`.

## Surprises

- Task worktrees do not see `wrk_oracle/`; everything that touches the BC4.52
  tree must honour `MDBCC_BC45_ROOT`, which the overlay work now centralises in
  `overlay::resolve_bc45_root`.
- `git show <blob>` yields LF while the working tree is CRLF under
  `core.autocrlf=true`; a byte comparison of generated overlay output must be
  made against the working-tree copies, not the blobs.
- The trunk is not rustfmt-clean in ten files (scratchpad entry).
