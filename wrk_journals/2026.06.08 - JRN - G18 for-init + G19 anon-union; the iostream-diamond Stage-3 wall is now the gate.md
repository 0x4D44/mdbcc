## Committed this arc

- **G18 (64119af)** — multi-variable for-init `for(int a=0,b=0;…)`. The init
  parses as a `Stmt::Block`; the For codegen bound it via `gen_stmt(Block)`,
  which pushed the Block's own scope and POPPED the loop vars before `cond`. Now
  a Block init's statements are INLINED into the enclosing for-scope (Borland
  for-leak #42 preserved). RUN-verified (6 vs bcc32). OWL DIB.CPP :235→:437.
- **G19 (b6ebae9)** — LOCAL anonymous union/struct member promotion
  (`union { A a; B b; };` → bare `a` rewrites to `$anonu.N.a`). Parser-only:
  a declarator-less anon record emits a hidden local + registers member→hidden
  promotions; `primary` rewrites, gated on the hidden local being a current
  `fn_locals` member (so stale promotions are inert). RUN-verified (42 vs bcc32,
  proving member promotion + union aliasing). OWL DIB.CPP :437→:756.

Both gated on suite (1677/0) + clippy (0) + the OWL compile sweep (82/119, no
regression) per the G15 lesson.

## The decisive finding: the wall is Stage-3 (iostream diamond) + frame MI

Tracing the DIB chain — for-init (G18) → anon-union (G19) → **`istream::seekg`
overload** (:756) — and the other closure-relevant OWL files, the remaining
blockers bottom out at the SAME architecture:

- **iostream**: DIB / doc-view / the streamer families use `istream`/`ostream`,
  which **virtually inherit `ios`** — the iostream diamond. APPLICAT
  (`cannot 'new' TWindowView`) and FILEDOC (`cannot 'new' TFileInStream`) fail
  EXPLICITLY on the virtual-base MI shape.
- **frame MI**: TFrameWindow/TDecoratedFrame/TLayoutWindow/TTinyCaption families
  combine MI with virtual bases (DECFRAME/DECMDIFR/FLOATFRA "no member named
  <BaseClass>" — the base classes don't fully parse under the MI shape).

So railc — an OWL app built on TDialog/TFrameWindow/TLayout — **cannot link
without Stage-3 (data-bearing virtual bases)**, task #10.
