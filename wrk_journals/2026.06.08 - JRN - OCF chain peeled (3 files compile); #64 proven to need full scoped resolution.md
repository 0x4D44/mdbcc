## #64 (nested-class tag collision): DEFINITIVELY needs the full feature

Three attempts + a clean instrumented diagnostic established there is NO
shortcut (recorded in task #14):

- The flat `tags` map holds ONE binding per name, so `TBase::Streamer` and
  `TButton::Streamer` cannot coexist.
- Minting a fresh uniquely-tagged record fixes member SYMBOL keys
  (`Streamer$<id>::method`) and inline-body resolution (this_ty(id)).
- BUT overwriting `tags[orig]=fresh` desyncs the enclosing class parse
  (the attempt-2 regression: APPLICAT/WINDOW/GAUGE → window.h:409); and NOT
  overwriting breaks external `Outer::Inner` refs (they flatten to the
  innermost name via `tags`).
- Therefore attempt-3 MUST add scoped `Outer::Inner` RESOLUTION: an explicit
  class-nesting stack (cur_class is None during nested defs), scoped-key
  registration, and scoped lookup in record_specifier / qualified-type
  decl_specifiers / the expression `::` resolver / the base-clause.

Key diagnostic insight: with REUSE (no mint), APPLICAT compiles THROUGH to
codegen and DEFERS the streamer inline funcs (non-fatal) — the merge is only
FATAL where a streamer method is REACHABLE (BUTTON-style files). So #64
blocks the ~14 streamer files but does NOT block files that merely include
the streamable headers.
