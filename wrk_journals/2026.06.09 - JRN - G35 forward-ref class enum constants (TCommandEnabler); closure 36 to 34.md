# 2026.06.09 — G35: forward-referenced class-scoped enum constants (OWL TCommandEnabler); railc closure 36 → 34

A contained parser fix in the same family as the existing static-data-member
complete-class-context pre-scan.

## Symptom

`TCommandEnabler::GetHandled` / `SendsCommand` were unresolved — deferred (S4.2h)
in WINDOW.CPP with `no member named 'WasHandled'` / `'NonSender'`.

## Root cause

`TCommandEnabler` (WINDOW.H) declares its accessors BEFORE the enum that gives
their constants:

```cpp
class TCommandEnabler {
  bool GetHandled()  { return Handled & WasHandled; }     // line 117
  bool SendsCommand() const { return !(Handled & NonSender); }
  enum { WasHandled = 1, NonSender = 2 };                  // line 124 — LATER
};
```

C++ [class.mem]/7 gives a member-function body the COMPLETE class context, so a
later-declared enum constant is in scope. mdbcc parses inline bodies EAGERLY but
only records enum constants when the member loop reaches the `enum` — so
`WasHandled` was unknown, fell through to a `this->WasHandled` member access, and
`field_of` raised "no member named". The inline accessor was deferred + dropped.

## Fix

Added a class-body **enum-constant pre-scan** (parser.rs), mirroring the existing
static-data-member pre-scan: a non-consuming token walk over the class body that
registers each enumerator into `enum_consts` BEFORE the member loop parses the
inline bodies. Folds the simple enumerator forms (implicit, `= <int|char
literal>`, `= <prior enumerator>`); a complex initializer falls back to the
running value (the member-loop `enum_specifier` re-parse still records the exact
value for later references). `enum_consts` is already TU-global (enum_specifier
inserts unqualified), so this only changes WHEN a constant becomes visible — a
class whose enum precedes its methods is byte-identical.
