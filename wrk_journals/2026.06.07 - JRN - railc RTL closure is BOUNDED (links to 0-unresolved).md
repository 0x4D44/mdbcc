# 2026.06.07 — railc's RTL closure is BOUNDED + mdbcc-compilable (links to 0 unresolved)

Empirical de-risking of W2–W5. Drove the link-closure by hand: start from the 21
mdbcc railc objs (one unresolved external, `TStringRef::TStringRef(unsigned)`),
then mdbcc-compile RTL source clusters and re-link, watching the unresolved set.

## The closure walk (each step = re-link after adding a cluster)

**Key result: railc + a BOUNDED set of mdbcc-compiled RTL leaf clusters
(STRING, CSTRINGS, LOCALE, MISC, CONVERT, MEMORY) resolves EVERY railc/RTL
symbol** (hit 0-unresolved twice; the only failures were my own duplicate
compiles across ad-hoc /tmp dirs). No OWL/BIDS lib needed — all OWL the app
reaches is header-inline and already emitted into the railc objs.

## Why this matters

The GOAL budgets S5/S6 (self-host OWL + app) at ~9–18 months under the
"compile ALL of OWL/RTL/BIDS" framing. But railc's ACTUAL reachable closure is a
few dozen RTL leaf files (string/char/locale/heap), not the whole RTL, and zero
non-inline OWL. So a RUNNING all-mdbcc railc.exe is far closer than the worst
case — gated on a handful of concrete W5-linker tasks, not a full RTL/OWL port.

## Remaining blockers to a running railc.exe (the concrete W2/W5 task list)

1. **`.mdbcc_ctor.*` thunk dedup** — header-defined file-scope ctor-globals
   (e.g. `__xalloc`) emit a CRT static-init thunk per TU; multi-TU RTL links
   collide. (The `__xalloc` dup I hit was a self-inflicted double-compile, but a
   genuine vague-linkage-thunk dedup is needed for a clean multi-obj RTL link.)
2. **RTL compile gaps (W2)** — NOT in railc's closure but seen in the heap files:
   `ULONG` typedef unrecognized (GETMEM/HEAP), `_DestructorCount` undeclared
   (VNEW/VDELX vector new/delete), global `operator new`/`delete` on i386
   (DELARRAY/NEWARRAY/VDEL), array-new on i386 (REGEXP), `istream::operator>>`
   overload (STRINGIO). Each a focused mdbcc increment; only those that enter
   railc's closure are blockers.
3. **GUI startup / CRT init** — the entry that calls WinMain + any RTL init the
   string/locale/heap need before WinMain (Borland's c0w32 does this).
4. **`.res` linking** — wire RAILC.RES (icons/bitmaps/dialogs/stringtable) into
   the mdlink output (CLI rejects `.res` today; merge_rsrc_unit exists in-process).
