# JRN — coverage wiring (J-17 closure, S1e)

Date: 2026-05-26. Closes **J-17** (cargo llvm-cov wiring) from the May-22
plan §A and §S1.J-17, per the May-26 plan §6 testing-charter item 7
("Coverage drops are journal lines (J-17 wired during S1)").

## What this delivers

1. **`scripts/coverage.ps1`** + **`scripts/coverage.sh`** — thin wrappers
   around `cargo llvm-cov --workspace --release --summary-only`. Both
   scripts:
   - Verify `cargo-llvm-cov` is installed (print install instructions if
     missing — `cargo install cargo-llvm-cov`).
   - Run the summary sweep and parse the `TOTAL` row.
   - Append one row to `wrk_journals/coverage_history.tsv` (timestamp,
     git commit short hash, line coverage %, region coverage %).
   - Print the current coverage AND the delta vs the previous row
     (formatted as a ready-to-paste journal line).

2. **`wrk_journals/coverage_history.tsv`** — header + first row. Tab-
   separated, one row per coverage run. The TSV grows monotonically;
   coverage history can be diffed/grepped/plotted from this file alone.

## How to run

From the repo root:

```powershell
pwsh scripts/coverage.ps1
```

or

```bash
bash scripts/coverage.sh
```

The first run takes 3-5 minutes (full instrumented rebuild). Subsequent
runs reuse the LLVM coverage cache and complete in ~30 s when only test
code has changed.

## Tick journal usage

A normal tick journal entry should now include a one-line coverage
reference, captured from the script output:

```
Coverage delta: 86.94% -> 87.12% (+0.18 pp)
```

(or `Coverage baseline: X% (line) / Y% (region)` on the very first run).

A drop is a journal *event*, not a CI failure — the script never
non-zero-exits on a regression. Policy is "investigate drops > 1 pp;
explain in the same commit" per the May-22 plan's J-17 brief.

## Known coverage gaps

1. **`main.rs` (0%)** — the `bcc` CLI driver. End-to-end tests use
   `compile_to_pe()` in-process (the V8 §6 PATH-hazard mitigation),
   bypassing `main()`. Either accept the gap (driver is thin and
   self-evident) or add a per-binary smoke test that shells out to
   `target/release/bcc.exe`. **Disposition**: defer to S1c (the
   linker work touches the driver anyway when `-c` is added; cover
   the driver in lockstep).

2. **`rc/mod.rs` (57.14%)** — only 7 lines total; the small denominator
   inflates the per-line impact of every uncovered branch. The
   uncovered lines are RC-error formatting paths. **Disposition**:
   not actionable until RC features expand.

3. **`rc/parser.rs` (65.34%)** — the RC parser has many directives
   (`MENU`, `DIALOG`, `STRINGTABLE`, etc.) but the test corpus
   exercises only the subset OWL samples use. As S5/S6 introduce
   real OWL `.rc` files, this number should rise organically.
   **Disposition**: opportunistic; not a separate work item.

4. **`pp.rs` (79.93%)** — preprocessor. Uncovered paths are mostly
   error-recovery branches and rarer pragmas (`#pragma warn`,
   `#pragma argsused`). S3 (real Borland headers) will exercise
   many of these. **Disposition**: defer to S3.

5. **`compile.rs` (80.95%)** — small module (42 lines); the gap is
   `CompileError` Display variants for error kinds no test currently
   triggers. Low value to chase.

## Caveat: emission-side coverage is misleading

`pe.rs` reports 92.81% line coverage, but most of those exercised
lines are static bookkeeping for sections that are emitted whether
or not the program semantically needs them (`.pdata`, `.xdata`,
`.idata`). A bug in *which* bytes get written into those sections is
fully bytewise-locked by `tests/o1_byte_identity.rs`, not by
llvm-cov. Coverage and byte-identity are **complementary** oracles;
neither alone is sufficient. The May-26 plan's S1 testing charter
keeps both.
