## printf format specifiers (2026-05-17) — DONE (with a flagged defect)

Next move chosen by Arthur. Implemented in `src/codegen.rs`:

- Compile-time `FmtSpec` parser + `parse_fmt`; flags/width/precision are
  constants from the literal so emission is **specialised per call site**.
- Supported: width (≤256), `-` (left), `0` (zero, sign-aware), string
  precision (max chars), length modifiers `h/hh/l/ll/L/j/z/t`
  parsed-and-ignored (long==int==4 on every target here).
- **Deferred = explicit `CodegenError`, never silently wrong:** `+`,
  ` `, `#`, integer precision, `*`. (The oracle would catch a silent
  miss anyway; an explicit error is honest and cheap.)
- `fmt_int` refactored into `int_token` (sign+digits) reused by a thin
  fast path (**byte-identical** — O1's 88 e2e unchanged) and the new
  `fmt_int_spec`/`fmt_str_spec`/`fmt_char_spec`. Padding via a 256-byte
  interned fill blob + ordered `WriteFile` (no fragile prepend asm).
  `ntemps` 8→16 (removes tmp-accounting risk; +negligible frame).
- Validated **three ways**: O1 hand-expected (`tests/printf_format.rs`,
  5 tests, C-standard expectations) + O2 MSVC + O3 Borland bcc32 over
  `tests/corpus/portable/printf_*.c`. 166 tests green, clippy clean.

### ⚠ DEFECT FOUND (pre-existing, NOT printf — needs coordination)

The in-house PE writer (`src/pe.rs`) **hard-codes section RVAs at fixed
0x1000 spacing** (`TEXT_RVA=0x1000, IDATA_RVA=0x2000, …`) and
`SizeOfImage`, assuming **every section ≤ 4 KB**. When `.text` exceeds
0x1000 its virtual range overlaps `.idata` ⇒ `STATUS_INVALID_IMAGE_FORMAT`
("not a valid application"). Diagnosed by diffing PE headers of a working
(`.text` 0x518) vs failing (`.text` 0x10DD) exe.

- Impact: **any real program with >4 KB of code cannot be built today.**
  This is a hard blocker for the project goal ("rebuild old apps") and is
  the single most important next fix.
- Why not fixed now: `src/pe.rs` has **another engineer's uncommitted
  changes**; the correct fix is a dynamic-section-layout refactor
  (RVAs = `align_up(prev_end)`, threaded through idata/rdata/data/text
  reloc math + `SizeOfImage`). CLAUDE.md forbids sweeping changes to
  others' in-flight files / says ask first. Decision: do **not** sweep
  pe.rs autonomously; flag loudly and let Arthur/owner coordinate.
- Unblock applied: split the two oversized printf corpus files
  (`printf_width{,2}.c`, `printf_zero{,2}.c`) so `.text` < 4 KB —
  legitimate test curation (same spirit as the bcc32 `// oracle: skip`);
  printf-format is still validated three-way. printf correctness is
  **independent of** this PE defect (proven by O1 + isolated runs).
