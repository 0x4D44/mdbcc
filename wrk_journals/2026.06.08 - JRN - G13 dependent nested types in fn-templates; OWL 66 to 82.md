# 2026.06.08 — G13: dependent nested types in function templates; OWL 66→82 / 119

The post-#64 streamer follow-on ("method call on non-class") is **landed**,
RUN-verified, regression-free. OWL source compilation: **66→82 / 119** (+16).

## The construct

CLASSLIB's `OBJSTRM.H` streamer machinery:

```cpp
template <class Base> void WriteBaseObject( Base *base, opstream& out ) {
    Base::Streamer strmr(base);      // DEPENDENT nested type, no `typename`
    strmr.Write( out );              // (bcc32 4.52 is pre-standard)
}
```

Every streamable OWL class (`BUTTON/CHECKBOX/EDIT/GROUPBOX/CONTROL/LISTBOX/
RADIOBUT/SCROLLBA/STATIC/FILTVAL/…`) instantiates these via `DECLARE_STREAMER`.

## Root cause (two distinct gaps, both at the dependent boundary)

1. **The parser dropped the qualifier.** `qualify_nested` turned `Base::Streamer`
   into `TemplateParam("Streamer")` (last component only), so monomorphisation
   could not substitute `Base` — `subst_type({Base→TControl}, "Streamer")`
   missed the key and left it dependent → codegen "method call on non-class".
2. **The dependent ctor call was never emitted.** The auto-ctor-invoke for a
   `Type v(args)` direct-init is synthesised at PARSE time, gated on the type
   being a concrete `Type::Record`. For a dependent type the `ctor_args` were
   captured and then DROPPED — so even after the type resolves, no ctor runs
   and the local is uninitialised (the minimal repro returned 0, not 42).

## The landed fix

- **parser.rs::qualify_nested** — KEEP the qualifier: `Base::Streamer` →
  `TemplateParam("Base::Streamer")` (chains for `A::B::C`).
- **parser.rs local-decl** — for a dependent direct-init `Base::Inner n(args)`,
  emit a sentinel ctor `MethodCall` named `$depctor$Base::Inner` (instead of
  silently dropping `ctor_args`).
- **ast.rs** — `TranslationUnit.nested_scopes`: the `::` subset of the parser's
  tag table (the scoped `Outer::Inner -> id` keys #64 registers for EVERY nested
  class). Exported so monomorphisation can resolve the concrete nested record.
- **codegen/template.rs** — a `Tcx { records, nested }` threaded through
  `rewrite_*`/`instantiate`/`subst_*`. `subst_type` resolves a dependent nested
  `Base::Inner`: once `Base` is bound to `Record{id}`, look up
  `<records[id].tag>::Inner` in `nested` → the concrete nested record.
  `subst_expr` resolves the `$depctor$…` sentinel to that record's ctor tag (and
  now also substitutes `MethodCall` args, previously skipped).

All presence-gated: a TU with no nested classes has empty `nested_scopes`; a
template body with no dependent nested type never hits the new arms ⇒ the 88
byte-identity baselines + the Lock/streamer reuse paths are untouched.
