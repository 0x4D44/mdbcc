## 1. `_EAX` register pseudo-variable (#62) — b88c05e

OWL's window-proc thunk loads EAX with the object pointer; StdWndProc recovers
`this` via `((TWindow*)_EAX)->ReceiveMessage(...)` (WINDOW.CPP:900). mdbcc now:
spills entry-EAX in the prologue BEFORE the param-spill clobbers it (slot
reserved ONLY when the body names `_EAX` — `body_uses_eax` walker), reads the
slot for `_EAX` (gen_expr arm ahead of the generic Var arm; no lvalue), types it
as a 4-byte unsigned word. RUN: `f()` leaves 42 in EAX; `g(){return _EAX;}` →
42, matching bcc32 4.52. Unblocks the OWL window-proc dispatch (W4).

## 2. i386 array-new + class-array `delete[]` — 8ceb8fe

The 32-bit parallel of the Win64 machinery, replacing the clean-error guards:

- `gen_new_array_i386`: cdecl HeapAlloc, Gpr32, **4-byte count cookie at
  `block+0`, payload `block+4`** (the Borland Win32 convention). Cookie-less raw
  alloc for no-ctor/no-dtor elements. Negative-count + mul-overflow ud2 traps.
  Ctor loop in index order, cleanup-DISABLED (i386 SEH3 is separate; mid-array
  throw leaks — same documented J-15 limitation as the x64 cleanup-disabled path).
- `gen_delete` i386 cookie path: count from `[p-4]`, reverse dtor loop
  (virtual dtor via vtable slot, else direct cdecl), HeapFree(`p-4`).

Both sites are mdbcc-built in the final exe, so the cookie layout is an internal
contract. RUN vs bcc32: ctor+dtor cookie 27, POD cookie-less 26, virtual-dtor
10. Unblocks REGEXP-style `new T[n]` and the BIDS/RTL container source.

## 3. `_DestructorCount` implicit extern — ecf9e18
