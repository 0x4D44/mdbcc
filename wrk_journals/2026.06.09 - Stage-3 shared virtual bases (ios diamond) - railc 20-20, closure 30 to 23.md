## Model (behavioural parity, not byte-identity — but layout IS byte-identical)
All TUs are mdbcc-compiled, so they only need to AGREE on layout. I match
bcc32's ABI anyway (a great oracle): `sizeof(fstream)=152`, shared `ios` at the
tail (+88), each virtually-deriving subobject carries a **vbptr** (a 4-byte
field `$vbptr` right after the vptr). Borland stores a vbtable offset; I store a
**direct pointer** to the shared vbase — same width/offsets, simpler, invisible
(no Borland objects link against mdbcc's).

- **Layout** (parser): a class that DIRECTLY virtually-derives a shared vbase
  gets a `$vbptr` Field (so the existing flatten/re-lay machinery preserves it
  when embedded); vbase fields are NOT flattened (kept in the vbase record,
  reached via vbptr); each distinct shared vbase is appended ONCE at the object
  tail. `Record` gains `vbases: Vec<VBase{id,offset,vbptr_offset}>` +
  `vbptr_offsets: Vec<(vbase_id, field_off)>`.
- **Construction** (site-driven, model B — LOCAL objects only): the `Decl` site
  sets every vbptr to `&obj + vbase.offset`, then default-constructs each shared
  vbase, then runs the most-derived ctor. The RTL stream ctors never init `ios`
  with args (`fstreambase(){ ios::init(&buf); }`), so no most-derived ctor flag
  is needed. `new`/placement/array of a vbase class still reject (out of scope).
- **Member access + `Derived*`→vbase upcast** (codegen): MANDATORY vbptr
  indirection (`vbase_field_of` + `convert`'s vbase branch + `load_vbptr_into_rax`)
  — a base-typed `this` (inside `istream::getline`) cannot use a static offset.

## The scoping trap (and the fix that matters)
First cut redirected ALL data-bearing virtual bases to Stage-3. That regressed
RAILC/TOOLBAR/… (railc 19→11, OWL 90→82): **OWL's `TWindow` is ALSO a
data-bearing virtual base** (`TFrameWindow`/`TDialog : virtual TWindow`), used
pervasively, and it needs ARG'd vbase construction (model A) my model-B can't do.
The OLD model worked for `TWindow` by laying a SINGLE-path virtual base as a
plain base-at-0 and poisoning only the true joins.

Fix: redirect to Stage-3 ONLY a **shared** vbase — reachable via 2+ distinct
base paths from some class (a real diamond join). A one-shot token pre-scan
(`scan_shared_vbases`) computes the shared-vbase NAMES (`ios`, `pstream`); the
redirect is gated on membership + i386 + data-bearing. `TWindow` (never joined
in railc — verified) stays plain-at-0, unchanged. Stage-3 is **i386-only**
(`ptr_bytes==4`); Win64 keeps the poison (byte-identical).
