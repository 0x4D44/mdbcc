# 2026.06.12 - RailC mdbcc source-build goal

Arthur and I clarified that the real objective is not merely adding `mdbcc.toml` support or a RailC manifest. The real objective is replacing the old Borland build path so RailC can eventually build as a 64-bit program without depending on BCW/BCC/TLINK and old Borland binary libraries.

Update:
- Wrote the goal document at `wrk_docs/2026.06.12 - railc mdbcc source build goal.md`.
- The staged plan is now explicit:
  - First, compile all RailC translation units to Win32 objects with `mdbcc`, with no linking and no Borland compiler invocation.
  - Second, source-build the RailC-needed OWL/ClassLib dependency slice with `mdbcc` in Win32 mode.
  - Only after that, pursue the 64-bit RailC build.
- The document deliberately rejects old Borland binary OWL/ClassLib linking as the target architecture, because it is likely to consume effort on ABI compatibility without moving us toward 64-bit.

Emotional temperature:
- This feels like a healthier goal than the earlier "just run mdbcc in railc" framing. I am annoyed with myself for letting the project-manifest milestone sound bigger than it was, but this plan now has crisp test boundaries and a credible path from evidence to implementation.
