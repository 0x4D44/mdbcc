# 2026.06.08 — EXCEPT/TXOwl blocker = the i386 non-trivial copy-ctor CALL convention; a G29 attempt was reverted (RUN-verification caught a silent miscompile)

Chased the EXCEPT.CPP → TXOwl blocker (`return new TXOwl(*this);` in
TXOwl::Clone → "no matching overload for TXOwl::TXOwl"). Pinpointed the real
cause, attempted a fix, and **reverted it** when RUN-verification exposed a
silent miscompile. No closure change this arc; the value is the precise
root-cause + the discipline lesson.

## Root cause (two layers)

1. **Overload-set gap (the surface error).** `new T(t)` where `T` has user
   ctors but no explicit copy ctor: `construct_in_place` (gen_new) resolves the
   ctor via `funcs`/`overloads`, which do NOT contain the implicit copy ctor →
   "no matching overload". Decl-init (`T a = b;`) avoids this by calling
   `copy_ctor_symbol` directly.
2. **The DEEPER blocker — i386 non-trivial copy-ctor CALL is broken
   (pre-existing).** Even Decl-init non-trivial copy fails on i386:
   `T b = a;` with a non-trivially-copyable member errors
   `no encoder row for Mov [Gpr64,Gpr64]`. The hand-rolled copy-ctor call
   (codegen.rs ~4424) emits **Win64** REX.W reg64 `mov`/`lea` and a register
   (rcx=this, rdx=src) convention — invalid on i386 (no reg64 encoder row; i386
   uses cdecl/stack, not rcx/rdx). So mdbcc has NO working i386 non-trivial
   record-copy path today. (The trivial/memcpy path works on both.)

## The reverted G29 attempt

Added a `construct_in_place` copy-construction fallback: `arg_is_self` +
`copy_ctor_symbol` Some → call the copy ctor; None (trivially-copyable) →
member-wise memcpy. Result:
- **Trivial** case worked (RUN == 7) and EXCEPT.CPP *compiled* (OWL sweep would
  be 86).
- **Non-trivial** case (the railc-relevant one — TXOwl has a `string` via xmsg)
  **segfaulted at runtime** (RUN-verified): `emit_call(copy_sym, …)` with a raw
  synth-ctor symbol produced a mis-conventioned call on i386, AND the synth copy
  ctor body itself rides the same broken i386 path.

Committing it would have shipped a crashing `TXOwl::Clone` (a silent miscompile
that "compiles clean"). Per the working agreement (don't commit miscompiles;
don't stack fixes when one fails) I **reverted** to the clean G28 state. The
ptys_override / lead details are captured in task #24.

## Lesson (reinforced)

RUN-verification, not compile-success, is the oracle for codegen changes. A
plausible "it compiles now" (EXCEPT.o produced) hid a runtime segfault. The
i386 non-trivial copy-ctor call is a genuine convention feature, not a
width-tweak — it must be done deliberately (route BOTH Decl-init and new-expr
copy through one width-aware, cdecl-correct i386 mechanism), with RUN tests for
trivial + non-trivial + chained cases, not bolted on at the tail of a session.
