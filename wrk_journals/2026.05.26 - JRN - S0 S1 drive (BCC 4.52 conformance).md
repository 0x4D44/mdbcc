### Decisions surfaced (Arthur input)

**Decision-1 (OMF discovery; from #4 finding)**: BCC32 4.52 emits
OMF, not COFF. The May-26 plan's O14 oracle was "our COFF .obj
links through TLINK32 AND bcc32's .obj links through mdlink." The
first half is impossible: TLINK32 1.50 only accepts OMF. Three
options:
- **A** — add **OMF read** to mdlink (we keep COFF-only on the
  write side; mdlink ingests bcc32 OMF as oracle input). Enables
  "compile-with-bcc32, link-with-mdlink → behaviour match."
  Stronger oracle than the original O14.
- **B** — use MS link.exe / lld-link as the COFF format witness
  (they accept COFF; if our .obj links through MS link and runs,
  format is conformant). Different oracle, no Borland round-trip.
- **C** — write a coff2omf converter (more code; uses TLINK32).

Recommendation: **A + B in parallel**. OMF read in mdlink (S1c
scope creep, +1-2 weeks) gives bcc32-OBJ-in oracle; MS link
acceptance (free, just spawn link.exe) gives COFF-format witness.
**Defer A's implementation to S1c start; capture the decision
now.** Arthur asked.
