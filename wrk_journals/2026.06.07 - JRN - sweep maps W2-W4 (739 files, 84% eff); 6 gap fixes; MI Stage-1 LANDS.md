## G1 Stage-1: plain multiple inheritance (77cbc8b)

`Record.extra_bases: Vec<BaseSpec>` over the flat class model (primary
`base`/`base_offset` untouched ⇒ byte-identity); extra subobjects appended at
`align_up(size, b.align)` with the base's internal layout preserved; ctor
mem-init naming any direct base; UNNAMED extra bases implicitly constructed
(decl order) and destroyed (reverse) via the end-of-parse sweep over every
ctor/dtor — the silent-never-constructed-2nd-base landmine is dead; codegen
needed only TWO funnel extensions (`base_offset_to` DFS, `method_target`
deque walk) for all upcasts/this-adjusts. 5 new RUN tests vs bcc32 (POD
access+upcast, both-base init, implicit construction, extra-base method,
dtor order) — all 42.

**Stage gating (the hard-won design):** definition-time errors broke every TU
that merely includes IOSTREAM.H (class iostream is MI) — caught compiling
FSBCTR1. Final design: over-Stage-1 extras (virtual heritage → Stage-3;
polymorphic extra → Stage-2) are dropped as before and the class POISONED
(`mi_dropped`); the four construction sites reject it cleanly. Includers stay
green; constructors get a precise diagnosis.

**Honesty corrections:**

  silently built with NO ostream subobject. W1's "21/21" was partly illusory;
  the true state is 20/21 + LAYOUT.CPP correctly deferred on **Stage-3
  virtual bases** (which cout/filebuf correctness needs anyway).
