## 2. mdbcc-built C shim for the asm-only primitives (closure 46 → 43)

`memmove`, `strchr`, `strncmp` ship in the Borland RTL ONLY as 32-bit assembly
(`RTL/SOURCE/CSTRINGS/COMMON32/*.ASM`). mdbcc cannot assemble. To keep "every
byte mdbcc-built", added **`wrk_rtlshim/rtlshim.c`** — standard-conforming C
reimplementations, behaviourally identical, C-linkage (bare symbols match the
RTL/OWL callers). NOT an edit of the Borland tree — a separate mdbcc-compiled
self-host shim, added to `mdcw32.lib`. RUN-verified (mdlink-linked standalone
exe = 16: forward-overlap memmove, strchr index, both strncmp branches). Suite
regression test `i386_rtl_shim_primitives_logic` (differential vs bcc32, renamed
to avoid clashing with bcc32's own RTL).

## Decision recorded (asm-RTL boundary)

The asm CRT primitives can't satisfy BOTH "compile from Borland source" AND
"mdbcc-built" — mdbcc can't assemble. Resolution taken for the TRIVIAL,
unambiguous computational ones (memmove/strchr/strncmp): reimplement in C
(mdbcc-built ✓, behaviour-identical, trivially correct, easily reverted). The
HARDER asm boundary is deliberately left for a decision:
- I/O syscall wrappers (`open`/`read`/`write`/`lseek`/`close`) — reimplement
  over Win32 (CreateFileA/ReadFile/WriteFile/SetFilePointer/CloseHandle) OR
  accept assembled objects;
- float formatting (`__realcvt`/`__nextreal`) — complex; exact golden parity
  matters for the GUI float display, so reimplementation is risky — likely wants
  the assembled golden object.
- `min` (string-class size compare), `_lrand`, `_lock_handle`/`_unlock_handle`,
  `readVersion`, `filebuf::seekoff`, `xerror::MakeString` — assess in the next
  RTL pass (some are compilable C TUs, some asm).
