# FINAL ship-readiness review — PE-writer dynamic section layout

Branch `feat/test-oracles-v1`, HEAD `2010507`. Independent adversarial
review judged from first principles (plan ignored). Read-only; no git
mutations. Original defect: `src/pe.rs` hard-coded section RVAs at fixed
4 KB spacing → any section > 0x1000 produced an unloadable PE
(STATUS_INVALID_IMAGE_FORMAT). Fix: dynamic linear layout
(`align_up(prev_rva + prev_vsize, SECT_ALIGN)`), `SizeOfImage` from real
layout, an always-on pre-pass reconciliation guard.

## Headline-guarantee verification (independent)

### 1. It actually works — VERIFIED (Y)
- Existing `tests/pe_layout.rs` re-run GREEN. It is a genuine load+exact
  oracle: ~800 fns (>8 KB `.text`) + `char *tag` `.data` abs-pointer +
  printf import + `.rdata` format string emitted AFTER the big code;
  writes a real `.exe`, launches via `Command::new`, asserts exact
  stdout (`T:<sum>\n`) and exit. An unloadable PE hard-fails at
  `.expect("launch")`; a stale `.data`/`.rdata` RVA → wrong `%s` deref
  → exact-bytes assert fails. Real teeth.
- I built an INDEPENDENT 4-case probe through `mdbcc::compile_to_pe`
  (temp `.exe`, launched, exact stdout+exit, then deleted). All passed:
  - **A** big `.text` (700 fns, >8 KB) AND big `.data` (4000-int array,
    16 KB) SIMULTANEOUSLY + abs `char*` + array written/summed →
    `exe=137728B exit=84 out="AB:57428\n"` exact. (NOT covered by the
    existing suite — bigcode.c/pe_layout.rs have effectively empty
    `.data`.) This is the strongest evidence.
  - **B** bare `main`, zero helpers/imports/strings/globals →
    `exit=127`, empty-section guards exercised.
  - **C** a SINGLE function whose own body > 4 KB + printf/string after
    → `out="C=3594\n"` exact (single oversized fn, not many small).
  - **D** huge `.data` (32 KB) + tiny `.text` + `char*`+`%s` →
    `out="D:16000\n"` exact (`.data` RVA pushed far out, `.text` at
    0x1000).

### 2. No regression — VERIFIED (Y)
Direct byte-level check via probe: a small program *with* a string
literal and printf import still yields `.text` va=0x1000, `.idata`
0x2000, `.rdata` 0x3000, `.data` 0x4000, `SizeOfImage`=0x5000; trivial
`return 42` identical. Because every byte-emitting builder
(`build_idata/rdata/data/text`) receives exactly the RVA values the old
hard-coded constants supplied whenever each section fits in 0x1000, the
output is byte-identical for fitting programs. 88 end_to_end + 5
printf_format + corpus differential staying green is the broad net.
Nothing in the diff alters bytes for fitting programs (RVAs reproduced,
`SizeOfImage` reproduced, `i64→i32` reloc math unchanged for in-range
displacements).

### 3. Determinism — VERIFIED (Y)
Only two HashMaps in `pe.rs` (`iat_slot`, `offsets`); both are populated
by iterating ordered sources (`IMPORTS` array, `module.funcs` Vec) and
consumed by keyed lookup only. NO HashMap-entry iteration feeds bytes,
sizes, or RVAs. The pre-pass sum iterates `module.funcs` in order. PE is
a deterministic function of `Module`; differential determinism guard
green corroborates.

### 4. Release safety — VERIFIED (Y)
`src/pe.rs:371-377` is a plain `if text.len() as u32 != text_vsize {
return Err(CodegenError(...)) }` on the unconditional `write_pe` path,
executed before any size/RVA reaches the headers. NOT a `debug_assert!`;
always-on in release. Remaining `debug_assert_eq!`s guard only internal
invariants (STUB_LEN, hint/name offset, PE_OFF) that do not affect
layout correctness.

### 5. clippy + counts — VERIFIED (Y)
`cargo clippy --all-targets -- -D warnings` clean (exit 0).
`cargo test --lib` = 59 passed / 0 failed (matches "lib 59"; 58→59 from
the S3 boundary test). `pe_layout` re-run = 1 passed. end_to_end 88 /
differential 15 / printf_format 5 per journal; counts internally
consistent and not re-run (slow sandbox-off arm already green, per
instruction).

| H2 | Single function body > 4 KB | Probe Case C PASS → **sound-by-construction** (`text_vsize = STUB_LEN + Σ code.len()`; per-fn size irrelevant to layout). |

| H4 | `i64→i32` RIP `disp32` truncation at large image | **Sound for all realistic inputs**: wrap needs >2 GB between a `.text` ref site and its `.idata`/`.rdata`/`.data` target. 137 KB probe well within range. Identical behaviour in old code → not a regression. Not a ship-blocker. |
| H5 | `u32` overflow in `align_up`/pre-pass sum | Needs >4 GB of code; would debug-panic, not silently emit a bad PE. Not realistic; not a regression. |
| H6 | IMPORTS 3→6 heap change × layout fix | **Sound**: `build_idata` is fully RVA-parameterised; `.idata` vsize grows by a fixed delta and the linear pass recomputes every downstream RVA from actual sizes. Probe A/C/D all import printf and pass exact. No bad interaction. |
| H7 | file-offset vs RVA skew at large sizes | **Sound**: file offsets use `align_up(_, FILE_ALIGN=0x200)` accumulation, RVAs use `align_up(_, SECT_ALIGN=0x1000)` independently; both monotonic from real sizes, never cross-derived. | H8 | `SizeOfImage` off-by-a-page | **Sound**: `align_up(data_rva + data_vsize, SECT_ALIGN)`; S3 unit test pins the exact-multiple edge (`div_ceil`, no spurious page) and was shown to have teeth (buggy `align_up` → test fails). Probe images all load (loader rejects a short `SizeOfImage`). |
| H9 | `rdata.push(0)` guard shifting a baked abs `ptr_str` address | **Sound-by-construction**: `build_data` bakes `IMAGE_BASE + rdata_rva + len` at append time; the empty guard fires only when `rdata` is truly empty (⇒ no `ptr_str` existed), so it never shifts a recorded string. Probe A/D (`char*` + populated `.data`) print exact bytes — would garble if skewed. |
