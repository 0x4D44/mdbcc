## Summary

The fix replaces four hard-coded section RVAs (`TEXT/IDATA/RDATA/DATA_RVA` at fixed 4 KB spacing) with a dynamic linear layout in `write_pe`: a cheap pre-pass computes `text_vsize`, then each section base RVA = `align_up(prev_rva + prev_vsize, SECT_ALIGN)`, and `SizeOfImage` is derived from the real layout. `build_idata/build_rdata/build_data/build_text` are re-signed to take/return section-relative offsets that the caller rebases. Two oracles are added.

This is a correct, minimal, well-reasoned fix. The RVA recurrence is sound for arbitrary section sizes, regression safety for the historical fixed layout is provably exact, determinism is preserved, and the in-process test genuinely hard-fails on a non-loading PE. Findings are all NIT/PRAISE — nothing blocks.

## Findings

### PRAISE

- **PRAISE `src/pe.rs:336-366`** — The ordering of the layout pass is exactly right and the trickiest part of the change. `idata_rva` is pinned *before* `build_idata` (which bakes RVAs into descriptor/ILT/IAT thunks), `rdata_rva` is pinned *before* `build_data` (which appends pointed-to strings to `.rdata` and writes their absolute address `IMAGE_BASE + rdata_rva + offset`), and `data_rva` is computed *after* `build_data` + the empty-section guards have mutated `rdata.len()`. Every internal RVA (`.idata` descriptor OriginalFirstThunk/Name/FirstThunk, ILT/IAT thunks, `.rdata` string RIP targets, `.data` pointer absolute value) is sourced from the pinned-before-use base. There is no lingering fixed-offset assumption. The data-dependency hazards were correctly identified and sequenced.

- **PRAISE `src/pe.rs:336-338, 366`** — The `text_vsize` pre-pass (`STUB_LEN + Σ f.code.len()`) is an exact mirror of the `build_text` cursor (`cursor = STUB_LEN`, `cursor += f.code.len()` per func; stub asserted to be exactly `STUB_LEN`; bodies appended verbatim; relocations patched in place without resizing). The `debug_assert_eq!(text.len() as u32, text_vsize)` at line 366 is therefore a true tautology in the current code and a genuine drift-guard against a future divergent edit — exactly the right tool, placed correctly, with an accurate comment.

- **PRAISE — regression safety is provably byte-exact.** For any program where every section ≤ 0x1000: `text_rva = align_up(0x400,0x1000) = 0x1000`; `idata_rva = align_up(0x1000+text_vsize,0x1000) = 0x2000` (text_vsize in 1..=0x1000; min STUB_LEN=0x12 so never 0); `rdata_rva = 0x3000`; `data_rva = align_up(0x3000+rdata.len(),0x1000) = 0x4000`; `size_of_image = align_up(0x4000+data_vsize,0x1000)` — identical to the old `align_up(DATA_RVA + data_vsize, SECT_ALIGN)`. All file offsets / `SizeOfRawData` / `FILE_ALIGN` / headers are untouched and size-independent. Existing-program output is byte-for-byte unchanged.

- **PRAISE — determinism preserved.** No HashMap/HashSet *iteration* enters the sizing or emission path. Every loop in the changed code iterates `IMPORTS` (fixed array), `module.funcs` (`Vec`, source order), or the `str_offs`/`data_offs` `Vec`s. The two `HashMap`s (`iat_slot`, `offsets`) are keyed-lookup / insert only — never iterated. The `mdbcc_determinism` guard remains satisfied.

- **PRAISE — edge cases handled.** `align_up` is `div_ceil`-based, so a section whose size is an exact multiple of `SECT_ALIGN` advances the next base by exactly that many pages with no spurious extra page. The empty-`.rdata`/`.data` `push(0)` guards at `src/pe.rs:349-354` run *before* `data_rva` is computed at line 357 and before `data_vsize` is taken at line 369, so a degenerate section still gets a valid 1-byte image and a correctly-spaced RVA. Large `.data` after large `.text` is handled by the same uniform recurrence.

- **PRAISE `tests/pe_layout.rs:33-45`** — The test genuinely proves loadability: `Command::new(&tmp.0).output().expect("launch")` — a `STATUS_INVALID_IMAGE_FORMAT` (the pre-fix defect) makes `CreateProcess` fail, `.output()` returns `Err`, and `.expect("launch")` panics → the test is RED, not silently green. Output correctness is then asserted exactly: `assert_eq!(stdout, format!("sum={sum}\n"))` and `assert_eq!(exit, expected_exit)` with the expected sum computed independently in Rust via `fval` (`(i*7+3)%97`, matching the emitted C `(i*7+3)%97`). A wrong string/global RVA that loaded-then-segfaulted would change stdout/exit and fail the assertions. This is a real oracle, mirroring the `tests/printf_format.rs` O1 pattern correctly. `.text` with `NFUNC=800` non-trivial bodies comfortably exceeds the old 4 KB ceiling, and the `printf` import + `"sum=%d\n"` literal are emitted *after* the bloated `.text`, exercising `.idata` and `.rdata` rebasing past the large section — the precise failure mode.

- **PRAISE `tests/corpus/portable/bigcode.c`** — Strict C89 (declarations precede statements in every function), deterministic, no uninitialised reads (`a` always assigned before use; `s` initialised to 0). All arithmetic is `int` bounded by `% 1000` then `+ N` (N ≤ 63), max ≈ 1062 — no overflow, no pointer arithmetic, no `int`-size or pointer-size dependent output, so O3 `bcc32` 32-bit behaviour matches mdbcc 64-bit and the O2 `cl` differential is exact. One `%d` printf is deterministic. Correctly slots into the existing `differential.rs` corpus harness (no skip directive needed).

## Verification performed (reasoning, no source modified)

1. RVA recurrence checked symbolically for arbitrary sizes: `VirtualAddress_n = align_up(VA_{n-1} + vsize_{n-1}, SECT_ALIGN)`, `SizeOfImage = align_up(data_rva + data_vsize, SECT_ALIGN)`. All four section-header `VirtualAddress` fields, `AddressOfEntryPoint`, `BaseOfCode`, `SizeOfCode` (`text_raw`), `SizeOfInitializedData`, Import dir [1] and IAT dir [12] all trace to the computed layout (`src/pe.rs:399-451`).
2. `.idata` internals: `build_idata(idata_rva)` derives every descriptor/ILT/IAT/hint-name/dll RVA via the `rva = |off| idata_rva + off` closure (`src/pe.rs:116-159`) — no fixed base remains.
3. `.rdata` string RIP targets: `str_offs` rebased by `+ rdata_rva` (`src/pe.rs:359-362`), consumed as `str_rvas[fi][idx]` in the RIP fixup (`src/pe.rs:276, 284-286`).
4. `.data` pointer absolute value: `IMAGE_BASE + (rdata_rva + rdata.len())` computed after `rdata_rva` is pinned (`src/pe.rs:196-198`) — correct.
5. Regression: small-program math reduces exactly to `0x1000/0x2000/0x3000/0x4000` and the old `SizeOfImage` formula (shown above).
6. Determinism: grep-confirmed no HashMap/HashSet iteration in sizing/emission; all iteration is over arrays/Vecs in source order.
7. Old constants fully removed: no residual `TEXT_RVA/IDATA_RVA/RDATA_RVA/DATA_RVA` or fixed `0x2000/0x3000/0x4000` RVA literals in the layout path (only doc prose and the unrelated `0x4000_0040` characteristics flag).
8. File offsets / `SizeOfRawData` / `FILE_ALIGN` / `HEADERS_SIZE` / DOS+PE headers confirmed size-independent and untouched by the diff.
