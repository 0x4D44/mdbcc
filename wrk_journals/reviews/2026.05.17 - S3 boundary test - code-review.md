## Summary

Adds one deterministic unit test that synthesizes a `Module` with a single
`main` whose `.text` virtual size is driven to *exactly* `0x1000` then exactly
`0x2000` (exact `SECT_ALIGN` multiples — the classic `align_up` off-by-one
edge), then parses the produced PE bytes and asserts: (a) the boundary was
actually hit, (b) `.idata` sits exactly at `text_rva + text_vsize` with no
spurious extra page, (c) every section base `== align_up(prev_end,
SECT_ALIGN)` with no `[va,va+vsize)` overlap, (d) `SizeOfImage` is the aligned
end of the last section.

## Overall Assessment

Looks good. The test locks the intended invariant, is deterministic, is
appropriately scoped, matches existing pe.rs test style, is clippy-clean by
inspection, and is the smallest change that covers the exact-boundary case
without duplicating the already-covered big-data path. Approve as-is.

## Strengths (PRAISE)

- **PRAISE — pe.rs:570–588 (`pe_with_text_body`).** Constructing the `Module`
  directly (bypassing lexer/parser/codegen) is exactly right: it makes
  `text_vsize` a closed-form `STUB_LEN + body_len`, so an *exact* multiple is
  hit deterministically with zero dependence on codegen byte counts. NOP
  filler with empty `calls/riprefs/strings` guarantees the
  `text.len() != text_vsize` pre-pass guard (pe.rs:371) cannot fire (no
  relocation can change emitted length), so the synthetic vsize is honoured
  end-to-end. Doc comment correctly states the rationale.

- **PRAISE — pe.rs:625–634.** The two "did we actually hit the edge"
  assertions (`text_vsize == want_text_vsize` and `text_vsize % SECT_ALIGN
  == 0`) prevent silent degradation into a non-boundary test if `STUB_LEN`
  or the layout ever changes. The `% SECT_ALIGN` check uses `%`, **not**
  `align_up`, so it anchors the boundary independently of the function under
  test — a deliberately good choice.

- **PRAISE — pe.rs:638–644.** `idata_rva == text_rva + text_vsize` is the
  load-bearing oracle and has **no `align_up` on the RHS**. For a `text_vsize`
  that is an exact multiple, this is correct *by definition of alignment*, so
  it catches an over-align off-by-one, an under-align off-by-one, and a
  truncating `align_up` equally — a clean, self-contained witness.

- **PRAISE — both `want_text_vsize` values (0x1000 and 0x2000).** Testing two
  distinct exact multiples rules out a coincidental pass that only holds for
  the first page.

## Teeth — does it genuinely catch regressions?

Traced by hand against the writer (pe.rs:338–390):

- Case `0x1000`: `body_len = 0xFEE`, writer `text_vsize = 0x12 + 0xFEE =
  0x1000`; `text_rva = align_up(0x400,0x1000)=0x1000`; correct `idata_rva =
  align_up(0x2000,0x1000)=0x2000`; assertion `0x2000 == 0x1000+0x1000` PASS.
  Buggy `(v/a+1)*a`: `align_up(0x2000,0x1000)=(2+1)*0x1000=0x3000` !=
  `0x2000` → **FAIL**. Confirms the implementer's empirical result.
- Case `0x2000`: analogous; correct `idata_rva=0x3000`, buggy `0x4000` →
  **FAIL**.

Failure-mode coverage (for the exact-boundary scope only):

- **(a) over-align off-by-one / spurious page** — caught twice: the dedicated
  `idata_rva == text_rva + text_vsize` assertion (RHS free of `align_up`) and
  the per-window `na == align_up(pa+pv, SECT_ALIGN)` whose RHS is recomputed
  from *parsed* bytes. Strong.
- **(b) section overlap / under-align** — caught by the same spurious-page
  assertion (would mismatch low) and the explicit `na >= pa+pv` guard.
- **(c) SizeOfImage drift** — pinned by `size_of_image == align_up(la+lv,
  SECT_ALIGN)`. See MINOR below: this one re-uses `align_up` on the RHS, so in
  isolation it is partly tautological against an `align_up` regression;
  however the spurious-page and `%`-based anchors in the same test still trip,
  so the *test as a whole* does not lose its teeth — only this single
  assertion is weaker than it reads.

Conclusion: the test genuinely has teeth for the exact-multiple boundary; the
empirical "fails under `(v/a+1)*a`" claim is corroborated analytically.

## PE-byte parsing — verified correct

- `opt = PE_OFF + 4 + 20` → PE sig (4, pe.rs:397) + COFF header (20,
  398–404) = optional-header start. Matches existing tests (pe.rs:539).
- `tbl = opt + 0xF0`. `SizeOfOptionalHeader` is written as `0xF0`
  (pe.rs:403); PE32+ optional header = 112 + 16*8 = 240 = 0xF0. Existing
  test reads `.text` VA at `opt + 0xF0 + 12` (pe.rs:544), corroborating both
  the table base and the +12 VA field offset.
- Section header (pe.rs:488–499): name[8], VirtualSize@+8, VirtualAddress@+12,
  40 bytes total. Test reads `h+8`/`h+12` with `i*40` stride — correct.
- `SizeOfImage` at `opt + 56`: field-by-field count of the optional header
  (pe.rs:407–425) lands `SizeOfImage` at byte 56 — correct per PE32+ spec.

No chance of reading garbage that coincidentally matches; offsets are exact.

## Determinism / hygiene

- Synthetic `Module` is fully literal and deterministic; `vec![0x90; n]` is
  reproducible. `TimeDateStamp`/`CheckSum` are zeroed in the writer, so bytes
  are stable across runs.
- Test-only import: `use crate::codegen::{CompiledFn, compile_module};` is
  inside `#[cfg(test)] mod tests` (pe.rs:505) — does not leak into the
  non-test build. `CompiledFn`/`Module` and all consumed fields are `pub` in
  `codegen.rs` (struct shape verified: `name: String`, `code: Vec<u8>`,
  `calls/riprefs/strings: Vec<_>`, `Module { funcs, globals }`), so the
  literal compiles.
- `compile_module` is still imported and used by the pre-existing helpers, so
  the widened `use` introduces no unused-import warning.
- `secs.last().unwrap()`, `.windows(2)`, `vec![..; n]`, `"main".into()` are
  idiomatic in `#[cfg(test)]` and clippy-clean by inspection; consistent with
  the surrounding test module.
- Smallest change: no duplication of the big-data-after-big-text path; helpers
  are minimal and single-purpose.

## Suggestions (non-blocking)

- **MINOR — pe.rs:666–669 (SizeOfImage assertion).** The expected value
  `align_up(la+lv, SECT_ALIGN)` re-uses the function under test on the RHS, so
  *this assertion in isolation* would still pass if `align_up` were globally
  replaced by an equivalently-buggy function (both sides move together). The
  test as a whole is still sound because the `idata_rva == text_rva +
  text_vsize` and `% SECT_ALIGN` anchors do not use `align_up`. Optional
  hardening: for the exact-multiple case, `la + lv` is itself already a
  multiple of `SECT_ALIGN`, so you could assert `size_of_image == la + lv`
  (no `align_up` on the RHS), making this assertion an independent oracle too.
  Not required — coverage is adequate as written.

- **NIT — pe.rs:617.** `want_text_vsize as usize - STUB_LEN` relies on
  `STUB_LEN (0x12) < SECT_ALIGN (0x1000)`; both are compile-time constants so
  underflow is impossible today and any future change would surface
  immediately, but a one-line `debug_assert!(want_text_vsize as usize >=
  STUB_LEN)` (or a comment) would document the precondition. Cosmetic.

- **NIT — pe.rs:620 vs 592.** `let opt = PE_OFF + 4 + 20;` is recomputed in
  the test body and again in `sections()`. This mirrors the existing file
  convention (pe.rs:539, 544 each recompute `opt` locally), so it is
  consistent rather than a defect; flagged only for completeness. No change
  needed.

## Fragility to legitimate future change

Low. The test asserts the *invariant* (`base == align_up(prev_end)`,
`SizeOfImage == aligned last end`, no overlap, no spurious page) rather than
hard-coded incidental byte values, and re-derives expectations from the
parsed layout. It does pin `idata_rva == text_rva + text_vsize`, but that is
the invariant being protected, not an incidental constant. The
self-check assertions (`want_text_vsize`, `% SECT_ALIGN`) make a future
`STUB_LEN`/layout change fail *loudly with a clear message* rather than
silently degrade — desirable. No over-assertion of unrelated bytes.

## Required Changes

None.

Independent verification by tracing `src/pe.rs` end-to-end for the synthetic

calls/riprefs**). All numbers below were computed by hand from the source and

### 1. Disagreement ruling — APPLY AGENT WAS RIGHT; reviewer's MINOR rationale was factually wrong

Verified facts from `src/pe.rs`:
- Section headers are emitted `.text, .idata, .rdata, .data` (pe.rs:447–462)
  and `sections()` reads `secs[0..4]` in that order ⇒ **`.data` IS the last
  section** (`secs.last()`). Confirmed.
- No globals ⇒ `build_data` loop never runs and (crucially) does **not**
  append to `rdata`; `build_rdata` produces empty image (no strings). Both
  `rdata` and `data` are empty, so the non-degenerate guards at pe.rs:351–356
  fire: `rdata.push(0)` (len 1) and **`data.push(0)` ⇒ `data_vsize == 1`**.
  Confirmed — the apply agent's pivotal claim holds.

Computed `idata_vsize` exactly = **0xF9 (249)** (6 imports: desc 40 + ILT 56 +
IAT 56 + hint/name 89 + `KERNEL32.dll\0` 13 = 249), independent of
`idata_rva`.

| Case | text_vsize | idata_rva | rdata_rva | data_rva | la+lv (`data_rva`+1) | la+lv % 0x1000 | correct SoI = align_up(la+lv) |
|---|---|---|---|---|---|---|---|
| A | 0x1000 | 0x2000 | 0x3000 | 0x4000 | **0x4001** | 1 (≠0) | **0x5000** |
| B | 0x2000 | 0x3000 | 0x4000 | 0x5000 | **0x5001** | 1 (≠0) | **0x6000** |

The reviewer's proposed assertion `size_of_image == la + lv` evaluates to
`0x5000 == 0x4001` (A) and `0x6000 == 0x5001` (B) — **FALSE in both cases**
under the *correct* `align_up`. The reviewer's premise ("for the exact-multiple
case `la+lv` is itself already a multiple of SECT_ALIGN", lines 136–137) is the
error: the test engineers the exact-multiple property for **`.text`**, but the
*last* section is `.data` with `vsize=1` forced by the non-degenerate guard, so
`la+lv = data_rva + 1` is **not** a SECT_ALIGN multiple. The apply agent's
rejection is correct and was **not** a rationalized skip — adopting the
reviewer's concrete suggestion would have introduced a test that fails under
correct code.

### 2. Teeth without (C) — YES, full teeth retained

Two classic `align_up` regression classes, traced against `align_up`-free
assertions:

- **Over-align off-by-one / spurious page** (`(v/a+1)*a`): Case A,
  `buggy_align_up(text_rva+text_vsize, 0x1000) = buggy_align_up(0x2000) =
  (2+1)*0x1000 = 0x3000`. **Anchor (A)** `assert_eq!(idata_rva,
  text_rva+text_vsize)` ⇒ `0x3000 == 0x2000` → **FAILS**. RHS is pure
  addition, **no `align_up`** — independent witness. (Matches reviewer's
  empirical claim and lines 67–73.)
- **Under-align / truncation** (`v/a*a`): at the non-exact `.idata`→`.rdata`
  edge, `trunc(0x2000+0xF9, 0x1000) = trunc(0x20F9) = 0x2000`, so `.rdata`
  collides with `.idata` `[0x2000,0x20F9)`. **Overlap guard in (B)**
  `assert!(na >= pa+pv)` ⇒ `0x2000 >= 0x20F9` → **FAILS**. Pure `+`/`>=`, **no
  `align_up`** — independent witness.

| Regression class | Caught by | RHS uses `align_up`? |
|---|---|---|
| Over-align / spurious page | Anchor (A) `idata_rva == text_rva+text_vsize` | No |
| Under-align / truncation | Overlap guard (B) `na >= pa+pv` | No |
| (C) `SoI == align_up(la+lv)` | redundant SoI cross-check only | **Yes — tautological in isolation** |

The `assert_eq!(na, align_up(pa+pv,...))` half of (B) *does* reuse `align_up`
(equally tautological as (C) in isolation), but it is paired with the
`align_up`-free `na >= pa+pv` on the very next line, so (B) as a pair keeps its
teeth. **Conclusion: the test as a whole catches both `align_up` off-by-one
directions via `align_up`-free anchors even with (C) deleted.**

### 3. (C) recommendation — LEAVE AS HARMLESS REDUNDANCY (do NOT de-tautologize)

(C) is genuinely redundant, not load-bearing: (A)+(B) already lock the
invariant. A *correct* de-tautologization would be concrete constants
(`size_of_image == 0x5000` / `0x6000`), **not** the reviewer's wrong `la+lv`.
But even the constant form adds essentially zero marginal coverage: the SoI
path is `align_up(data_rva+data_vsize, SECT_ALIGN)` — the *same* `fn align_up`
already exercised on the `.text`→`.idata` edge and pinned by the
`align_up`-free anchor (A). A single uniform off-by-one cannot pass (A) and
fail only on the SoI path; off-by-ones are uniform across argument values, so
"breaks SoI but not the text edge" is not a realizable single-function
regression. Conversely, pinning `0x5000`/`0x6000` hard-codes incidental layout
(the 0xF9 idata image size, the two `+1` non-degenerate guards) and would break
under *legitimate* future change (e.g. adding an `IMPORTS` entry) with a
confusing failure though the invariant still holds — exactly the
over-assertion-of-incidental-values cost the project quality philosophy warns
against (oracles multiply only when they don't cost more than the confidence
they add). **Recommendation: keep (C) unchanged; the MINOR is correctly
non-blocking; the reviewer's concrete fix is rejected as both wrong and, even
when corrected, brittle for nil marginal gain.** Optional (not required):
soften (C)'s comment to call it a redundant cross-check rather than implying an
independent oracle, for documentation honesty.
