#pragma hdrignore SECTION

## 7. Risk-relevant observations

| Risk | Finding |
|------|---------|
| **R3 (CRT intricacy)** | `SOURCE/RTL/` is fully present (903 .C files, 206 ASM, 53 internal headers, complete makefile set for DOS/DPMI16/DPMI32/WIN16/WIN32). The CRT can be rebuilt from source. **Low risk.** |
| **R4 (host can't run oracle)** | `BCC32.EXE`, `TLINK32.EXE`, `BRC32.EXE`, `CPP32.EXE`, `TLIB.EXE`, `TDUMP.EXE`, `MAKE.EXE`, `IMPLIB.EXE` are all PE32 i386 — will run on Win11 WOW64. **Low risk.** All 16-bit (NE) tools cannot run on Win11 x64 — these are not oracle-critical but flagged in §2. |
| **R8 (TLINK32 quirks)** | TLINK32 banner gives only `Copyright (c) 1993,1994 Borland International`, no version string. Identical SHA-256 between 4.5 and 4.52, so any TLINK32 quirks we encounter will be common to both releases. |
| **OWL source location** | Lives at `SOURCE/OWL/` (flat, 119 .CPP files, no subdirs). Public headers at `INCLUDE/OWL/` (89 .H + 16 .RH + 14 .RC, no subdirs). |
| **OWL source style** | Pre-standard lowercase `string` class (Borland's `cstring`, NOT `std::string`). Heavy macro use (`DIAG_*`, `_OWLDATA`, `pragma hdrignore SECTION`). Section-based compilation for header reuse. **Flag:** these are non-standard patterns that may stress an MSVC-targeting front end if S5 ever ports them; rebuilding with BCC32 itself avoids the issue. |
| **PAQ archives** | **None present.** The CD is fully expanded; `UNPAQ.EXE` is a residual extractor. No user action needed. |
| **4.5→4.52 deltas** | `BCC32`, `CPP32`, `TLIB`, `MAKE` are different SHA-256 (same size — in-place rebuild). `TLINK32`, `BRC32`, `TDUMP` are byte-identical. `LIB/` grew by 21 MB (likely added NOEHxx variants per README). `INCLUDE/` grew by 1.2 MB. The 4.52 bugfix is concentrated in the compiler frontend + a substantial library expansion. |
| **Extra `LIB/` size** | 55.73 MB of pre-built libs we are not using (COFF-only policy). Manifest captures them for completeness but we will not consume them. |
