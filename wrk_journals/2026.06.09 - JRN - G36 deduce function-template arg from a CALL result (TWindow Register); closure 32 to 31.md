# 2026.06.09 — G36: deduce a function-template argument from a CALL result (OWL TWindow::Register); railc closure 32 → 31

Third `type_of_expr` robustness extension (after G33's comparison and the
arithmetic case), closing the function-call-result deduction gap.

## Symptom

`TWindow::Register` unresolved — deferred (S4.2g) in WINDOW.CPP.

## Root cause

`TWindow::Register` does `static bool checkGlobal = ToBool(::GetVersion()&...)`
and `gc = ToBool(::GetClassInfo(0, GetClassName(), &windowClass))`. The second
calls the function template `ToBool<T>(const T&)` with a **function-call**
argument. The monomorphizer's `type_of_expr` could type literals, vars, casts,
and arithmetic/relational binaries, but NOT a `Expr::Call` — so `T` was
undeducible from `::GetClassInfo(...)`, `ToBool` wasn't instantiated, and the
whole function deferred + dropped.

## Fix

`type_of_expr` now types an `Expr::Call` via a new `fn_rets` map (function name →
return type) carried on `Tcx`, built in `monomorphize` from the TU's `Item::Func`
definitions + `extern_protos` (Win32 API decls included). A leading `::` on a
global-scope call name is stripped to match the proto. `::GetClassInfo(...)` ⇒
`int` (BOOL) ⇒ `ToBool<int>` instantiates ⇒ `Register` emits.
