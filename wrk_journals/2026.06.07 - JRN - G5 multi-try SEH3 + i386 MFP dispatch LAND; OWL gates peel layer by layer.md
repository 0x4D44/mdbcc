## G5 — multi-try i386 SEH3 (0e0e71e)

Pre-G5: ONE `try` with ONE clause per function (single late-bound pad imm32).
Now, gated to functions with 2+ trys or 2+ clauses (legacy byte-identical
otherwise):
- 20-byte fs:[0] record {prev, handler, scope-table VA, frame, trylevel};
  trylevel at [ebp-4], armed per-try by the body, disarmed (-1) after each
  try and by the handler before delivery (rethrow-from-catch propagates
  without popping the record).
- Inline scope table after `ret` (count + {level, kind, type VA, pad VA}
  rows; DIR32 Func-addend pads — the legacy record's own mechanism).
- `.mdbcc_seh3_multi_handler`: both exception codes, row walk (level, kind
  vs code, exact class type), RtlUnwind, frame transfer at regptr+20.
- Frame reservation 32 so the handler's two cross-RtlUnwind stash words
  never alias a live local.
- v1 sequential trys (the OWL shape); nested rejected cleanly.

Tests (all bcc32-matched): two sequential trys across every throw path (30);
one try with mixed int+class clauses (42); throw from a catch body
propagating OUT to the caller's catch (42).
