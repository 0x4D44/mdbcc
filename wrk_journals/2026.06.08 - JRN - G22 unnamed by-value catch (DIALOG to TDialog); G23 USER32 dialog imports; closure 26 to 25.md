## G22 (1fd2170) — unnamed by-value class catch → type match

OWL DIALOG.CPP's CATCH chain has `catch(Bad_cast)` / `catch(Bad_typeid)` — by
value, NO parameter name. An unnamed by-value catch observes no parameter, so the
copy is UNOBSERVABLE: it is a pure type match, identical to `catch(E&)`. mdbcc
deferred ALL by-value class catches, blocking the whole of DIALOG.CPP (→ the
TDialog ctor railc needs).

Two-site fix: (1) `gen_try` classifies an UNNAMED by-value class catch as
`CatchPolicy::ByRef` (match by class, bind nothing, run body) — reuses the entire
ByRef machinery; a NAMED by-value catch still defers (needs copy-construction of
the parameter). (2) `first_class_catch_record`'s `ty_record_id` now recognises a
bare `Type::Record` so the SINGLE-try personality gets the right class type
(without this the class throw went UNHANDLED — exit 0xE0000002).

RUN i386_unnamed_by_value_class_catch == bcc32 == 42. OWL sweep 82→83 (DIALOG
compiles); TDialog ctor RESOLVES.
