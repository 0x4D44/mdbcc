# 2026.06.09 — W2 RTL: mdbcc-built POSIX file-I/O shim over Win32 + 4 KERNEL32 imports; railc closure 43 → 36

Continued the W2 RTL self-host. The iostream `filebuf` calls the Borland RTL's
low-level POSIX I/O (`open`/`read`/`write`/`close`/`lseek`) plus the per-handle
MT locks (`_lock_handle`/`_unlock_handle`). The Borland originals are 32-bit
assembly / `.CAS` over an internal fd→OS-handle table — mdbcc can't assemble
them. Provided a plain-C equivalent layered on the Win32 file APIs.

## What landed

- **`wrk_rtlshim/rtlio.c`** — mdbcc-built C: an fd→HANDLE table with
  `open`/`read`/`write`/`close`/`lseek` over `CreateFileA`/`ReadFile`/`WriteFile`/
  `SetFilePointer`/`CloseHandle`, oflag→(access,disposition) mapping from
  Borland `<fcntl.h>` `__FLAT__` values, and `_lock_handle`/`_unlock_handle`
  no-ops (Borland's own `_IO.H` `#define`s them away in the non-MT build). This
  is "OS resolved as imports" (the GOAL's explicit exception) while staying
  every-byte-mdbcc-built. NOT an edit of the Borland tree — a self-host shim
  added to `mdcw32.lib`. C linkage ⇒ bare symbols match the filebuf callers.
- **`src/link/pe_writer.rs`** — added `CreateFileA`/`ReadFile`/`SetFilePointer`/
  `GetExitCodeThread` to `WIN32_IMPORTS` + `EXTENDED_ON_DEMAND` (emit-only-when-
  referenced ⇒ byte-identical for images that don't use them).
