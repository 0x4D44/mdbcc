# 2026.06.09 — G34: OWL DDVT dispatcher mangling — free-fn-value uses `extern_symbols`; records threaded through Func/MemFn; railc closure 78 → 72

Two coupled fixes that resolved the DDVT `*_Dispatch` cluster (the response-table
dynamic dispatchers taken as function pointers).

## Diagnosis

OWL response tables store the DDVT dispatchers as function pointers, e.g.
`(TAnyDispatcher)v_Dispatch` where `v_Dispatch` is a FREE function
`v_Dispatch(GENERIC&, void(GENERIC::*)(…), uint, int)`. Two independent
mangling-consistency defects left them unresolved:

1. **A free cxx-param function used as a function-POINTER VALUE emitted the BARE
   name.** `free_fn_value_symbol` returned `name` whenever `funcs.contains_key`,
   but a cxx-param free function defined out-of-TU is registered in BOTH `funcs`
   (its signature) AND `extern_symbols` (its `@name$q…` reference symbol, G15
   #25). So the definer emitted `@v_Dispatch$q…` while every referencing TU's
   response table referenced bare `v_Dispatch`.

2. **`borland_mangle_type_with_records` had no Func/MemFn arm.** Even once the
   reference mangled, the PMF parameter `void(GENERIC::*)(…)` mangled via the
   records-LESS `borland_mangle_type` as `m<class_id>` — a per-TU record index
   (`m966` in DISPATCH.CPP, `m969` in the referencing TU) — so
   `@v_Dispatch$qr7GENERICm966qvuii` ≠ `…m969…`.

## Fixes

1. `free_fn_value_symbol` (codegen.rs): prefer the registered `extern_symbols`
   mangled symbol over the bare `funcs` name. No-op for primitive/member/extern-C
   functions (their registered symbol IS the bare name) and for same-TU
   definitions (absent from `extern_symbols`).
2. `borland_mangle_type_with_records` (cpp.rs): add `Type::Func` and
   `Type::MemFn` arms that thread the records table — a MemFn's class id resolves
   to its stable tag (`m7GENERIC…`), inner records to their tags. mdbcc's own
   structural form is kept (ret-before-params, lowercase `m`); not byte-identical
   to bcc32's `M7GENERICqv$v` but self-consistent across the all-mdbcc link
   (symbol bytes are internal — never observed at runtime; the dispatcher is
   resolved to an address and called through the response table).

## Effect

- railc closure **78 → 72**: `v_Dispatch`, `v_POINT_Dispatch`,
  `v_U_POINT_Dispatch`, `I32_WPARAM_LPARAM_Dispatch`, `DoEnableAutoCreate`,
  `InitWndProc` resolve (bare → mangled-and-consistent in two waves).

## Gate (green)

## Remaining

The last DDVT piece is the 5 `*_Sig` thunks (`v_Sig`, `v_POINT_Sig`,
`I32_U_I32_Sig`, `v_U_POINT_Sig`, `v_U_SIZE_Sig`) — template inline functions in
SIGNATUR.H (`template<class T> v_Sig(PMF) {return pmf;}`) instantiated via
`v_Sig(&Class::method)`. They defer because deducing `T` from a
pointer-to-member argument needs PMF typing in `type_of_expr` + `MemFn`
unification — a deeper deduction feature (filed under #25 DDVT).
