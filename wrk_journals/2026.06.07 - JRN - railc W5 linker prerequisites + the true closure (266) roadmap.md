# 2026.06.07 — railc W5 linker prerequisites + the TRUE closure (266) roadmap

A 4-agent ultracode workflow (`railc-link-path-analysis`) blueprinted the path to
a running railc.exe and CORRECTED a key earlier finding. This entry records the
correction, the three W5-prerequisite linker fixes landed, and the remaining
W2–W5 plan.

## Correction: "objs functionally complete (1 external)" was a MASKING ARTIFACT

`mdlink` bailed at the FIRST reloc-referenced unresolved symbol
(`apply_one_reloc`'s `?`), so it reported "1 unresolved" (TStringRef) when the
true first-level set was ~429. The W1 **compile** milestone (21 TUs → clean
COFF) is real; but the objs reference a large external closure. Fixed
(commit 28db990): apply_relocs_multi now batches ALL unresolved.

## Three W5-prerequisite linker fixes (landed this session, each gated green)

1. **Un-mask the closure** (28db990) — batch all unresolved; relinking the 21
   objs revealed 429 (not 1). +regression test.
2. **i386 GUI entry stub** (d954b6b) — was hInstance=0 / nCmdShow=0(SW_HIDE);
   now hInstance=ImageBase, nCmdShow=1. Load-bearing for an OWL app (resource
   loads + a visible main window). Stub 24→27 B.
3. **+163 Win32 imports** (56be355) — Win32 APIs called from inlined OWL/RTL
   bodies were C++-mangled (unlinkable); added them across 4 new DLLs
   (CTL3D32/WINMM/COMDLG32/SHELL32) + USER32/GDI32/KERNEL32, via
   EXTENDED_ON_DEMAND (byte-identity preserved). **Unresolved 429 → 266.**

## The TRUE remaining closure: 266 symbols (the real W2–W4 work)

Relinking the 21 railc objs now leaves **266 unresolved**, all genuine library
code (no Win32-mangled left): ~RTL (`string@*`, `filebuf::*`, `streambuf::*`,
`_ctype`, `cout`, `sprintf`, `malloc`, `xalloc`/`__xalloc`) → **W2 mdcw32**;

`TApplication::*`, `TDialog::*`, OwlAppDictionary, GetWindowPtr) → **W4 mdowl**;
plus OLE-GUID data (`CLSID_*`/`IID_*` — likely dead, prune or stub).

## `.res` resource linking (blueprinted, the other discrete W5 piece)

mdbcc's rc parser CANNOT compile RAILC.RC (string-id MENU, #include, ICON/
BITMAP/RCDATA). Plan (agent 2, ~300 LoC): reuse the golden BRC32 `railc.res`;
add a `.res` binary READER (`src/link/res.rs`) + a GENERAL `.rsrc` emitter
(named entries + the 3-level type/name/lang tree, correctly SORTED — the loader
binary-searches; wrong order → silent NULL resource) hooked INTO
`write_pe_from_objects` (the correct i386 PE writer; NOT the buggy PE32+ append
path) + `.res` CLI plumbing. Golden inventory = 27 records (MENU/DIALOG×4/
ICON×6/GROUP_ICON×6/BITMAP×7/RCDATA/VERSION/STRING), all lang 0.
