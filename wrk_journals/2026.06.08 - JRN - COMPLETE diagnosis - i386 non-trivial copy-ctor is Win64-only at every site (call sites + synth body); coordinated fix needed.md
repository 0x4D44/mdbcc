## The four Win64-only sites (all need an i386 path)

1. **Decl-init copy-ctor call** — `codegen.rs ~4424` (`T a = b;`). Hand-rolled
   Win64: `encode(Mov reg64 rdx,rax)` + REX.W `lea rcx` + rcx=this/rdx=src
   register convention → "no encoder row for Mov [Gpr64,Gpr64]" on i386.
   FIX DEMONSTRATED (then reverted): an `if Win32` branch routing through
   `emit_call(ctor_sym, Some(this_slot), [src], [Ptr<T>, Ref<T>])` — cdecl,
   marshal_args_cdecl-correct. RUN-verified for an EXPLICIT copy ctor (`T b=a`
   == 5, correct). Win64 keeps its hand-roll (byte-identical).
2. **new-expr copy-ctor call** — `construct_in_place` / `gen_new` (`new T(t)`).
   Needs the same `arg_is_self → emit_call(copy_sym …)` + memcpy-when-trivial
   fallback (the G29 attempt; its CALL was ~right, the crash was site #4).
3. **by-value-argument copy-ctor call** — `codegen.rs ~7131` (passing a record
   BY VALUE). Same Win64 register hand-roll.
4. **THE SYNTH BODY — `build_synth_copy_ctor` (cpp.rs:591)** — emits an ENTIRELY
   Win64 function: prologue `mov [rbp-8],rcx` / `mov [rbp-16],rdx` (this/src in
   REGISTERS), REX.W throughout, member/base copy-ctor calls via rcx/rdx+REX.W
   (`emit_inner_ctor_call`), field byte-copies via rcx/rdx. On i386 this is
   garbage (0x48 REX.W = `dec eax`; this/src arrive on the STACK at [ebp+8]/
   [ebp+12], not rcx/rdx). So an IMPLICIT copy ctor, even if CALLED correctly,
   crashes in its own body on i386.

## Why partial fixes are unsafe (the trap)

Fixing only the CALL sites (#1–#3) without #4 is WORSE than leaving it: an i386
implicit copy goes from "no encoder row" (clean defer → clean unresolved at
link) to "calls a crashing Win64-only synth body" (compiles, links, **segfaults
at runtime** — a silent miscompile). nt2.cpp proved this (rc=139). EXPLICIT copy
ctors are safe (normal i386 codegen body) but IMPLICIT ones need #4. Since you
can't cheaply tell explicit-vs-synth at the call site, the fix must be
ALL-OR-NOTHING: do #4 (the synth-body i386 rewrite) together with #1–#3.
